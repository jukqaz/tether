# Tether v3 · 디자인과 출시 전 미확인 항목

2026-10-06 · macOS 26 이상 / Apple Silicon. [디자인 계약](DESIGN.ko.md), [기능 정의](PRODUCT-SPEC.ko.md), [실행 설계](ARCHITECTURE-REDESIGN.ko.md), [현재 조사](COMPETITOR-DEEP-RESEARCH.ko.md)를 기준으로 한다.

**아래는 실제 완료 근거를 채울 체크리스트다.** 과거 빌드의 시험 개수·저장 렌더·설치 성공을 v3 합격으로 가져오지 않는다. 문서 완료, 예시 미리보기, 출시 앱 모델 연결, OS 효과, 원격 입력, 공개 배포는 서로 다른 단계다.

## 1. 판정과 증거 규칙

| 상태 | 사용할 조건 |
|---|---|
| 미확인 | 필요한 구현·시험·직접 관측 근거가 없음 |
| 예시 확인 | 모의 데이터와 메모리 내 조작/렌더에서만 확인 |
| 구현 확인 | 출시 UI가 실제 모델과 연결되고 해당 회귀가 통과 |
| 실기기 확인 | OS/모델/전원/덮개/화면 조합과 관측 출처·시각이 기록됨 |
| 제한 확정 | 지원할 수 없는 조합이나 영향이 확인되어 설정·문구에 반영됨 |

체크할 때 항목 ID, 대상 소스/빌드, 환경, 입력·조작, 예상/실제 결과, 관측 시각·출처, 제한을 남긴다. 없는 값을 정상으로 채우거나 명령 exit 0·표본 공백을 Sleep 증거로 사용하지 않는다. 이 문서 작성 자체는 아래 체크를 해제하지 않는다.

로그는 기본 접고 전이 중심으로 제한한다. 필요한 시험 자료는 사용자와 합의한 범위에서만 수집하며 Desktop에 저장하지 않는다. 비밀번호·토큰·환경 전체·화면 내용을 진단 자료에 넣지 않는다.

## 3. 출시 UI와 일반 작업 유지

- [ ] V3-U01. 출시 앱이 하나의 결정 모델을 읽으며 UI가 별도 시간/전원 정책을 재계산하지 않는다.
- [ ] V3-U02. 도우미 없음·구형·인증 취소·비관리자에서도 가능한 일반 유휴 유지에 진입한다. 덮개 실패가 일반 시작을 일괄 막지 않는다.
- [ ] V3-U03. 실제 프로세스 소유 assertion 확인 뒤 `작업 유지`를 표시한다. 설정 선택·명령 접수만으로 활성이라고 하지 않는다.
- [ ] V3-U04. 데스크톱에서는 덮개 조작을 숨긴다. 배터리/덮개 조회 실패와 해당 기능 없음은 별도로 설명한다.
- [ ] V3-U05. AC 연결과 충전률/충전 중 상태를 구별한다. 100% 배터리에서도 AC 자동 조건이 유효하다.
- [ ] V3-U06. 자동 ON/OFF와 AC/배터리/둘 다 조건이 별도이고 OFF→ON에서 조건·시간·수동 요청을 보존한다. 배터리 자동 1~120분을 설명하며 전체 중지·보호를 토글로 해제하지 않는다.
- [ ] V3-U07. 조회 실패·중복 통지·창 열기·IPC 재연결이 자동 배터리 활성 구간을 새로 만들지 않는다.
- [ ] V3-U08. 자동 배터리 만료·전체 중지·보호 marker를 재실행/업데이트가 지우지 않으며 필요한 `다시 시작`을 표시한다.

## 4. 수동 시간·종료·잠자기

- [ ] V3-T01. 시간 선택·마지막 기본값 저장만으로 시작하지 않는다. 명시적 버튼 이후 실제 요청/관측 단계가 표시된다.
- [ ] V3-T02. AC 무제한과 배터리 최대 120분을 구별한다. 배터리에는 무제한 선택이 없고 직접 입력도 검증한다.
- [ ] V3-T03. AC의 분리 후 유지 예외는 별도 선택이며 최초 실제 배터리 전환에서 한 번 시작한다. 선택·시작·대기의 의미를 설명한다.
- [ ] V3-T04. AC 왕복·덮개 열림·원격 접속·시계 변경·재연결로 최초 배터리 마감이 늘어나지 않는다. UI 숫자와 모델의 마감이 같다.
- [ ] V3-T05. 실행 중 기간·배터리 예외 변경은 기존 요청·마감을 바꾸지 않는다. 만료된 요청은 명시적 새 시작으로만 만든다.
- [ ] V3-T06. 수동만 끝내기 후 유효한 자동 유지가 남는 상황, 자동만 끄기 후 수동이 남는 상황을 확인한다.
- [ ] V3-T07. 지금 모두 중지 후 전원 왕복·Wake·재실행·업데이트에서도 일시중지가 유지된다. 다시 시작이 만료 수동 시간을 복원하지 않는다.
- [ ] V3-T08. Tether 잠자기는 자체 해제→최신 안전 확인→한 번 요청이며 OS Sleep→FullWake 근거가 있을 때 해당 이유만 해제한다.
- [ ] V3-T09. 원복 실패·Sleep 미확인·프로세스 재시작에서는 `다시 시작`을 제공하며 보호·전체 중지 이유를 함께 지우지 않는다.
- [ ] V3-T10. Sleep 요청 대기 중 새 작업·전원 재연결·소유자 변화와 이미 OS가 수락한 경계를 구분한다. 늦은 완료가 최신 상태를 성공으로 덮지 않는다.

## 5. 덮개·닫힌 전원 분리의 물리 게이트

- [ ] V3-L01. macOS 26의 실제 Apple Silicon MacBook에서 준비·권한·원복을 확인한다. 다른 OS 빌드 성공을 이 실증으로 쓰지 않는다.
- [ ] V3-L02. 열린 덮개에서 선택적 기능 준비·인증을 끝내고 실제 적용을 확인한다. 닫힌 뒤 인증을 기다리는 구조를 제거한다.
- [ ] V3-L03. 무외장 AC 닫힘의 연속 동작과 실제 Sleep 로그를 대조한다. 시험 기간을 넘는 장시간 내구성을 주장하지 않는다.
- [ ] V3-L04. 닫힌 분리에서 유효한 자동·수동 배터리 요청이 없으면 자체 유지 해제와 실제 Sleep을 각각 확인한다.
- [ ] V3-L05. 유효한 배터리 요청이 남으면 유지하고, 최초 마감 만료 이후 종료한다. 수동 만료만으로 유효한 자동 배터리를 없애지 않는다.
- [ ] V3-L06. 추천 Sleep 모드와 macOS에 맡기기를 비교한다. 후자는 자체 해제 성공을 즉시 Sleep 성공으로 표현하지 않는다.
- [ ] V3-L07. 전역 후보가 native macOS 메뉴 Sleep을 차단하는지 실측하고 제한 문구를 덮개 설정에서 확인한다. 제한 미검증 상태를 지원 완료로 표시하지 않는다.
- [ ] V3-L08. 타사 유휴 assertion은 해제하지 않는다. 타사 전역 SleepDisabled는 채택/해제하지 않고 동일 값 작성의 관측 한계를 설명한다.
- [ ] V3-L09. 전원 재연결·열림·새 요청·GUI 종료·unknown이 최종 분리 Sleep을 취소하는 범위를 실측한다. 반복 Sleep 재시도 없음도 확인한다.
- [ ] V3-L10. 닫힌 awake에서 AC 이벤트가 작동하는 경우와 실제 Sleep 후 전원 연결을 나눈다. 케이블만으로 FullWake·로그인·원격 준비를 보장하지 않는다.
- [ ] V3-L11. 외장 화면/독/가상 화면 조합을 각각 확인한다. 화면 존재만으로 자체 종료 책임을 넘기거나 일반 유지를 끝내지 않는다.
- [ ] V3-L12. 닫힌 AC 분리 때 GUI stall·원격 연결이 있어도 도우미가 AC 허가를 즉시 무효화하고 승인된 잠자기 경로를 집행한다. 원복·general assertion 잔존·실제 Sleep을 따로 기록한다. 전원 재연결 자동 깨움은 출시 조건에서 제외한다.

## 6. 화면·잠금·원격의 별도 게이트

- [ ] V3-R01. 실제 내장 화면 꺼짐을 OS 화면 절전 관측·밝기 0과 구별한다. panel 전력 0은 별도 증거가 없으면 주장하지 않는다.
- [ ] V3-R02. 전체 display sleep 명령을 내장 전용으로 자동 사용하지 않는다. 외장/원격 프레임·입력에 미치는 영향은 별도 확인한다.
- [ ] V3-R03. 앱의 덮개 잠금 선택 꺼짐이 OS 자동 잠금 방지를 의미하지 않는 문구인지 확인한다.
- [ ] V3-R04. OS 암호 요구 정책·실제 잠금·잠금 조회 실패를 구별한다. 조회·설정 열기 외 전역 보안값을 몰래 변경하지 않는다.
- [ ] V3-R05. 앱 잠금 선택만 저장하며 무잠금을 약속하는 역방향 설정이 없다. 옛 로그인 선호값으로 보안 정책을 낮추지 않고 MDM/iPhone Mirroring 제한을 설명한다.
- [ ] V3-R06. 공개 실행 수단으로 화면 꺼짐+세션 무잠금+전역 보안 미변경이 가능한지 실제 근거를 확보한다. 불가능/미확인은 제한으로 표시한다.
- [ ] V3-R07. 인증된 다른 원격 클라이언트에서 프레임·입력·재연결을 확인한다. 설치/버전/PID/요청 감지로 `원격 준비됨`을 표시하지 않는다.
- [ ] V3-R08. 잠금은 사용자 전환·로그아웃·Sleep과 구별된다. 원격 연결/해제가 작업 요청·마감·writer 소유권을 바꾸지 않는다.
- [ ] V3-R09. 실험 조건별 화면/잠금/작업/원격의 네 결과를 따로 기록한다. 한 결과를 다른 기능 성공으로 확대하지 않는다.

## 7. 보호·이관·원복·설치의 사용자 경험

- [ ] V3-S01. OS 열 상태·저전력·사용자 잔량 하한을 보여 준다. 근거 없는 CPU 온도나 120분의 하드웨어 안전 보증을 넣지 않는다.
- [ ] V3-S02. serious/critical은 AC·배터리와 자동·수동 모두 중지하며 수동 배터리 예외도 무효화한다. 닫힌 기기의 자체 원복→한 번의 승인된 Sleep→실제 OS Sleep 근거를 구별한다. GUI stall·냉각·ON/OFF·전원 재연결·Wake로 보호가 부활/우회하지 않음을 확인한다. 보호 이유와 직접 재개 조건은 진단을 펼치기 전에도 보인다.
- [ ] V3-S03. 사용자 off·명확한 선택·중지/보호를 이관하고 옛 runtime 시간·240분 예산·재시도 경로를 새 작업으로 가져오지 않는다.
- [ ] V3-S04. 이전 자체 변경 원복과 원본 보존을 확인한다. 실패 debt가 있을 때 새 전역 쓰기만 막고 가능한 일반 유지·UI·복구를 제공한다.
- [ ] V3-S05. 설치 A/B, 중단·rollback·재실행에서 진행/취소/실패 상태를 정확히 표시한다. rollback이 사용자의 새 설정이나 off를 덮지 않는다.
- [ ] V3-S06. 관리자 인증 동안 UI/상태 확인이 계속 가능하고 중복 설치·제거가 경쟁하지 않는다. 인증 취소를 일반 기능 실패로 표현하지 않는다.
- [ ] V3-S07. 실제 helper 준비·버전/프로토콜·원복 postcondition을 확인한다. 등록·installer 성공만으로 활성이라고 표시하지 않는다.
- [ ] V3-S08. 빠른 사용자 전환·잠금·앱 crash·watchdog 복구를 구별하며 외부 사용자의 자원을 해제하거나 강제 Sleep하지 않는다.
- [ ] V3-S09. lease 수명과 복구 지연을 macOS 26에서 측정해 고정한다. 옛 상수·시험 개수로 최대 복구 시간을 광고하지 않는다.

## 8. 시각·접근성·아이콘

- [ ] V3-A01. 표준 toolbar/주요 조작의 Liquid Glass와 안정적인 Form 내용층을 구별한다. 긴 설명에 유리 카드 배경을 반복하지 않는다.
- [ ] V3-A02. 제목 22pt/상태 17pt/본문 13pt/설명 12pt/숫자 22pt를 첫 렌더에서 확인하고 잘림·밀도에 따라 조정한다.
- [ ] V3-A03. 실제 밝고 어두운 배경·반투명·Increase Contrast에서 일반 텍스트 대비 4.5:1 목표를 측정한다. 측정 전 합격을 주장하지 않는다.
- [ ] V3-A04. Reduce Transparency/Reduce Motion과 native focus 표시를 확인한다. 앱이 시스템 접근성 설정을 변경하지 않는다.
- [ ] V3-A05. 실제 VoiceOver에서 선택·값·시간·중지 범위·오류를 낭독하고 매초 숫자 갱신이 낭독을 방해하지 않는다.

## 9. 현재 증거의 범위

| 대상 | 현재 문서가 정한 것 | 완료를 표시할 추가 근거 |
|---|---|---|
| 메뉴·설정 구조 | 기본/최소 창 세 페이지·정보 순서·예시 조작, 비교 PNG 확인 | 모든 예시 상태·숫자·오류·긴 번역 조합 확인 |
| 네이티브 재질 | 로컬 실행 창의 탐색/조작층 확인 | macOS 26·접근성 설정·focus 조합의 직접 관측 |
| 일반·덮개 상태 | 의도와 실제 관측을 분리하는 계약 | 출시 앱 모델 연결 + 실행기 관측 |
| 시간·중지 | 자동/수동의 독립 수명과 중지 범위 | 정책 전이 회귀 + UI 경로 |
| 화면·잠금·원격 | 네 결과를 별도로 판정하는 계약 | macOS 26 + 인증된 원격 클라이언트 |
| 이관·원복 | 사용자 선택 보존과 복구 debt의 제한 | 장애 주입 + 실제 설치/원복 관측 |

2026-10-06 예시 확인의 대상은 `Sources/Tether/DesignPreview/`와 현재 작업 트리에서 빌드한 `build/Tether Design.app`이다. 로컬 macOS 27.0 SDK로 `scripts/build-preview.sh --design`이 성공했고, 번들 ID는 `io.github.jukqaz.tether.design`이며 도우미 실행 파일을 포함하지 않는다. `TetherApp.main`에서 디자인 진입을 출시 앱·Workbench·AppModel 초기화보다 먼저 처리한다. 예시 상태의 조작은 메모리에만 반영되며 실제 전원·보안 설정에 연결하지 않는다.

Computer Use로 기본 880×720pt 설정 창의 제목·세 페이지·예시 메뉴를 관측했다. 3분 선택 뒤 시작 전 상태, 명시적 시작, 수동만 종료 뒤 자동 유지 보존, 전체 중지와 직접 재개를 예시 상태에서 확인했다. 도우미 필요 예시에서 일반 시작이 활성이고 해당 덮개 제한이 따로 보임도 확인했다. 실제 마감 시간이 흐르는 타이머 시험이나 출시 앱 동작 시험은 아니다.

같은 날 자동 OFF에서도 수동 시작이 가능한 패널, 설정의 ON/OFF 뒤 `둘 다` 조건·60분 배터리 선택 보존과 수동 유지 보존을 Computer Use로 확인했다. 기기 보호 페이지의 적용 범위·닫힌 Sleep·직접 재개 안내도 직접 관측했다. `swift test --filter DesignPreviewStateTests`는 표시 모델의 자동/수동 독립, 전체 중지 보존, 배터리 무제한/상한 초과 거부, 보호 우회 거부 7개를 통과했다. 실제 OS 이벤트·마감·helper 실행이 없어 V3-U/T/S나 인수 JSON의 `notRun`을 완료로 바꾸지 않는다.

기능을 좁힌 뒤 같은 표시 회귀 7개와 디자인 번들 빌드가 통과했다. Computer Use에서 배터리 예외가 수동 시작 근처에 있고 시작 후 비활성, 수동만 끝내면 편집 가능·자동 유지 보존을 확인했다. 잠금 스위치는 한 개이며 ON/OFF 설명이 앱 요청과 OS 정책을 구별한다. 앱 설정의 외관·아이콘 폭 행은 없어지고 업데이트 채널·진단은 접힌 상태로 보였다. 채널 실제 전환·설정 저장·이관·OS 잠금 효과를 시험한 것은 아니다. 분 단위 직접 입력·마지막 시간의 영속 저장은 채택한 계약이며 현재 예시에는 구현되지 않았다.

설정+348pt 패널의 [비교 PNG](images/redesign-v3.png)는 2592×1620 픽셀로 생성해 열어 확인했다. 저장 렌더의 사이드바와 재질에는 bitmap용 대체가 있으며 실제 native `List`·Liquid Glass·접근성 합격을 대신하지 않는다. V3-D04/D05/D06/D08과 실제 모델·OS 효과 게이트는 이 예시 확인으로 완료 처리하지 않는다.

이어 진행한 [디자인 리뷰와 전후 캡처](DESIGN-REVIEW.ko.md)는 macOS 27.0.1의 네이티브 창 근거다. 최소 760×600pt/190pt 사이드바에서 세 페이지와 하단 스크롤, 영어 348pt 패널을 확인했다. 패널·진단 정렬, 창 제목/예시 메뉴, 페이지 전환 스크롤, 수동 종료 및 도우미 준비 상태의 설명을 수정했다. 앱 설정의 Tab·Space 일부를 확인했으나 전체 키보드·VoiceOver·대비·macOS 26 재질은 미확인이다. 이 근거로 V3-D02만 예시 확인으로 추가 처리했다.
