# 기기 관측 실패의 일반 작업 유지와 실제 OS 요청 만료

2026-10-01 · 빌드 50 미배포 후보. 이전 [사용자 세션 보완](USER-SESSION-INPUT-20261001.ko.md)을 앱의 기기별 실행 경로와 연결했다. 설치본은 빌드 49이며 전역 전원 값·잠금·화면 설정·관리자 도우미 설치는 변경하지 않았다.

## 수정한 동작

일반 작업 유지의 제공 여부를 `hardware == desktop`에 한정하던 경로를 수정했다. 지원 플랫폼에서 내장 배터리와 덮개가 함께 확인되지 않으면 프로세스 소유 idle 실행기를 사용한다. 데스크톱과 부분 관측 실패를 같은 하드웨어라고 분류하지 않으며, 기기 종류·덮개 제어의 확인 여부는 보존한다. 확인된 MacBook은 기존 덮개 실행 경로를 계속 사용한다. 두 실행기의 공통 세션·의도 통합이 완료됐다는 뜻은 아니다.

일반 작업 유지에는 관리자 도우미를 요구하지 않는다. 해당 실행기는 닫힌 덮개 제어를 제공하지 않으므로 화면에서 ‘일반 절전만 방지하며 덮개를 닫을 때는 macOS를 따른다’고 설명한다. 내장 배터리가 확인된 경우 잔량과 제한을 보여 주고, 미확인 Mac에 데스크톱 심벌을 사용하지 않는다.

앱 모델 검사에서 초기 `snapshot.power`가 현재 사용자 세션의 배터리 상태 대신 호스트 AC 상태를 사용해 무제한 버튼을 허용하는 오류가 재현됐다. 초기 연결과 이후 갱신을 같은 함수로 처리해 전원·잔량·보호·제한·타이머를 동일한 사용자 세션 상태에서 표시한다. 해당 잔량이 누락됐을 때 다른 조회의 잔량을 대신 표시하지 않는다.

일반 세션의 제한 변경도 해당 조정자로 보낸다. 잔량 하한을 높이면 새 기준으로 자체 요청을 해제하며 시간 제한 변경은 이미 소비한 예산을 보존한다. 폐기한 온도 제한·무한 수치와 종료된 조정자의 변경은 거부한다. 수동 AC 입력 상한과 별도로 배터리 제한 선택은 최대 2시간이다. root `Control` schema 3·IPC protocol 2·사용자 설정 v2는 변경하지 않았다.

## 실행 결과

| 검사 | 결과와 범위 |
|---|---|
| 앱의 기기별 경로 | 8가지 배터리/덮개 관측 조합에서 일반 세션 시작·자체 종료. unsupported 플랫폼과 확인된 MacBook은 이 대체 경로로 몰래 전환하지 않음 |
| 추가 회귀 | 앱 모델 4개와 조정자 제한 변경 1개. 초기 AC 표시 오류는 수정 전 실패를 보존 |
| 전체 Swift, native 옵션 포함 | Core 437 + 업데이트/앱 35 = **472 통과·0 건너뜀·0 실패** |
| 기존 native assertion 검사 | 전체 472개에 포함된 6개. 고유 검사 수로 다시 합산하지 않음 |
| 제품의 실제 90초 idle lease | 아래 별도 비관리자 프로세스 시험 1회. Swift 검사 수와 구별 |
| 로컬 배포 후보 | macOS 15 arm64 앱·helper·복구 실행기·CLI 포장, 서명·리소스 일치·설치 판정·격리 소켓·CLI 경로 통과 |

기기 조합·배터리 잔량과 제한 변경은 별도 UserDefaults 도메인과 모의 OS backend로 검사했다. 실제 센서 장애·MacBook 닫힘·데스크톱·UPS 연결 또는 macOS 15 실행의 증거가 아니다. 미리보기 조정자를 주입한 앱 모델은 운영 서비스 조회·연결을 수행하지 않는다.

## 실제 90초 만료 관측

제품의 `IdleAssertionDriver`를 사용하는 별도 비관리자 시험 프로세스가 실제 OS 요청을 생성했다. 독립된 `caffeinate` 요청도 관측한 뒤 시험 프로세스만 SIGSTOP으로 멈췄다. 자체 타이머나 새 정책 평가가 실행되지 못하는 동안 OS의 활성 목록을 19회 조회했다.

- 자체 단조 시작: `966500.8885918334`, 마감: `966590.8885918334`.
- 마지막 활성 관측: `966590.7828665416`.
- 첫 비활성 관측: `966590.9102832084` — 시작에서 약 **90.022초**, 마감에서 약 **0.022초** 뒤.
- 활성과 비활성 사이의 관측 간격: 약 **0.127초**. 그 사이의 정확한 만료 순간을 추측하지 않는다.
- 시험 프로세스는 살아 있었고 외부 `caffeinate` 프로세스와 그 요청은 계속 활성 상태였다. 조회 실패·프로세스 종료를 만료 성공으로 계산하지 않았다.

이 결과는 현재 호스트의 제품 idle 실행기와 OS 만료 계약을 확인한 1회 측정이다. 실제 Tether 앱 전체 hang, 전 기기 최악 지연, OS 응답 불가, 시스템 잠자기, root 덮개 watchdog을 포함한 전체 복구 상한을 증명하지 않는다. 시험 종료 시 생성한 두 프로세스만 정리했다.

재현 명령은 기존 앱이나 전원 설정을 변경하지 않는다. 현재 GUI 사용자로 실행하며 실제 유한 idle 요청을 만든다.

```sh
swift build --product TetherWriterFixture --disable-sandbox
python3 scripts/test-idle-lease.py --fixture .build/debug/TetherWriterFixture --output /private/tmp/tether-idle-lease-result
```

출력 폴더는 새 경로여야 한다. `TetherWriterFixture`는 배포 앱에 포함되지 않으며 포장 검사에서 제외를 확인했다.

## 남은 범위와 GitHub

확인된 MacBook의 일반 작업과 덮개 실행기를 하나의 의도·수명으로 조정하는 경로, CLI의 일반 세션 관리, 기기 관측 복구 뒤 실행기 전환과 기존 root 예산·복구 기록의 안전한 이관은 남아 있다. 기기별 일반 기능을 열어 두는 이번 수정으로 그 계약을 대신하지 않는다. 전원/발열/full wake/GUI·배터리 운용 시 잔량이 미확인이면 새 요청을 시작하지 않는 가드는 유지한다.

원격 화면·입력·무잠금과 물리 Sleep/Wake, 실제 macOS 15·데스크톱·UPS·독, 사용자 전환, 전체 Sparkle 업데이트와 root 보호 해제 지연은 별도 검증이 남았다. 설치본 교체·커밋·푸시·원격 CI·릴리스도 실행 전이다. [남은 설계 한계](DESIGN-GAPS.ko.md)를 완료로 바꾸지 않는다.
