# 수동 조작 순서를 재생하는 도우미 시뮬레이션 — 빌드 49

`scripts/test-manual-scenarios.py`는 1~6번 조작 순서를 실제 도우미 프로세스와 소켓으로 실행한다. 각 사례의 센서·설정·소켓·로그는 별도 임시 폴더에 두며, 시스템 명령은 항상 `--dry-run`으로 처리한다. 실행 중인 Tether의 전원 규칙을 수정하거나 실제 Mac을 잠재우지 않는다.

## 실행

소스 빌드로 검사할 때:

```sh
swift build
python3 scripts/test-manual-scenarios.py --out /tmp/tether-manual-simulation-1
```

설치된 도우미를 그대로 검사할 때:

```sh
python3 scripts/test-manual-scenarios.py \
  --helper /Library/PrivilegedHelperTools/local.tether.helper \
  --out /tmp/tether-installed-simulation-1
```

결과 폴더는 매 실행마다 새 경로를 사용한다. 3분 타이머를 실제 시간으로 실행하므로 전체 약 5분이 걸린다. 독립된 사례들은 별도 도우미에서 동시에 진행한다. 실제 고온·배터리 방전은 유발하지 않는다.

기존 서비스·충돌 검사도 설치된 도우미로 선택해 실행할 수 있다. 이때 CLI는 기존과 같이 Swift 빌드 폴더의 실행 파일을 사용한다.

```sh
TETHER_TEST_HELPER=/Library/PrivilegedHelperTools/local.tether.helper python3 scripts/test-service.py
TETHER_TEST_HELPER=/Library/PrivilegedHelperTools/local.tether.helper python3 scripts/test-conflicts.py
```

## 검사 내용

| 구분 | 입력과 검증 |
|---|---|
| 1 | 열린 덮개에서 배터리 20초·AC 35초, 소유권·유지 상태 전환 |
| 2 | AC에서 닫힌 덮개 60초 유지, 분리 시 해제·잠자기 요청 |
| 3 | 배터리 3분 유지 시작, 덮개 닫고 20초 뒤 AC, 210초 뒤 분리, 60초 후 모의 깨움 |
| 4 | 배터리 1분 유지 시작, 90초 동안 실제 만료, 모의 깨움 후 타이머 재활성화 방지 |
| 5 | 배터리 전용 자동 2분, AC에서 비활성·배터리에서 활성·AC 복귀 후 타이머 취소 |
| 6 | 수동 끄기 유지, 앱 연결 해제·도우미 재시작·재연결, 설정 보존·임시 예약 폐기 |
| 보호 | OS serious/critical·배터리 하한·필수 잔량/열 상태 누락 시 중지·잠자기 요청·재개 거부. 선택적 섭씨값과 그 누락만으로 중지하지 않음 |
| 화면 회귀 | 일시 미확인 복구, 10초 지속 미확인·실제 켜짐 중지, 차단 유지, 시작 거부, 명시적 재개 |
| 진단 | 8회 DarkWake 사이클을 깨움 통지와 함께 또는 통지 없이 입력했을 때 집계 차이 |

`scenario`의 통과는 해당 도우미 제어 흐름의 검사 통과다. `reproduction`의 통과는 **지정한 문제 경로나 조건부 동작이 재현됐다는 뜻**이며 제품 문제가 해결됐다는 뜻이 아니다.

## 결과 읽기

- `summary.json`: 검사 대상 도우미 경로·SHA-256, 결과, 실제 전원 설정 전후 비교.
- 각 사례의 `trace.jsonl`: 입력, 소켓 응답, 실제 경과 시간, 상태.
- 각 사례의 `helper.log`, 상태·설정 파일: 종료 시 보존한 모의 도우미 증거.
- `result.json`: 통과 여부와 실패 시 예외. 한 사례가 실패해도 다른 사례의 결과를 보존한다.
- `host-before.json`, `host-after.json`: 실제 설정 해시·공개 소유권 상태·읽기 전용 `pmset -g custom`. 개인 root 소유권 파일의 권한을 변경하거나 읽지 않는다.

## 검증 경계

3분·1분 유지의 벽시계와 연속 시간 만료는 실제 경과 시간으로 검사한다. 센서 값과 AC 안정화용 `powerClock`은 모의 입력이다. AC 안정화·사용 한도 재설정의 시간 경계는 기존 `test-service.py`가 별도로 검사한다.

화면 절전, 시스템 Sleep/Wake는 입력으로 제공한다. 도우미가 올바른 명령을 요청했다는 결과를 실제 패널 꺼짐이나 물리 잠자기 성공으로 표시하지 않는다. GUI 버튼에서 소켓까지의 전달, 실제 IOKit 통지 유실, 독·원격 앱의 센서 보고도 여기서 확정하지 않는다. 앞선 물리 시험의 실패는 시뮬레이션 통과로 덮어쓰지 않는다.

빌드 49는 일시적인 화면 상태 미확인이 회복되면 유지를 계속한다. 재점등은 10초 관측 창과 사건당 최대 3회 요청으로 복구한다. 지속 켜짐이나 10초 지속 미확인은 중지한다. 이후 60초 동안 표본 간격 10초 이내로 정상 화면 절전이 관측됐을 때만 다음 사건의 복구 예산을 새로 부여한다. 통지에 의한 DarkWake 관측치는 완료된 잠자기 구간의 macOS 로그와 별도로 대조한다. 큰 로그에서도 8초 읽기 한도를 지키도록 파이프의 데이터 도착을 기다린다.

`python3 scripts/test-power-fixes.py`는 위 화면 처리와 기존 기록의 보정을 검사한다. 실제 시험과 같은 시각의 macOS 이벤트를 넣어 과거 0회가 8회로 보정되는지 확인하며, 불완전한 로그에서는 확인 표시를 붙이지 않는다. 실제 사고 순간의 화면 원시 입력이 기록되지 않았다면 과거 중지 원인을 확정하지 않는다.

## 빌드 49 시험 기준 보정

기존 보호 사례는 제거된 43°C 차단과 선택 온도 센서 누락 차단을 기대하고 있었다. 이를 새 계약에 맞춰 보정했다. OS 상태가 정상/주의이면 선택 센서 누락이나 합성 섭씨값 43/90만으로 중지하지 않는지 확인하고, OS 심각/위험·잔량 하한·필수 상태 누락 각각에는 유지 해제·닫힌 상태의 잠자기 요청·성급한 재개 거부가 모두 필요한 것으로 검사한다. 실제 기기를 가열하는 시험이 아니다.
