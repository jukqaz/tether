# Tether 기능 조정 구현·검증

2026-09-30 · 소스 변경에 대한 기록이다. 현재 설치된 앱은 `2026.9.1`, 빌드 `49`, 최소 OS `26.0`으로 확인했다. 이번 소스는 설치·배포하지 않았다. 기존 변경이 많은 작업 트리를 보존했으며, 이 문서의 구현 항목과 과거 빌드의 변경을 구별한다.

## 확정한 동작

원격 화면이 연결돼 있거나 끊겨도 사용자가 정한 작업 유지 규칙은 같다. 원격 연결 여부·앱 이름·추가 화면 존재를 작업 유지의 시작 또는 종료 조건으로 사용하지 않는다. 전원 조건, 유효한 수동 세션, 제한 시간, 직접 중지, 배터리·OS 발열 보호가 작업 수명을 결정한다. 원격 앱을 지정하거나 접속 확인을 통과해야 기본 기능을 쓰는 흐름은 없다.

| 상황 | 이번 구현 |
|---|---|
| 원격·가상·유형 미확인 화면 추가 | 유효한 자체 작업 유지 계속. 화면 하나만으로 macOS 기본 클램쉘 위임을 확정하지 않음 |
| 유지 중 화면 목록 조회 실패 | 소유하고 적용을 확인했던 유지 보존. 전원·시간·보호·직접 중지는 계속 평가. 새 전역 유지 획득은 관측을 기다림 |
| 화면 끄기 실패·재점등·관측 공백 | 화면 요청 횟수와 대기만 제한. 작업 종료나 배터리 타이머 소비로 번지지 않음 |
| 다른 앱의 유효한 화면 필요 요청 또는 요청 조회 실패 | 전체 화면 절전 명령 보류. 자체 시스템 유지·배터리 기한 계속 |
| 전원 조건 종료·타이머 만료·보호 | Tether가 추가한 유지 해제. 다른 앱의 작업 요청 보존 |
| 자동 시스템 잠자기 | 매 시도에서 외부 유지 요청 재조회. 요청 존재·조회 실패는 보류 사유로 기록 |
| 직접 누른 ‘지금 잠자기’ | 자동 종료와 다른 의도로 처리. 외부 전역 값을 임의로 해제하지 않음 |
| 이전 잠자기 재시도가 뒤늦게 실행됨 | generation이 달라지면 실행하지 않음. 새 사용자 의도의 횟수 예산과 섞지 않음 |
| 실제 물리 화면의 네이티브 위임 | 화면 존재와 검증된 위임을 별도 값으로 분리. 현재 실환경에서 위임 검증 값을 만드는 경로는 아직 미구현 |

다른 앱의 요청이 남으면 Tether를 종료해도 Mac이 계속 깨어 있을 수 있다. 이를 자체 유지 해제 실패나 충돌로 표시하지 않는다. 자동 해제와 Mac 전체 잠자기는 각각 관측해야 한다. 화면 잠금 정책도 작업 유지 상태와 별개이며 이번 변경은 OS 암호 요구·잠금 설정을 수정하지 않는다.

## 구현 범위

- `Policy`, `SleepRequestPolicy`, `Helper+Display`: 작업 유지·화면 요청·자동 잠자기를 분리했다. 기존 `displayConflict` 기록만 이관 시 해소하며 열·배터리 보호 차단은 유지한다. 미확인 외부 화면도 자체 유지의 보호 평가를 건너뛰게 하지 않는다.
- `IdleAssertionDriver`: 공개 IOKit의 프로세스 소유 `PreventUserIdleSystemSleep` 한 ID를 생성·갱신·해제한다. OS에 유한 만료를 두고, 해제 실패나 관측 실패 때 새 ID를 중복 생성하지 않는다. 1초 미만 남은 기한은 유지 종료로 처리해 정수 초 만료가 0으로 절삭되는 경로를 피한다.
- 실제 OS에서 단일 assertion 속성 조회가 활성 수준 255를 남기면서 활성 목록에는 없던 만료 사례를 확인했다. 현재는 자체 PID·ID·종류를 대조한 활성 목록을 함께 사용한다. 조회 실패·손상 결과를 성공이나 비활성으로 바꾸지 않는다. 초기 실패 로그도 보존했다.
- `MacCapabilities`, `IdleSessionPolicy`, `UserSessionController`: 데스크톱의 일반 작업 유지가 관리자 도우미 없이 동작하는 경로를 추가했다. 수동 시간 제한·무제한과 명시적으로 켠 AC 자동 유지의 유효한 사유를 통합한다. 기본 자동 유지는 꺼져 있으며 실제 assertion 적용을 확인한 상태를 표시한다.
- 소스 최소 OS는 macOS 15다. 노트북은 기존 도우미 제어 경로를 사용하고, 공통 사용자 조정자로의 완전한 통합은 남아 있다. macOS 15 실제 실행·모든 Apple Silicon 기기 동작을 완료한 것은 아니다.
- 보호 알림은 ‘Tether 유지 중단’으로 설명한다. 보호 결정 시각·잠자기 요청 수락·실제 OS Sleep을 같은 사건으로 표시하지 않는다. 다른 앱 때문에 자동 잠자기를 보류한 이유도 상태에 별도로 남긴다.

## 검증 결과

증거 폴더: `작업 폴더의 work/tether-implementation-20260930`. 테스트를 위해 실제 전원·덮개·화면·잠금 설정을 변경하지 않았다. 통합 시나리오는 격리된 도우미와 모의 OS 입력을 사용한다. 실제 IOKit 시험은 시험 프로세스가 소유한 유한 요청만 사용하고 종료 시 정리했다.

| 실제 IOKit assertion | 5개 통과. 생성·갱신·해제·공존·OS 만료 뒤 같은 ID 갱신 확인 | `native-final.log` |

실제 IOKit 시험에서 조사한 일차 자료는 로컬 SDK의 `IOPMLib.h`와 [Apple IOKitUser 소스](https://github.com/apple-oss-distributions/IOKitUser/blob/323ead896d04424f87184d8f6ff0cce811aab106/pwr_mgt.subproj/IOPMAssertions.c)다. 원문·commit·조사 기록은 증거 폴더의 `primary`에 보존한다.

## 배포 전에 남은 사항

1. 도우미·watchdog·설치/제거가 공유하는 recovery lock과 단계별 내구성 journal. 현재 전역 `SleepDisabled`에는 다른 앱과의 배타적 소유권·CAS가 없어 완전 무충돌을 보장할 수 없다.
2. 명령 타임아웃 뒤 자식 프로세스 사망 확인, 전체 작업의 session/action generation 계약, 로그인 세션 incarnation 확인. 이번 잠자기 retry generation 개선만으로 전체 계약을 완료했다고 하지 않는다.
3. 노트북·데스크톱 공통 조정자 통합과 데스크톱 CLI·진단 내보내기. 추가 상태 필드·화면 보류 phase의 앱/도우미·업데이트 호환성도 배포본에서 확인한다.
4. 전원·덮개 입력 자체의 unknown 보존 개선과 실측한 네이티브 위임 경로. 화면 unknown 유지 개선이 모든 센서 unknown 처리를 완료한 것은 아니다.
5. 실제 덮개 닫힘→전원 분리→Sleep→열림 Wake, 이미 잠든 닫힌 Mac의 전원 연결 깨움, 실제 원격 화면·입력·무잠금과 패널 절전의 양립, 장시간 유지·보호 지연.
6. macOS 15 실제 실행, 화면 없는 데스크톱, 기기·독·원격 앱별 확인. 수정 앱/도우미 설치 후 같은 경로의 로그 검증과 배포 준비.

현재 결론은 기능을 상충시키던 확인된 소스 경로를 개선하고 이 표의 범위를 통과했다는 것이다. 설치본 전체의 문제가 해결됐거나 모든 설계 계약이 구현·실측됐다는 판정은 아니다.
