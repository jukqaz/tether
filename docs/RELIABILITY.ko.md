# Tether 2.2.0 빌드 27 — 핵심 동작과 신뢰성 개선

> 빌드 27의 변경 이력입니다. 현재 동작은 [빌드 29 문서](COORDINATION.ko.md)를 우선합니다. 현재 빌드 28은 AC critical 추가 대기를 제거했습니다. 최신 근거는 [보호 기준 자료](PROTECTION-EVIDENCE.ko.md), 화면은 [디자인 검증](DESIGN.ko.md)을 따릅니다.
2026-09-28 공식 제품 설명 및 로컬 코드 기준. 경쟁 앱을 실기기에 설치해 동일 조건으로 성능 비교한 결과는 아니다. 기능 수, 소비 전력, 기기 수명 또는 무오류에서 모든 앱보다 우수하다는 뜻은 아니다.

## macOS 기본 클램쉘과 공존

[Apple의 닫힌 덮개 및 주변기기 안내](https://support.apple.com/en-ca/102282)와 [전원·외장 화면 구성 안내](https://support.apple.com/en-ca/117373)를 기준으로, 전원과 외장 화면이 있는 구성에서는 추가 잠자기 방지를 해제한다. 입력 장치 승인, 유휴 잠자기 및 화면 관리는 macOS가 판단한다. 앱은 주변기기 요건 충족이나 실제 물리 동작을 추정해서 보장하지 않는다.

| 상태 | 일반 동작 |
|---|---|
| AC + 외장 화면 | macOS에 맡김. Tether가 잠자기 금지나 전체 화면 끄기를 추가하지 않음 |
| AC + 외장 화면 없음 | 사용자가 선택한 전원 조건에 따라 Tether가 유지 |
| 배터리 | 수동/자동 제한 타이머가 있을 때만 Tether가 유지 |
| 기본 클램쉘 중 Tether 끄기·타이머 취소 | 외장 화면을 끄거나 강제 잠자기를 요청하지 않음 |
| 외장 화면 분리 | 현재 전원 조건을 재평가해 Tether 유지 또는 일반 잠자기로 전환 |
| 명시적인 잠자기 요청·보호 중지 | 일반 해제와 구분한 잠자기 요청 |

전체 스위치가 켜져 있고 AC를 포함하는 조건이면 기본 클램쉘에서도 과열·약한 충전기 보호를 감시한다. Tether를 끄면 그 추가 보호도 중지한다. 사용자는 별도의 macOS/Tether 모드를 선택할 필요가 없다.

도우미 고장 시 독립 감시는 같은 부팅의 변경 기록을 확인하고 Tether가 적용한 잠자기 금지만 해제한다. 그 이후 **배터리 + 닫힌 덮개 + full wake**에서만 추가 잠자기를 요청한다. AC 또는 전원 미확인 상태에서는 최신 외장 화면 구성을 신뢰할 수 없으므로 macOS의 기본 클램쉘을 강제로 중단하지 않는다. 이 비상 경로에서 AC의 물리 잠자기까지 보장하지 않는다.

## 사용 흐름 변경

- 충전 중 수동 타이머 시작: `전원 분리 대기`에 들어가며 시간은 아직 줄지 않는다. 분리되어 완전히 깨어 있는 상태일 때 시작한다.
- 이미 배터리 사용 중: 즉시 시작한다. 실행 중 다시 시작 요청은 거부하고 연장·종료만 허용한다.
- 예약 취소, 도우미 재시작, 알 수 없는 전원, Dark Wake 중 분리: 예약을 재생하지 않는다.
- 일반 15/30/60분 만료는 정상 종료다. 자동 재시작하지 않지만 사용자가 원래 배터리 허용 시간 안에서 다시 시작할 수 있다.
- 공통 최대 배터리 시간 소진은 `budget` 보호 중지다. 충전 후 명시적으로 재개해야 한다. 기존 버전의 `time` 중지는 안전하게 기존 차단 의미를 유지한다.
- 과열·센서·잔량 보호는 기존처럼 원인이 해소된 뒤 직접 재개한다.
- 알림을 허용하고 메뉴바 앱이 실행 중이면 배터리 타이머 종료 1분 이내에 한 번 알린다. 빌드 29에서는 앱 종료 시 현재 유지와 예약도 끝나며, 설정 창만 닫으면 계속 동작한다.

## 내부 개선

- 직렬 `ServiceConnection` actor가 UI 밖에서 IPC를 처리한다. 응답 확인 후 상태를 갱신하며 오래된 읽기 응답이 새 명령 결과를 덮지 않게 한다.
- 앱은 한 서비스 응답의 설정·관측·보호 이유를 함께 사용한다. 단순 snapshot 요청은 정책 실행이나 파일 쓰기를 일으키지 않는다.
- 평상시 앱 보조 조회는 5초에서 15초로 줄였고, 도우미 상태 변경 알림은 즉시 처리한다.
- 도우미의 3초 타이머는 배터리 유지나 보호 감시가 진행 중일 때만 생성한다. 평상시 30초 안전 점검은 유지한다.
- 진단 페이지의 시스템 조회도 UI 밖에서 실행하고 15초 간격으로 제한한다.
- 외부 명령에 시간 제한과 출력 상한을 적용한다. 전원 변경은 2초 뒤 시간 초과로 처리하며 종료 신호를 무시하는 프로세스도 정리한다.
- AC 과열·약한 충전기의 지속시간을 단조 시간 기준으로 계산한다. 과열 경고는 60초, 보호 잠자기는 120초로 순서를 바로잡았다.
- watchdog은 30초 간격, 마지막 상태 갱신 이후 90초 이상일 때 동작한다. 실제 실행 시점은 launchd 스케줄에 따라 늦어질 수 있다.
- 상태 저장 실패 시 보호 차단. 저전력 명령 실패 시 적용했다고 표시하지 않고 다시 시도하며, 복원 실패 시 원래 값을 버리지 않는다.
- 사용하지 않는 실행 중 통계 요약 계산을 제거했다. 구버전 이관에 필요한 계산은 보존한다.

## 저전력·고성능 모드 호환성

현재 Mac의 읽기 전용 `pmset -g custom` 결과는 `powermode`를 사용한다. [Apple의 pmset 소스](https://github.com/apple-oss-distributions/PowerManagement/blob/main/pmset/pmset.m)는 고성능 모드를 지원하면 0/1/2, 그렇지 않으면 `lowpowermode`의 0/1을 표시한다고 설명한다.

두 형식을 모두 읽고 변경·복원 명령에 같은 키를 사용한다. 기존 고성능 값 2도 보존하며 자동 값 0으로 잘못 복원하지 않는다. 원래 값을 읽을 수 없으면 임의로 0이라고 가정하지 않는다. 사용자 변경이 관측되면 그 설정을 우선한다. 실제 모드 전환은 아직 실기기에서 실행하지 않았다.

## 호환성과 검증 경계

저장 schema와 IPC 버전은 2를 유지한다. 예약 시간은 선택 필드이며 기존 schema 2 설정을 그대로 읽는다. 새 `startHold` 요청을 모르는 구형 도우미에서는 실행되지 않으며, 새 앱은 구형 도우미에서 시작 버튼을 비활성화한다. 기존 enabled/전원 조건/잔량/최대 시간/저전력 선택은 유지한다. 도우미 재시작 시 일회성 예약과 타이머는 재생하지 않는다.

자동 검증은 순수 정책, 실제 helper/CLI의 격리된 dry-run, 설치 실패·복구, 업데이트 서명 검증을 대상으로 한다. 실제 관리자 설치, 물리 전원·덮개·디스플레이 절전·원복, 외장 화면의 연결 전환은 별도 실기기 검증이 필요하다. 미리보기는 모의 전원·온도만 사용한다.

## 빌드 27 검증 결과

- 단위 테스트 202개, 실제 helper/CLI dry-run 통합 시나리오 38개, 설치기 성공·실패·복구 시나리오 4개 통과.
- AC·외장 화면 인계, 일반 끄기·취소, 외장 화면 분리, 배터리 전환, 예약 취소·재시작·Dark Wake, 정상 만료와 공통 시간 소진, 전원 명령 실패·재시도를 검증했다.
- 격리된 서비스의 snapshot 100회 호출은 0.011초였으며 정책 재실행이나 상태 파일 쓰기를 일으키지 않았다. 이 수치는 전체 앱의 전력 소비나 다른 제품과의 성능 비교가 아니다.
- 조작 가능한 dry-run 미리보기에서 전원 분리 예약 → 배터리 타이머 시작 → 연장 → 종료, 기본 클램쉘 표시, 일반 끄기·켜기, 간단히 보기의 예약 취소를 확인했다.
- 릴리스 앱과 미리보기 빌드 및 코드 서명 검사를 통과했다. 개인 개발용 ad-hoc 서명이며 Developer ID 서명·공증·공개 배포는 하지 않았다.
- Sparkle 실제 엔진의 합성 앱 업데이트 성공·ZIP 변조 거부·피드 변조 거부 3개는 빌드 24 작업에서 통과했다. 빌드 27에서는 해당 엔진 시험을 반복하지 않았으며, 이번 릴리스 파일과 서명된 피드를 새로 생성했다.
