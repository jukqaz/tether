# Tether 기능명세서

2026-11-10 · 제품 컨셉: **기능은 넓게, 기본 화면은 간단하게 + 안정성** · 기본 자동 모드: 전원 연결·해제

## 1. 이 문서의 역할

이 파일이 현재 기능 범위·기본값·전원/종료 규칙의 유일한 기준이다. 요구사항 확정과 앱 구현 완료는 다르다. 현재 소스에는 전원 중심 기본 자동 모드와 전원·덮개/수동 유지/보호·진단/일반의 4페이지 구성을 연결했다. §9의 확장 옵션은 연결된 기능과 미구현·후속 후보를 나누며, 목록 자체를 구현 완료로 보지 않는다. 자동 검증 결과는 기능 감사와 연결된 보고서에서 관리하며, 설치·물리 시험·배포는 별도 인수다.

2026-10-29 사용자는 조사한 Keepresso·Amphetamine의 기능을 옵션으로 폭넓게 제공하고 보기 쉽게 배치하도록 범위를 확장했다. §9가 추가 옵션의 현행 범위다. 이전의 확장 보류·기본 화면 제외는 새 기능 목록에서 삭제한다는 뜻으로 쓰지 않는다. 기본값·현재 작업·설치본은 이번 문서 변경으로 바꾸지 않는다. 지원 조사·명세·시안·구현·검증을 구분하며, §9의 목록 자체를 지원 완료로 표시하지 않는다.

- 기능과 규칙: 이 문서. 표시 문구: [문구 사전](COPY-V5.ko.md). 화면 구성: [화면 설계](DESIGN-V5.ko.md). 색·치수·컴포넌트: [디자인 가이드](../DESIGN.md).
- 검증할 조건: [검증 체크리스트](V5-VALIDATION-CHECKLIST.ko.md). 실제 실행 근거: [기능 감사](FUNCTION-AUDIT.ko.md)와 연결된 결과 보고서. 명세에 시험 통과 수를 중복 기록하지 않는다.

### 2026-11-10 승인된 제품 구성

- 메뉴는 현재 상태에 따라 대기·자동·수동·중지를 표시하는 한 표면이다. 설정은 전원·덮개, 수동 유지, 보호·진단, 일반의 4페이지를 유지한다. 시작하기의 도우미 필요·준비 완료도 별도 제품 탐색 항목이 아닌 같은 흐름의 상태다.
- 일반 macOS bordered 컨트롤과 불투명 읽기 표면을 사용한다. custom Liquid Glass·glassEffect·glassProminent를 사용하지 않는다. 그래파이트 + 블루와 시스템 입력·포커스 동작은 유지한다.
- 수동 기능은 다음 시작용 초안으로 적용·변경 취소한다. 전원 범위·배터리 한도는 별도로 즉시 저장한다. 앱 전체 화면·덮개 허용과 유지별 기능 선택은 서로 다른 범위다.
- 일반의 알림은 접힌 상세에서 즉시 저장한다. 업데이트 채널은 일반 한 곳에서 편집하고 설치는 명시 확인한다. 설정 가져오기는 파일 선택 뒤 검토하며 비활성 사본으로 저장한다.
- 명령 안내와 작업 이벤트 연동은 일반의 고급 연동에서 제공한다. CLI `manual 30m`, `manual +15m`, `manual off`와 대응 URL을 사용하며 `run`·`manual --pid`는 제공하지 않는다. 구조화 작업 이벤트와 고급 자동 프로세스 조건의 별도 지원은 보존한다.
- 중복 전체 옵션 카탈로그와 미지원 로드맵은 제품 주 동선에서 제외한다. §9의 승인 옵션·저장값은 삭제하지 않고 각 기능의 담당 페이지·편집창으로 접근한다. 미지원 저장 조건은 해당 규칙에서 이유를 표시한다.
- 보호 중지의 안전 확인·재개와 진행 중 기록의 종료 조작은 상세 접힘 밖에 둔다. 자동만 일시 중지는 수동의 원래 기한을 보존하며, 모두 중지·보호·잠자기로 끝난 수동 유지는 재개나 Wake로 복원하지 않는다.
- 앱 종료는 자체 유지를 끝내고 변경한 전원·화면 상태를 복원하는 동작이다. 저장한 환경설정은 유지한다. 이번 UI 적용을 설치본·물리 Sleep/Wake·실제 권한·전원 시험의 통과로 해석하지 않는다.
- 이전 v4/v5 명세와 41개 확장 조사·과거 디자인/시험 기록은 [문서 안내](README.md)에서 구분한다. 옛 문서의 ‘현재·최종·완료’는 그 문서가 작성된 시점에 한정한다.

## 2. 목적과 범위

전원이 연결된 Mac에서는 선택한 작업을 유지하고, MacBook 덮개를 닫아도 계속 사용할 수 있게 한다. 기본 전원 분리는 기존 Tether 작업을 모두 끝내며, 배터리에서 필요하면 사용자가 별도로 타이머를 시작한다. 현재 동작과 중지 이유를 짧게 설명하고, 문제는 제한된 로그로 확인한다.

- 지원 목표: **macOS 26 이상 · Apple Silicon MacBook과 데스크톱 Mac**. 지원 목표가 전기종 물리 검증 완료를 뜻하지 않는다.
- 일반 잠자기 방지는 도우미 없이 사용한다. MacBook 덮개 기능을 선택할 때만 도우미 준비·정상 관리자 인증을 요구한다. 인증 자체로 자동 시작·덮개 사용·새 타이머를 켜지 않는다.
- 데스크톱에는 덮개·내장 배터리 옵션과 덮개 도우미 설치 요구를 표시하지 않는다. 밝기 기능은 확인된 내장 화면에만 한정한다.
- 기존 승인 옵션·설정값을 이 문서 정리로 삭제하거나 실행 중인 앱에서 임의로 끄지 않는다. 이번 자동화 범위 축소는 F02의 전원 전용 전환 계약을 따르며, 비전원 조건 데이터를 보존하는 것과 계속 실행하는 것을 구분한다.

## 4. 제공할 기능

### F01. 직접 시작과 시간

- 메뉴바에서 30분·1시간·2시간을 고른 뒤 **직접 시작**한다. 시간 선택만으로 시작하지 않는다. 전원 연결 중에는 **끄기 전까지**를 보조 선택으로 제공한다.
- 실행 중에는 남은 시간·끝날 시각, **30분 추가**, **타이머 끝내기**를 표시한다. 무기한 작업에는 의미 없는 남은 시간·추가 버튼을 숨긴다.
- 시간제 요청은 하나다. 현재 타이머 조작과 다음 시간 선택을 구분하며, 다음 선택이 실행 중 기한을 바꾸지 않는다. 기존 고급 시간 선택값은 보존하되 기본 메뉴를 늘리지 않는다.
- 기본 경과시간 타이머의 기간은 잠자기·전원 연결 중에도 흐른다. §9의 활성 시간 타이머는 별도 종류의 확장 후보이며 기존 타이머의 계산을 바꾸지 않는다. 연장은 명시한 분량 전체가 허용될 때만 수행하고, 일부 연장이나 새 타이머로 조용히 대체하지 않는다.
- 배터리 상한은 시작 때 선택을 캡처하고 최초 배터리 사용 때 기준을 정한다. 전원 왕복·일시중지·연장·앱 재연결로 초기화하지 않는다. 상한은 배터리에서 집행하며, 원래 타이머 마감은 전원 연결 중에도 경과한다.

### F02. 자동 시작

- 기본 자동 모드는 **전원 연결·해제**다. **전원이 연결되면 자동 시작** ON/OFF를 제공하며 사용자가 허용한 상태에서 깨어 있고 전원·보호·실행 조건이 확인되면 시작한다. 충전 중 여부가 아니라 현재 전원 공급을 확인한다. 추가 조건은 §9의 선택적 고급 규칙에서 다루며 새 설치에 켜지 않는다.
- 전원 해제는 F03의 종료·계속 정책을 적용하는 사건이다. 새 배터리 자동 작업을 시작하는 조건으로 쓰지 않는다. 배터리에서는 사용자가 직접 타이머를 시작할 수 있다.
- **자동만 쉬기**는 30분·1시간·직접 재개할 때까지다. 수동 타이머와 저장된 자동 ON/OFF는 바꾸지 않는다. 시간 경과나 **자동 재개** 시 현재 조건을 새로 확인한다.
- 앱·시간표·외장 화면·USB·Bluetooth·Wi-Fi와 조건 조합·프로필 편집은 고급 옵션으로 범위에 포함한다. 전원 전용 모드에서는 이들 조건을 위한 관측·권한 요청·새 시작/갱신을 수행하지 않는다. 고급 규칙도 기본 AC 허가·분리 정책·보호·사용자 중지보다 우선하지 않는다. 기기 보호를 위한 배터리·열 관측은 계속한다.
- 기존 고급 조건·전원 범위·프로필 데이터와 호환 코드는 삭제하지 않는다. 비전원 조건을 쓰던 사용자는 **전원만으로 자동 동작** 전환 시 고급 조건 실행 중단과 저장값 보존을 확인할 수 있어야 한다. 전환 전 호환 경로가 실행 중이면 **기존 자동 규칙 사용 중**과 현재 규칙·전환 진입을 표시하며 전원 전용인 것처럼 숨기지 않는다. 전환 후 두 경로를 동시에 평가하지 않고 설정 가져오기만으로 비전원 조건을 활성화하지 않는다.
- 자동과 타이머가 함께 실행될 수 있다. 타이머만 끝나고 자동이 유효하면 **타이머 종료 · 자동 잠자기 방지 중**으로 표시한다. 끝난 타이머를 복원하지 않는다.
- 잠든 Mac을 전원 재연결만으로 반드시 깨우는 기능은 제공하지 않는다.

### F03. 전원을 뺐을 때

| 선택 | 동작 |
|---|---|
| **잠자기 방지 모두 끝내기** · 기본 | 기존 자동·타이머·연결 작업을 종료. 배터리 타이머는 사용자가 별도로 시작 |
| **자동만 끝내기** · 기존 고급 선택 | 자동은 종료. 배터리 사용이 허용된 수동 타이머만 원래 기한·상한 안에서 계속 |
| **배터리에서 허용한 작업은 계속** · 기존 고급 선택 | 이미 배터리 실행이 허용된 유효 작업만 같은 작업·원래 기한·최초 배터리 상한으로 계속 |

- 전원 분리는 종료 정책을 먼저 적용한다. 같은 분리 사건을 새 배터리 자동 시작으로 바꾸지 않는다. 과거의 ‘분리 직후 자동 시작’ 데이터는 호환 이관 대상으로만 보존하고 전원 전용 동작에 추가하지 않는다.
- 계속할 작업이 없고 덮개가 닫혀 있으면 **Mac 잠자기 요청 / macOS에 맡기기** 중 저장된 종료 동작을 적용한다. 유효 작업이 남아 있으면 이 종료 동작으로 잠자기를 요청하지 않는다.
- 전원 재연결은 끝난 타이머를 되살리지 않는다. 자동이 허용돼 있으면 사용자 중지·보호·복구 차단을 먼저 확인한 뒤 새 자동 시작만 평가한다.

### F04. 덮개를 닫아도 계속 사용

- 독립 ON/OFF 선택이다. 켜도 새 작업이 시작되지는 않으며 유효한 자동/직접 시작 작업에만 덮개 허용을 적용한다.
- 도우미 준비·지원·실제 적용을 확인한다. 준비가 안 됐으면 덮개 기능만 제한하고 일반 잠자기 방지는 사용할 수 있게 한다.
- 작업 중 주 옵션을 변경할 때는 현재 적용되는 기본값 사용 작업과 다음 작업에 미치는 영향을 표시한다. 작업 ID·마감·전원 범위는 바꾸지 않고 개별적으로 꺼 둔 선택을 몰래 켜지 않는다.
- 끄면 Tether의 덮개 유지 요청을 회수한다. macOS나 다른 앱이 그 뒤 어떤 동작을 할지는 별도다. 덮개를 닫았다는 이유만으로 강제 잠금·잠금 해제를 실행하지 않는다.

### F05. 덮개와 내장 화면

덮개 유지 ON 아래에 **덮개를 닫으면 내장 화면을** 선택기를 둔다. OFF에서는 값을 접어 보존하며 실행하지 않는다.

| 선택 | 설명 |
|---|---|
| **화면 끄기** · 기본 | 내장 화면 끄기를 요청. 실제 패널 전력 0의 증거로 표시하지 않음 |
| **밝기 0으로 낮추기** | 화면을 끄는 요청 대신 밝기만 0으로 낮춤. 원격 화면이 필요한 환경에서 선택·시험 가능 |
| **변경하지 않기** | Tether가 내장 화면 밝기·절전 상태를 별도로 바꾸지 않음. macOS·타사 동작은 계속 적용 |

- 열린 동안의 **화면 켜두기**와 닫힌 내장 화면 선택을 같은 판단 경로로 조정한다. 별도 제어 루프가 서로 덮어쓰지 않으며 외장 화면을 이 선택으로 변경하지 않는다. 필수 화면 요구와 충돌하면 파괴적 변경을 보류한다.
- 밝기 0은 원본 읽기·변경·재조회·지속 복구 기록과 해당 기기/OS 지원이 확인된 경우에만 제공한다. 원본을 읽지 못하거나 대상이 미확인이면 낮추지 않는다.
- 열림·마지막 덮개 작업 종료·보호·종료/재실행 뒤 자체 변경을 복구한다. 사용자가 바꾼 밝기는 반복해서 0으로 강제하거나 과거 값으로 덮어쓰지 않는다. 복구 실패 기록은 보존한다.
- 미지원·실패를 성공으로 표시하거나 다른 화면 모드로 몰래 전환하지 않는다. 실패 때문에 무관한 일반 잠자기 방지까지 종료하지 않는다.
- **화면 꺼짐·밝기 0·잠금·실제 잠자기·원격 프레임/입력은 별개**다. 원격 접속 감지로 전용 화면·별도 자동 정책을 만들지 않고, 잠금/암호 설정을 무단 변경하거나 자동 잠금 해제를 제공하지 않는다.
- 이 세 화면 선택과 지속 복구는 구현 후보에 연결했다. 밝기 0은 현재 외장·가상 화면이 없는 단일 내장 패널에서만 지원 후보로 제공하며, 해당 기기의 실제 닫힘·원격 동작은 미검증이다. [Keepresso 공식 설명](https://keepresso.com/help/keep-macbook-awake-lid-closed)과 참고 코드는 동작 방식의 근거이며 Tether의 구현·물리 성공 근거가 아니다. 밝기 API는 조건부 비공개 어댑터이며 실패 시 다른 화면 모드로 전환하지 않는다. 기기 호환성·배포 인수는 별도다.

### F06. 기기 보호

- OS 열 상태와 배터리 잔량에 따라 자체 유지를 중지한다. 새 설치는 심각/위험 열 상태 중지이며 위험 상태는 항상 중지한다. 센서 온도 숫자를 기종 공통 하드웨어 위험 온도로 쓰지 않는다.
- 배터리 기준, 승인된 최대 시간, 저전력 모드 중지, 심각 열 중지, 자동 회복 선택은 고급에서 보존한다. 낮은 배터리만으로 정상 전원 연결 중인 작업을 배터리 부족으로 오판하지 않는다.
- 기본은 직접 다시 허용이다. 선택적 자동 회복도 안전한 최신 관측이 60초 이어진 뒤 유효한 자동 조건만 평가한다. 배터리는 정상 전원 연결 또는 하한보다 5%p 높은 잔량의 안정 조건을 함께 확인한다.
- 보호로 끝난 타이머·연결 작업을 부활시키지 않는다. 알림 OFF나 앱 UI 응답 지연이 보호 중지를 늦추지 않는다.

### F07. 중지·종료·복구

| 조작 | 범위 |
|---|---|
| **타이머 끝내기** | 직접 시작한 타이머만 종료. 유효한 자동 작업은 계속 |
| **자동 시작 끄기** | 자동만 종료·비활성화. 직접 시작한 타이머는 계속 가능 |
| **자동만 쉬기** | 정한 기간 자동만 잠시 중단. 타이머와 저장한 자동 선택은 보존 |
| **모두 중지** | Tether 작업 모두 종료 + 직접 다시 허용할 때까지 자동 시작 차단 |
| **다시 허용** | 중지 차단 해제 후 현재 자동 조건 평가. 끝난 타이머 복원 없음 |
| **앱 종료** | 기본은 자체 유지 해제·자체 변경 복구 후 종료. 미확인/실패를 숨기지 않음 |

- 전원 분리·배터리 수동 만료로 마지막 닫힌 작업이 끝날 때는 선택한 잠자기 요청/OS 위임을 적용한다. 그 밖의 일반 작업 완료·자동 조건 해제·취소는 기본적으로 macOS에 맡긴다.
- 잠자기 요청의 수락과 실제 잠자기를 구분한다. 출처가 확인된 Tether 명시 잠자기는 **수락 때 자동 재시작 차단을 저장**하며, 호출 실패·Wake만으로 해제하지 않는다. 그 뒤 선택된 새 실제 전원 사건·자동 조건의 false→true·명시 재개에서만 재평가하고 모두 중지·보호·복구 차단을 먼저 지킨다. 일반 fullWake의 새 자동도 신선한 관측·시작 권한·기존 차단과 같은 자동 활성 사건의 최초 배터리 기준/상한을 보존하며, 끝난 수동 작업은 복원하지 않는다.
- 자기 요청·자기 임시 변경만 회수한다. 다른 앱의 요청이나 출처가 확인되지 않는 전역 값을 임의로 해제하지 않는다. 정상 종료·충돌·서비스 재시작·로그아웃·재부팅에 오래된 작업을 재생하지 않는다.
- 승인된 백그라운드 지속 선택은 기본 종료와 구분해 보존한다. 유효한 기존 작업·원기한·유한 허가에 한정하며 비정상 서비스 재시작으로 옛 작업을 복구하지 않는다. 새 지속 옵션을 기본 UI에 추가하지 않는다.

### F08. 통계

- 설정의 접힌 **사용 통계**에서 최근 7일의 덮개를 닫고 유지한 시간, 배터리로 유지한 시간, 보호 중지 횟수를 우선 제공한다. 메뉴에 별도 통계 카드를 두지 않는다.
- 장기 기록·복잡한 대시보드·성능 점수·에너지 절감 추정치는 이번 범위에 넣지 않는다. 센서 온도·배터리 잔량 변화는 지원될 때 진단 상세로만 제공한다.
- 관측이 끊긴 시간을 유지 시간으로 채우지 않는다. 읽을 수 없는 값은 없거나 미확인으로 표시한다. 배터리 잔량 변화는 Tether만의 소비량이라고 표시하지 않는다.
- 기존 도우미에 일별 집계·덮개/잠자기 기록 모델이 있으나 모든 Mac·일반 사용자 실행 경로에서 동일한 통계가 수집된다고 간주하지 않는다. 작은 요약 UI·공통 수집 경로는 구현 확인 대상이다.

### F09. 로그와 다른 앱 확인

- **최근 동작**에서 시작·기한 변경·종료 이유·전원 전환·보호·도우미/복구 실패의 제한된 기본 기록을 확인한다. **로그와 보고서**의 상세 기록은 15분·1시간·4시간 선택 후 자동 종료한다.
- 보관 중인 최근 기록 1/6/24/72시간 범위로 보고서 저장·복사를 제공한다. 보관 한도·누락을 표시하며 선택한 시간 전체가 반드시 남아 있다고 약속하지 않는다.
- 일반 사용자 경로의 macOS 로그·최근 메모리 기록과 도우미 로그 파일을 구분한다. 무제한 파일 누적·자동 업로드·Desktop 자동 저장을 하지 않는다. 사용자/Mac 이름·요청 원문 등 민감 정보를 최소화한다.
- **다른 앱의 잠자기 방지 요청**은 문제 확인 안에 접어 둔다. Tether 중지 후에도 실제 요청이 관측되면 메뉴에 요약 한 줄과 상세 진입을 제공한다.
- 상세는 앱/프로세스 이름, **컴퓨터 잠자기 방지 / 화면 꺼짐 방지**, 확인 시각, 확인된 대상의 **앱 열기**를 제공한다. 설치된 앱/실행 중이라는 사실만으로 충돌을 확정하지 않는다.
- 조회 실패는 실패로 표시한다. 요청 0개로 바꾸지 않으며 다른 앱을 자동 종료·제거하거나 요청을 회수하지 않는다. 기본 로그 삭제와 복구에 필요한 저널 삭제는 분리한다.

### F10. 알림

- 타이머 종료 알림과 선택적 만료 예고를 별도로 제공한다. 예고 기본은 OFF/5분 전 한 번이며 보호·실패 안내와 구분한다. 기존 승인 선택값은 보존한다.
- 예고·종료 알림이 꺼져도 타이머 종료·전원 분리·보호·복구는 동작한다. 알림 권한은 필요할 때 정상 OS 경로로 요청하며 거절해도 핵심 기능은 사용 가능하다.
- 알림에서 연장을 선택해도 현재 요청·기한·배터리 한도를 재확인한다. 옛 알림은 끝난 타이머를 재시작하지 않는다. 반복 예고·반복 소리는 새로 추가하지 않는다.

### F11. 앱 설정과 업데이트

- 로그인 시 앱 실행, 언어, 시스템 외관 따르기, 선택적 메뉴바 남은 시간, 도우미 준비/복구, 현재 버전과 업데이트 확인을 제공한다. 로그인 실행과 자동 잠자기 방지 시작은 구분한다.
- 메뉴바 남은 시간은 확인된 유한 타이머만 짧게 표시한다. 보호·모두 중지·만료·미확인을 오래된 숫자로 덮어쓰지 않는다.
- 채널은 **정식 / 정식 + 베타** 두 개다. 저장된 선택이 없는 새 설치는 정식 배포본에서 정식, 베타 번들에서는 정식 + 베타로 시작한다. 현재 베타 번들도 이 예외를 따르며 기존 선택은 보존한다. 베타에서 정식으로 바꾸면 현재 버전보다 새로운 정식을 기다리며 강제 다운그레이드하지 않는다.
- 업데이트 자동 확인과 실제 설치는 별개다. 직접 설치를 선택해야 하며, 진행 중인 작업을 몰래 끝내거나 작업 종료 후 설치를 예약하지 않는다. MacBook은 열린 덮개와 안전한 교체 조건을 확인한다. 덮개가 미확인이면 설치 가능으로 간주하지 않는다.
- 서명·패키지·앱/도우미 계약 호환성·설정 이관·부분 실패·취소·채널 변경을 검증한다. 안전하게 교체할 수 없으면 기존 작업을 보존하고 이유를 표시한다. 실패 시 복구 경로·원본 설정을 보존하되 자동 다운그레이드를 약속하지 않는다.

## 5. 충돌과 실패를 다루는 공통 규칙

1. 한 실행 소유자가 **실행 권한 → 보호/모두 중지 → 확정 전원 정책 → 마감·상한 → 새 명시 조작 → 자동 조건** 순서로 판단한다. 메뉴·설정·기존 CLI가 독립 제어 루프를 만들지 않는다.
2. 전원·열·실행 소유가 미확인이면 새 시작·연장·덮개 획득/갱신을 허용하지 않는다. unknown을 전원 분리나 정상 상태로 해석하지 않는다.
3. 기존 유지의 관측 공백은 원래 마감·기존 유한 허가·마지막 정상 관련 관측+15초 중 먼저 끝나는 시점까지만 추가 갱신 없이 인정한다. 확인된 분리·위험·만료는 즉시 우선한다.
4. 종료 결정 즉시 요청과 갱신 권한을 끝내고 자체 해제를 시도한다. 정리 최대 60초는 추가 유지 시간이 아니다. 원복 확인·현재 조건 재검사 뒤의 후속 행동은 15초 안에 한 번만 유효하며, 늦은 응답으로 다시 발급하지 않는다.
5. 새 작업·전원 재연결·소유자 변경은 해당 이전 종료 행동의 유효성을 다시 검사해 오래된 행동을 취소한다. **덮개 열림은 닫힘 조건부 잠자기만 취소**하며, 열린 Mac에서 사용자가 명시한 잠자기는 별도로 허용한다. 이미 OS에 파견한 명령이 항상 취소된다고 약속하지 않는다.
6. 설정 선택·명령 수락·실제 적용·원래 설정 복구·OS 잠자기는 별도 사실이다. 실패 상태에는 이유와 확인된 해결 조작을 제공하고 내부 토큰/TTL을 기본 화면에 노출하지 않는다.

## 6. 화면과 용어

- 메뉴바: 현재 상태/이유 → 실행 중인 타이머 조작 또는 새 시작 → 덮개·화면 빠른 조작 → 필요한 상세 → 모두 중지·설정. 시간 선택과 현재 작업 종료는 같은 의미로 표현하지 않는다.
- 설정은 사이드바의 **전원·덮개 / 수동 유지 / 보호·진단 / 일반** 4페이지다. 자동 시작·전원 분리·화면/덮개 허용·도우미는 전원·덮개, 다음 수동 기능·전원 범위·배터리 시간 한도는 수동 유지, 보호 기준·사용 통계·최근 동작·다른 앱 요청·로그와 보고서는 보호·진단, 로그인·메뉴 표시·언어·알림·업데이트는 일반에 둔다. 분리 정책 편집기를 여러 페이지에 중복 배치하지 않는다.
- 평소에는 상태·남은 시간·가능한 조작만 표시한다. 상세는 접되 보호/원복 실패와 필수 해결 조작은 숨기지 않는다. 메뉴와 설정의 선택값·실제 상태는 일치해야 한다.
- 쉬운 표현: AC→전원 연결 중, 클램쉘→덮개를 닫아도 계속 사용, 트리거→자동 시작 조건, 원복→원래 설정으로 되돌리기. 로그 내부 식별자는 그대로 유지할 수 있다.
- 실제 디자인 치수·색·글자 크기는 [디자인 가이드](../DESIGN.md)에서만 관리한다. 한영·밝음/어두움·상태별 펼침/스크롤 검수는 검증 목록에서 추적한다.

## 9. 선택적 기능 확장 · 2026-10-29

### 범위와 기본값

사용자 승인 방향은 **경쟁앱의 기능을 넓게 옵션으로 제공하고, 기본 화면은 간단하게 유지**하는 것이다. 아래 O01~O26은 기능군 전체 목록이다. 중복은 하나의 옵션으로 합치고 다른 의미는 분리한다. 기존 F01~F11을 대체 구현하거나 이미 검증된 것으로 세지 않는다. 각 항목의 상태는 `명세 / 시안 / 구현 / 자동 검증 / 실제 환경 확인`으로 따로 기록한다.

- 기본 메뉴는 30분·1시간·2시간, 현재 작업의 연장/종료, 자동 쉬기, 덮개/화면, 모두 중지/설정이다. 고급 선택은 기본 메뉴를 영구히 늘리지 않는다.
- 새 고급 규칙·hook·외부 도구·디스크/활동/장치 제어는 OFF 또는 빈 목록에서 시작한다. 열어 보기·설정 가져오기·업데이트만으로 켜지 않는다.
- 기본 자동 모드는 AC 전용이다. 고급 조건을 추가해도 전원 분리·사용자 중지·보호·복구 차단을 우회하지 않는다. 새로 도입할 배터리 자동·배터리 무제한·보호 무시와 같은 경쟁앱 선택지는 비교 목록에서 지우지 않되, 현행 핵심 계약과 충돌하는 예외로 표시하고 별도 확정·지원 검증 전 실행하지 않는다. 이 제한을 이유로 이미 승인·저장된 배터리 한도를 금지하거나 초기화하지 않으며 기존 값은 F01/§7대로 보존한다.
- 적용 범위는 `이번 작업만 / 다음 작업 기본값 / 이 자동 규칙 / 앱 전체`로 구분한다. 같은 저장값을 다른 화면에서 편집하는 것은 중복 기능이 아니다. 설정 변경만으로 현재 작업 ID·마감·소비한 배터리 한도를 다시 만들지 않는다.

아래의 승인 후보 목록은 향후 범위를 보존하는 문서다. 명령/PID 수동 수명 연결을 현행 CLI 지원으로 소개하지 않는다. 현재 제공되는 수동 명령 제어, 고급 자동 프로세스 조건, 구조화 작업 이벤트는 각각의 실제 실행 경로로 구분한다.

### 충돌 조정

1. 사용자 전체 중지·확정 보호·복구 실패 차단은 자동 규칙·수동 연장·외부 도구보다 우선한다. 규칙 간 우선순위로 이를 뒤집지 않는다.
2. 전원 분리는 동일 사건에서 종료/계속 판정을 한 번 한다. 고급 조건·hook·예약이 끝난 요청을 즉시 재생하지 않는다. 분리 계속 선택의 실제 결과가 같은 기본 모드에서는 합쳐 표시하고, 외부 작업 등 결과가 달라지는 고급 범위에서만 대상 차이를 설명한다.
3. 자동+수동 병존을 기본으로 한다. 경쟁앱식 수동 우선/자동 쉬기는 선택적 제어 방식으로 분리하고, 바꾸기 전 현재 자동·타이머에 미칠 영향을 표시한다.
4. N분 추가와 지금부터 N분 뒤 종료는 서로 다른 버튼·기록이다. 기본 경과시간은 F01을 유지한다. 활성 시간은 별도 타이머 종류로 두고 Sleep/일시정지의 계산·최종 마감 계약을 확정하기 전에는 실행하지 않는다. 이 종류를 제공해도 최초 배터리 안전 상한·lease 기한은 멈추거나 리필하지 않는다.
5. 유휴 화면 허용과 유휴 밝기 낮춤은 한 화면 정책에서 고른다. 닫힌 내장 화면·열린 화면·외장 화면·활동 입력이 각각 제어 루프를 만들지 않는다.
6. 종료 행동은 원인·대상·최신 조건을 검증한다. 새 작업/명시 재개가 생기면 오래된 행동은 취소하며 수면 뒤 밀린 행동을 실행하지 않는다. 원복 미확인 상태를 확인 없이 잠금/강제 명령으로 덮지 않는다.
7. hook 실패가 핵심 종료·보호를 막지 않는다. 사용자가 저장·허용한 작업만 실행하며 실행 시간·동시 실행·재시도·오래된 사건·자격증명 처리의 계약을 구현 전에 정한다. 가져온 설정으로 명령을 자동 실행하지 않는다.
8. 팬·저전력·밝기·음량·디스크·예약 등 자체 변경에는 하나의 소유/원복 경로를 둔다. 지원 확인 없는 기종에서 조작을 활성화하지 않고 사용자 변경을 옛 값으로 덮지 않는다.

### 색상 선택 통합 — 2026-10-30
