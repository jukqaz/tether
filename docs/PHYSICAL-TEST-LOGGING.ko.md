# 개발용 물리 시험 기록

사용자는 안내한 덮개·전원 조작만 한다. 시험 시작과 종료, 시각 확인, 실패 판정, 로그 분석은 개발자가 맡는다. 정상 여부를 말하거나 문제 시점 표시 버튼을 누를 필요가 없다.

## 시작 전 준비

실제로 실행 중인 앱·도우미·관측 CLI의 빌드가 같고, 앱에 도우미가 연결돼 있으며 덮개 유지 옵션이 켜져 있어야 클램쉘 시험을 진행한다. 관리자 인증 대기나 버전 불일치는 먼저 해결한다. 준비가 안 된 상태에서도 진단 기록은 가능하지만 클램쉘 통과 근거로 쓰지 않는다. 미리보기와 모의 도우미는 물리 시험 대상이 아니다.

개발자는 저장소에서 관측 CLI를 빌드하고 수집을 시작한다. 일반 사용자로 실행한다.

```sh
swift build --product TetherCLI
python3 scripts/record-physical-test.py --minutes 30
```

현재 설치된 `/Applications/Tether.app`의 companion CLI가 앱의 응답을 읽고, 새로 빌드한 관측 CLI가 native 상태와 도우미의 실시간 응답을 읽는다. 다른 설치 경로는 `--app`, 관측 바이너리는 `--probe-cli`로 지정한다. 임의로 설치 앱을 교체하거나 설정을 바꾸지는 않는다. `TETHER_*` 모의 환경 변수, root 실행과 Preview 앱은 거부한다.

기본 30분, 선택 범위 1~240분이다. 수집은 설정·절전 방지 요청·잠금 정책·상세 기록 선택을 바꾸지 않는다. 잠자기·깨우기를 요청하거나 다른 앱을 종료하지도 않는다. Mac이 잠들면 다음 깨움 뒤 종료 기한을 확인한다.

## 남는 근거

| 파일 | 내용 |
|---|---|
| `session.json` | 앱·관측 CLI·도우미 빌드, 설치 구성 요소, 부팅 ID, 시작·종료 시각, 수집 한도·종료 사유 |
| `samples.jsonl` | 약 3초마다 전원·덮개·Full Wake·SleepDisabled·화면 절전·잔량·배터리 온도·OS 발열 상태, 앱 판단, 도우미 연결·승인·소유권·보호·세션·순번·기한·종료 receipt, 저장된 선택, watchdog 점검 |
| `queries.jsonl` | Sleep/Wake·도우미 로그·앱 로그 조회의 시각·성공·실패·제한·출처. 읽기 권한 부족도 남김 |
| `events.jsonl` | 실제 macOS Sleep/Wake와 읽을 수 있는 도우미·앱의 주요 전이. 사건이 없으면 생성하지 않음 |
| `analysis.json`, `analysis.ko.md` | 조건별 통과·실패·미확인, 근거 구간·지연·공백, 준비 상태·수집 한계 |

다른 프로세스의 절전 요청은 15초마다 PID·요청 유형으로 저장한다. 앱 이름은 `--include-app-names`를 지정했을 때만 포함하며 요청 설명·명령 인수·앱 경로·유지 출처·자유 형식 오류는 제외한다. 이 목록만으로 충돌 원인을 단정하지 않는다. 저장된 설정은 적용된 설정의 증거와 구분한다.

로그는 저장소 `.build/verification/physical-tests/<세션>/`에만 저장한다. 바탕화면·원격 서버에 저장하거나 자동 업로드하지 않는다. 세션 디렉터리는 `0700`, 파일은 `0600`이고 수집은 총 32MiB로 제한한다. 분석을 포함한 한도는 33MiB다. 기존 세션은 덮어쓰지 않고, 심볼릭 링크·다중 링크·과대 파일을 거부한다. 여러 시험의 보관 파일은 개발자가 필요한 것만 남긴다.

분석 JSON은 512KiB, 한국어 보고서는 256KiB로 제한한다. 긴 시험의 반복 상세는 마지막 구간만 요약하고 생략한 개수와 원본 보존 여부를 표시한다. 전체 원본은 JSONL에 남는다. 단일 상세도 한도를 넘으면 분석은 미확인으로 남긴다.

## 시험과 판정

1. **AC에서 닫힌 덮개 유지:** 전원을 연결한 채 덮개를 닫고, 개발자가 120초 연속 관측을 확인한 뒤 다음 조작을 안내한다. 외장 화면·원격 앱 상태는 개발자가 기록된 관측과 함께 판단한다. 같은 빌드의 앱·실시간 도우미·유한 덮개 권한·자체 소유권·독립 OS 관측·보호·최근 watchdog 점검을 대조한다. 완료 구간을 포함하는 성공한 OS 로그 조회에 실제 Sleep이 없어야 그 구간의 유지 통과다. 현재 자동 분석기의 80초는 짧은 진단 구간 기준이며, [인수 체크리스트](MANUAL-ACCEPTANCE.ko.md)는 `durationSeconds`를 별도로 읽어 120초 이상을 요구한다. 수집 시작 전 닫혀 있던 시간은 더하지 않는다.
2. **닫힌 상태에서 전원 분리:** 전원을 연결한 채 덮개를 닫고 20초 뒤 전원을 뺀다. 60초 기다렸다 연다. AC→배터리→자체 유지 해제→실제 Sleep→열림·Wake의 순서와 관측 지연을 확인한다. 빠르게 잠들어 배터리 표본이 빠졌다면 같은 부팅·세션·승인 기한 안의 도우미 종료 receipt와 실제 OS Sleep/Wake를 대조한다. 이 경우 배터리 표본을 직접 관측했다고 표시하지 않는다. 다른 앱의 요청 때문에 Sleep이 확인되지 않으면 해당 요청 후보와 미확인을 남긴다.
3. **임시 유지·보호:** 개발자가 현재 선택과 실제 활성화·기한을 먼저 읽고 다음 조작을 안내한다. 타이머 선택만으로 시작됐다고 판단하지 않는다. 원래 기한·전원 연결 중 만료·분리 뒤 부활 여부·잔량/발열에 의한 해제를 기록으로 대조한다. 위험한 온도나 방전을 일부러 만들지 않는다. 현재 자동 분석은 타이머·보호의 관측을 정리하며 최종 판정은 기록을 읽어 별도로 확정한다.

SleepDisabled·명령 성공·`willSleep`·표본 공백은 실제 Sleep의 증거가 아니다. 실패한 조회나 파일 fallback은 실시간 ACK가 아니다. 수집 손상·시계 역전·큰 공백·다른 부팅·오래된 근거는 통과를 막는다. 한 조건을 통과해도 다른 조건과 장시간 내구성은 별도다. 전체 `verdict=pass`는 AC 유지 또는 분리 중 관측된 한 조건의 통과일 수 있다. `completeAcceptance=false`와 항목별 `checks`를 함께 읽고, 타이머·잠금·원격의 최종 인수 결과를 따로 남긴다.

OS 화면 절전은 패널 전력 0을 증명하지 않는다. 현재 잠금 상태·원격 화면 출력·원격 입력 성공도 이 수집기로 확정하지 않는다. 잠금 정책이나 GUI 로그인 소유권을 실제 잠금 상태로 대신 해석하지 않는다.

## 종료와 다시 분석

개발자가 Ctrl-C 또는 해당 세션의 `STOP` 파일로 정상 마무리한다. 종료 기한·용량 제한에도 수집을 끝내고 분석을 저장한다. 사용자는 “시험 끝”이라고만 알려도 된다. 수집을 임의로 재시작하거나 사용자의 타이머를 늘리지 않는다.

```sh
python3 scripts/record-physical-test.py --analyze .build/verification/physical-tests/<세션>
```

재분석은 보관 파일만 읽는다. Mac 상태나 앱 설정을 다시 조회하지 않는다. `analysis.json`에는 분석기와 입력 파일의 SHA256을 남겨 어느 기록·코드로 판단했는지 구분한다. 이전 결과와 소스 버전이 필요하면 분석을 수정하기 전에 개발자가 해당 세션 안에서 비교 근거를 보존한다.

## 자동 회귀 검사

```sh
python3 scripts/test-physical-recorder.py
python3 scripts/test-physical-analysis.py
python3 scripts/test-physical-probe.py
python3 scripts/test-physical-roundtrip.py
```

수집기의 파일·개인정보·용량·timeout 경계, 모의 Sleep/Wake의 오판 방지, 실제 격리 도우미와 CLI의 읽기 전용 계약을 확인한다. 통합 실행기 `scripts/test-automated.py`에도 연결한다. 이 검사와 실수집 확인은 물리적인 덮개·Sleep/Wake 시험의 완료를 뜻하지 않는다.
