# Tether 기능 효용 평가

2026-10-08 · v3 / 실제 설치본 **2026.10.1 Beta 1 · 앱·도우미53**이다. 관리자 설치·현재 연결과 최종 설정/메뉴 배치 적용을 확인했다. 공개 배포·실물 인수는 남아 있다. 아래51/52 당시 검사 수는 역사 기록이며 최신 결과와 합산하지 않는다. 최신 근거는 [검증 체크리스트](VALIDATION-CHECKLIST.ko.md)에 연결한다.

## 사용자 승인으로 정리한 보조 기능 · 2026-10-08

수동 시간 선택을 메뉴바로 통합하고 설정의 중복 행·데스크톱 빈 수동 섹션을 제거했다. 종료 예고·시간 만료 알림과 별도 사용법 창도 제거했다. 첫 설치 준비·열/관측 실패/잔량 보호 알림·종료 로그는 유지한다. 옛 종료 알림 선호는 저장소에서 보존하되 실행하지 않는다. 이 후속 후보는 위에서 기록한 설치본과 구별하며 아직 교체하지 않았다. [검증 단위](../.build/verification/essential-cleanup-20261008/SCOPE.ko.md).

## 필수 기능 범위 · 2026-10-07 최종 간소화

사용자 요구에 직접 대응하는 기능만 남긴다. 자동 전원 트리거 ON/OFF와 조건, 독립적인 수동 유지(AC 무제한·배터리 최대120분), 덮개 유지·닫힌 전원 분리 종료, 열·잔량 보호가 실행 기능이다. 충돌 원인 표시·보호 알림·제한된 로그·업데이트 이관·실패 원복은 이 실행을 확인하고 유지하기 위한 필수 보조 기능이다.

CPU 사용량 분석과 전역 단축키를 UI뿐 아니라 수집·타이머·등록 코드까지 제거했다. CPU 비율로 열이나 배터리 소모의 원인을 판정하지 않는다. 작업 유지 화면의 중복 암호 설정 카드는 제거하고 진단의 정책 조회·설정 링크만 유지한다. 기존 전원·시간·보호·언어·알림 선택은 초기화하지 않는다. 삭제된 단축키 선호는 더 이상 실행하지 않는다.

[간소화 검증 단위](../.build/verification/minimal-scope-20261007T064444Z/scope.json)에 기준과 설치 상태를 분리해 기록한다. [후속 결과](../.build/verification/minimal-scope-20261007T064444Z/RESULT.ko.md)는 소스966개·별도IOKit7개, 새 패키지67개 그룹·51→52 이관10개 통과와 native 프리뷰를 확인했다. 실제 설치·물리 인수는 남았다. 아래 빌드52 초기 검사와 이전51 근거는 이 간소화의 재검사 결과와 합산하지 않는다.

현재 판정은 **핵심 기능과 자동 회귀 검증을 갖춘 개발 후보, 실사용 인수는 미완료**다. 테스트 수나 기능 수로 상용 앱보다 우수하거나 몇 % 완성됐다고 판단하지 않는다. 같은 Mac·OS·원격 환경에서 비교 앱을 함께 시험하지 않았고, 소비 전력·CPU·종료 지연·장시간 안정성의 비교 측정도 없다.

### 차별화와 미완료의 경계

- Tether는 전원 분리 종료와 제한된 배터리 예외, 열 보호의 우선순위를 좁게 고정한다. 원격·최근 입력으로 기한을 늘리지 않고 보호 해제 뒤 자동 재개도 하지 않는다. 이는 요구 적합성의 장점이며 비교 앱보다 안전하다는 실측 결론이 아니다.
- Keepresso 정식 소스에는 [트리거 해제의 자연 종료](https://github.com/gyorgysh/keepresso/blob/e114f3230e3501005ec285839f874911d24fe024/Sources/KeepressoCore/SessionController.swift#L1235-L1259), [세션 종료 Sleep 선택](https://github.com/gyorgysh/keepresso/blob/e114f3230e3501005ec285839f874911d24fe024/Sources/KeepressoCore/SessionEndAction.swift#L4-L19)이 있다. AC 트리거 + Only while brewing + Sleep 종료의 조합은 공개 계약상 유사한 요구를 구성할 수 있다. 현재 Mac에서의 성공 보장은 아니다.
- Tether의 일반 유지와 덮개 실행을 분리하고 자체 변경만 원복하는 원리는 유용하다. 다만 Keepresso도 baseline·복구를 갖추고 있고 양쪽 덮개 구현에 전역 SleepDisabled의 한계가 있다. Tether만의 공식 Apple 덮개 API로 해결한 기능이 아니다.
- 남은 최우선 항목은 실제 AC 닫힘 유지·닫힌 분리 Sleep/Wake, 유효한 배터리 예외와 만료, 화면 절전·OS 잠금·인증된 원격 입력의 동시 관측이다. Tether는 OS 자동 잠금을 세션 동안만 우회하거나 이미 잠긴 화면을 자동 해제하지 않는다.
- 앱·도우미53 적용을 완료했으며 기능 확대보다 위 실물 인수를 먼저 끝내야 한다. 같은 조건의 종료 성공률·지연·원복 잔재를 비교한 뒤에만 실사용 우위를 판단한다.

## 2026-10-08 · 코드와 디자인에서 채택한 원칙

공개 main 소스를 고정해 읽었다. [Keepresso의 자체 IOKit 요청](https://github.com/gyorgysh/keepresso/blob/e9d96264d9500e5c3b0bc904d303d13fb3be2d0d/Sources/KeepressoCore/PowerAssertion.swift)도 system/display 요청을 구분하고 자기 ID만 해제한다. Tether는 사용자 요구대로 일반 작업 유지와 덮개 실행을 분리하고, 일반 요청의 유한 기한·관측·갱신을 유지한다. Keepresso의 [열 보호](https://github.com/gyorgysh/keepresso/blob/e9d96264d9500e5c3b0bc904d303d13fb3be2d0d/Sources/KeepressoCore/ThermalGuard.swift)에서 관측 누락을 정상 회복으로 취급하지 않는 원칙을 교차 확인했다. 팬 제어·별도 섭씨 기준·자동 회복은 이번 제품에 추가하지 않는다.

[KeepingYouAwake의 native status item](https://github.com/newmarcel/KeepingYouAwake/blob/2be93dd7f390b23fbca934ff3b1ac03468a80077/Packages/KYAStatusItemUI/Sources/KYAStatusItemUI/KYAStatusItemController.m)은 활성/비활성 아이콘과 다음 조작의 도움말을 바꾼다. Tether도 일정한 캔버스와 상태별 실루엣·동작 설명을 사용한다. 원격 배지를 중복 표시하거나 외부 상태에 따라 폭을 늘리지 않는다. 기존 사용자 선택인 앱 아이콘6·메뉴바1을 유지했다.

[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)의 역할 구분에 맞춰 Liquid Glass는 탐색·동작에 쓰고 설명/진단의 읽기 영역은 표준 재질로 유지한다. [Settings](https://developer.apple.com/design/human-interface-guidelines/settings)와 [Menus](https://developer.apple.com/design/human-interface-guidelines/menus)를 따라 관련 옵션·짧은 명칭·예상 가능한 표준 조작을 묶었다. native 그룹형 폼과 Section footer로 반복 설명을 줄이고 자동 OFF/수동 지속, 선택/시작, 분리 후 동작을 가까이 설명한다. “항상”은 무기한과 혼동될 수 있어 전원 조건을 “둘 다”로 바꿨다. 모델·옵션·마감 의미는 바꾸지 않았다.

[Sparkle의 실제 updater](https://sparkle-project.org/documentation/api-reference/Classes/SPUUpdater.html)를 private bundle에서 시작해 초기 KVO·구성 실패까지 확인했다. CLI 교체 검사만으로 앱 delegate wiring을 통과 처리하지 않는다. 해당 Goal 검토 당시 설치본은52였고 새 helper 로직을 실행하지 않았다. 현재 설치본53의 적용은 위 최신 근거에 연결한다. 실제 클램쉘 종료와 원격 입력의 비교 우위는 여전히 측정하지 않았다.

## 판단 기준

객관적 근거는 사용자 요구와의 대응, 실제 실행 경로, 자동 검증, 부작용 범위와 확인된 한계다. 테스트 개수·GitHub star·설치 여부를 사용자 만족도나 우수성 점수로 바꾸지 않는다. 아래 **주관적 효용**은 이 사용자가 반복해서 요청한 작업을 기준으로 한 개발자의 판단이며 사용자 조사 결과가 아니다.

| 평가 축 | 객관적으로 확인하는 것 | 주관적으로 판단하는 것 |
|---|---|---|
| 문제 해결 | 요구한 상태 전이·종료·원복이 구현/시험됐는지 | 일상에서 이 기능이 없으면 얼마나 불편한지 |
| 조작 부담 | 시작·종료·조건·예외 선택에 필요한 조작과 상태 구분 | 사용자가 쉽게 이해하고 예측할 수 있는지 |
| 영향 범위 | 전역 설정·타 앱 요청·권한·타이머에 미치는 효과 | 효과에 비해 옵션·설명·관리 부담이 과한지 |
| 증거 수준 | 소스·실제 프로세스·패키지·실물·원격 결과를 구분 | 이 사용자에게 필수/선택/불필요한지 |

보조 기능·필수 준비와 늦은 ACK·종료 순서·OS 배터리 경고 보완 뒤 전체 소스 **967/967**, 이번 패키지 helper 격리 실행 **49/49**, 일괄 자동 검증 **42단계**를 확인했다. 이전 소스 919개·회귀 86개·통합 27그룹은 당시 근거로 보존하며 겹치는 수치를 합산하지 않는다. helper 실행은 실제 격리 프로세스와 모의 OS 관측이다. 테스트 수를 성공률·신뢰도 점수로 쓰지 않는다. 사용자 사용 빈도·조작 시간·만족도·비교 앱의 같은 조건 성공률은 아직 실측하지 않았다.

평가의 중심 작업은 다음이다: 전원 연결 중 작업 유지 → 덮개 닫힘에서도 유지 → 닫힌 채 전원 분리 → 사전에 허용한 배터리 예외가 없으면 자체 유지 해제와 실제 Sleep. 원격 화면·입력은 그 작업과 함께 확인하되 유지 시간을 임의로 늘리는 조건으로 쓰지 않는다.

## 정보 배치에 대한 판단

기본 화면에는 현재 유지 이유·자동 ON/OFF·수동 시작/끝내기·남은 시간만 우선 둔다. 전원 분리 후 배터리 예외는 시작 전에 선택하고, 실행 중에는 적용 중인 예외만 설명한다. 이는 서로 다른 종료 범위를 이해해야 하는 부담을 줄이기 위한 주관적 UX 판단이다.

충돌 상세는 문제 해결 효과가 크지만 매번 읽을 정보는 아니다. 설치돼 있다는 이유만으로 충돌이라고 표시하면 불필요하게 앱을 삭제하게 만들 수 있으므로 설치/실행/실제 요청을 구분한다. 요청 종류·PID·조회 시각·영향·조정 방법과 macOS/앱 기능 겹침은 실제 UI에서 기본 접힘으로 연결했다. 앱 열기·Finder는 제공하며 자동 삭제·강제 종료는 제공하지 않는다. 현재 51 native 화면에서 요청 종류의 상세 줄·갱신·타이머·정상 종료를 확인했다. 센서·OS 쓰기는 모의이며 production 메뉴바와 인증된 원격은 별도다.

현재 사용자에게 배터리 자동/둘 다·macOS 위임은 보조 옵션이다. AC 추천을 바꾸면 닫힌 분리 뒤 계속 유지될 수 있는 이유를 가까이 설명해야 한다. 과열 보호·원복·업데이트는 평소 보이지 않아도 실패 비용이 커서 제거 대상이 아니다. 완벽함이나 경쟁 우위는 이러한 판단만으로 확정하지 않는다.

이 판단을 반영해 사용하지 않는 연장·종료 예약 화면, 중복 진단 버튼, 정상 설정의 메뉴 미리보기를 제거했다. 진단 창은 현재 상태·실제 요청·설치된 전원 앱을 우선 보여주고 화면·원격 정보는 펼쳐서 확인한다. 구버전 이관·원복 기록과 잘못된 옛 명령을 거부하는 호환 경계는 유지한다. 이전51의 [간소화 검증](../.build/verification/v3-20261006T102138Z/scope-cleanup/regression.log)은 당시 제공했던 CPU 읽기와 별도 관측 시각, 접힘/재펼침·창 종료에서의 취소, 요청 종류·PID 안전 동작, 한국어/영어 UI 렌더를 포함한다. 현재 후보 51의 네이티브 설정·메뉴 패널·타이머·보호·데스크톱 분기·정상 종료를 모의 센서/private helper 범위에서 확인했다. production 메뉴바·실물·인증된 원격은 별도다.

## 기존 앱을 쓸지 결정하는 기준

일반 절전 방지만 필요하면 기존 앱을 사용하는 편이 개발·관리 부담이 작다. Tether를 계속 개발할 이유는 이 사용자의 닫힌 분리 종료, 제한된 배터리 예외, 열 보호, 실패 원복을 한 계약으로 검증하고 필요한 조작만 제공하는 데 있다.

기능 수로 우위를 주장하지 않는다. 같은 Mac·OS·외장 화면·원격 조건에서 핵심 종료 시험이 통과하고, 타 앱보다 반복 조작과 예상 밖의 유지가 줄어드는지를 확인해야 한다. 비교 자료는 [2026-10-06 조사와 고정 소스 근거](COMPETITOR-DEEP-RESEARCH.ko.md) 기준이며 비교 앱의 실물 성공률 자료는 없다.
