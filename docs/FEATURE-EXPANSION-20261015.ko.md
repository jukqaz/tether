# Tether 확장 기능 채택안

**최신 방향 · 2026-10-16:** 아래는 구현 전의 22개 후보·출처·당시 계약을 보존한 기록이다. 이후 v4가 구현돼 현재 후보58의 상태는 [기능 명세](PRODUCT-SPEC.ko.md)와 [구현·검증 결과](IMPLEMENTATION-V4-20261015.ko.md)를 따른다. 이번에 사용자는 기존 유지 규칙을 차기 조사의 제약에서 잠시 제외했다. 새 기능 범위와 정책 선택지는 [기능 수집·통합안](FEATURE-SYNTHESIS-20261016.ko.md)을 따른다. 아래 ‘없음/미구현/구현 중단’은 당시 관측이며 현재 구현 현황이 아니다.

**당시 후속 기준 · 2026-10-15:** 사용자가 기능 명세부터 다시 정리하도록 요청해 v4 초안과 검토용 HTML 시안을 우선했다. F-14~17(규칙 예행연습·작업 후 업데이트·설정 이력·단발 만료 예고)은 v4 §12.7~11로 이어졌다. 아래 E01~22는 고정 출처 목록이고 과거의 종료 예고 제외 문구는 최신 제외 결정이 아니다.

2026-10-15 · 사용자 요청: “좀 더 복잡하게 만들어도 될 것 같다. 다른 곳에서 가져올 만한 기능 다 가져오자.”

**이 문서는 확장할 제품 범위와 검증 계약이다. 신규 기능을 구현·설치·시험 완료했다는 기록이 아니다.** 현재 작업 소스에는 배터리 자동·전원 분리 후 승계가 남아 있고, 아래 기본 계약으로 먼저 정리해야 한다. 앱 적용 전 시안 확인 방침을 유지한다. 구현 상태의 ‘있음/부분/없음’은 소스 관찰이며 설치본 또는 실기기 판정이 아니다.

## 1. 확장해도 유지할 기본 계약

- 자동은 AC에서만 작동한다. 배터리는 새 명시적 수동 요청으로만 시작하며 최대 120분이다.
- **관측된 모든 AC→배터리 전환은 기존 자동·수동·작업 연동 요청을 끝낸다.** 배터리 수동→AC→재분리도 종료하며 승계 예약은 제공하지 않는다.
- 닫힌 분리는 자체 변경 원복 확인 뒤 선택한 종료 동작을 한 번 수행한다. 기본은 잠자기 요청이며 열린 분리는 강제로 잠재우지 않는다. 명령 성공과 실제 Sleep은 구분한다.
- 배터리 수동 중 AC를 연결해도 마감은 늘어나지 않는다. IPC 재접속·원격 연결·조건 재평가·프리셋 선택도 현재 수동 마감을 바꾸지 않는다. **사용자가 실행 중 연장을 명시적으로 요청한 경우만** 같은 요청의 마감을 변경하며, 배터리에서 시작한 요청은 AC를 거쳐도 최초 시작부터 총120분 상한을 유지한다.
- 수동만 종료하면 켜 둔 AC 자동은 계속된다. 전체 일시 중지·보호 중지는 수동을 종료하고, 재개해도 종료한 수동은 부활하지 않는다.
- 전원 상태가 unknown인 관측을 AC 또는 배터리 전환으로 만들어 내지 않는다. 뒤늦은 관측·ACK가 이미 소비한 요청을 되살리지 못하게 한다.
- 타사 assertion·프로세스·미소유 전역값은 변경하지 않는다. 원격 앱 실행 관측을 접속 성공·무잠금·원격 입력 준비로 표시하지 않는다.
- 새 확장 기능은 기본 꺼짐이다. 기존 사용자가 켜 둔 기능·중지·보호·화면 선택은 별도로 보존하며, 업데이트로 새 트리거를 자동 생성하지 않는다.

macOS 26 이상 Apple Silicon Mac을 대상으로 한다. 데스크톱의 일반 유지와 MacBook의 도우미 기반 덮개 실행을 구별한다. 팬·충전·잠금 정책을 조정하지 않아도 아래 기능을 제공할 수 있어야 한다.

## 3. 확장 입력과 실행 책임

### 자동 조건

자동 모드는 두 가지다.

1. **AC 연결 동안:** 기존 기본 흐름. 추가 필터 없이 AC에서 자동 유지한다.
2. **AC + 고급 조건:** `AC && 자동 ON && 안전/소유자 유효 && !전체 중지 && 조건 묶음 성립`일 때만 유지한다.

고급 조건 모드에서 빈 규칙은 활성화하지 않는다. 삭제·손상·권한 실패로 빈 규칙이 됐다고 ‘AC 연결 동안’으로 바뀌면 안 된다. 활성 조건이 하나도 없는 경우와 조건 관측이 미확인인 경우를 별도로 보여준다. AND/OR의 필수 관측 미확인은 실행 권한을 생성하지 않는다. 자동 필터가 끝나도 독립된 수동 요청은 원래 마감까지 유지할 수 있다.

### 작업 수명과 사건 소비

- UI·단축키·CLI·Intent와 작업 이벤트는 현재 `UserSessionController`/`IdleSessionPolicy`의 공통 결정 경로에 전달한다. 확장 모듈마다 `caffeinate`, `pmset`, 별도 root writer를 만들지 않는다.
- 요청 출처·명시적 사용자 의사·요청 ID·고정 마감·관측 수명을 구분한다. 여러 입력이 같은 OS 자원을 요구해도 실행 자원은 하나의 공통 결정에서 관리한다.
- AC 분리 당시의 요청·작업 이벤트 권한은 소비한다. 프로세스가 계속 실행 중이거나 heartbeat가 도착해도 배터리 권한이 되살아나지 않는다.
- 새로운 배터리 수동 시작은 분리 이후의 새 명시적 요청이어야 한다. 종료 ACK·이전 키 이벤트·IPC 재접속은 새 시작이 아니다. 새 유효 요청은 아직 실행하지 않은 과거 종료 Sleep을 취소할 수 있다.
- PID 연동은 PID와 시작 identity를 함께 사용한다. PID 재사용·조회 실패·루트 프로세스와 자식 생존의 의미를 구분한다. 프로세스 트리 전체 완료는 별도 관측 없이 약속하지 않는다.
- 작업 heartbeat의 TTL과 실제 수동 마감은 다르다. heartbeat 갱신은 고정 마감·배터리 120분·분리 소비 상태를 연장하지 않는다. Keepresso의 하루 TTL/장기 lease를 그대로 가져오지 않는다.
- helper는 유한 허가·실제 전원/덮개·보호·소유자를 다시 확인하고 자체 원복·한 번의 종료만 수행한다. 규칙·일정·AI 작업을 root에서 다시 판정하지 않는다.
- 스케줄은 달력·시간대 규칙으로 성립 여부를 계산하고, 수동의 경과 시간은 연속 시간으로 계산한다. DST·시계 변경·수면 후 복귀로 수동 마감을 늘리거나 놓친 스케줄을 소급 실행하지 않는다.

### 관측·개인정보·권한

규칙은 사용자가 선택한 대상만 관측한다. 네트워크 이름·PID·일정 상세·파일 경로를 기본 로그에 불필요하게 남기지 않고, 진단 내보내기는 기존 제한·가림 정책을 따른다. 일정·기기·파일 등 필요한 권한은 해당 기능을 켤 때만 요청한다. 미지원/거부/조회 실패를 정상 또는 조건 불일치와 혼동하지 않는다. 앱 프로세스, 미디어/회의 상태, 원격 접속·프레임/입력은 별개 관측이다.

### 실행 중 연장과 종료 알림

2026-10-15 사용자는 기존 삭제 유지 선택 뒤 **실행 중 연장·종료 알림은 복원**하도록 정정했다. 이 두 항목에 최신 정정을 적용하고 직접 시간 입력은 복원하지 않는다.

- 연장은 활성·시간제·동일 요청 ID를 가진 수동 요청의 명시적 조작이다. +15분/+30분은 현재 마감에 더하며, 배터리에서 시작한 요청은 `min(현재 마감 + 연장, 최초 시작 + 120분)`으로 제한한다. 실제로 추가할 수 있는 시간을 표시하고 남은 허용량이 없으면 비활성화한다.
- AC에서 시작한 시간제 수동은 기존 허용 기간 상한 안에서 연장할 수 있다. 무제한 수동에는 연장 조작을 표시하지 않는다. 배터리 수동이 AC로 이동해도 최초120분 상한을 초기화하지 않는다.
- 만료·분리·전체 중지·보호·OS Sleep으로 끝난 요청과 종료 중인 요청은 연장할 수 없다. 연장 메시지에 요청 ID/현재 revision을 묶고, 종료 사건과 경합하면 이미 관측된 종료가 우선한다. 연장은 새 수동 시작이나 보호 재개 명령이 아니다.
- 배터리의 최초 시작/120분 상한은 연장 revision과 별개로 불변이다. 현재 receipt의 ‘더 이른 마감만 수락’ 규칙을 보통 heartbeat에서 완화하지 않는다. 명시적 연장은 인증된 별도 의사로 검증한 revision에 속한 사용자 마감만 갱신하고, receipt·ACK도 연장 승인 revision에 귀속시킨다. 이전 ACK가 새 승인을 취소하거나 과거 요청을 되살리지 못하게 한다. 일반·화면·덮개의 적용 마감과 연장 확인 상태를 구분하며 응답 대기·거절을 연장 완료로 표시하지 않는다. 현재 덮개 실행에 참여한 도우미가 연장 계약을 지원하지 않으면 기존 마감을 유지하고 연장 성공으로 알리지 않는다.
- PID/작업 완료는 연장된 시간보다 먼저 요청을 끝낼 수 있다. 자동 트리거·외부 heartbeat·프리셋·시계 보정은 연장 의사가 아니다. helper의 새로운 허가는 명시적 연장에 따른 새 마감과 순서를 검증하며 오래된 종료 준비를 재사용하지 않는다.
- 종료 알림은 기본 꺼짐이며 사용자가 켤 때만 OS 알림 허용을 요청한다. 기존 보호 알림과 별도로 저장하며 종료 알림을 꺼도 보호·기록·실제 종료는 그대로 작동한다.
- 수동 만료 시 AC 자동 또는 다른 작업 요청이 남아 있으면 “수동 시간 종료 · 자동/다른 작업 유지 중”으로 표시한다. 모든 자체 요청을 해제했더라도 타사 요청이나 실제 Sleep을 확인하지 못했으면 “Mac이 잠들었습니다”라고 알리지 않는다.
- 사용자가 직접 끝낸 세션은 기본적으로 별도 종료 알림을 내지 않는다. 같은 사건의 보호/시간 알림은 중복하지 않고, 잠든 동안 전달이 늦어지거나 오래된 알림이 몰리지 않도록 사건 ID·유효 기간을 적용한다. 알림 표시를 기다리며 원복·종료를 지연하지 않는다.
- 연장이 승인되면 이전 revision/마감의 타이머와 알림 예약을 취소·재검증한다. 늦게 도착한 이전 만료 콜백으로 새 마감을 종료하거나 조기 종료 알림을 내지 않는다.
- 종료 예고/반복 ‘계속 유지 중’ 알림은 이번 정정에 포함하지 않는다. 필요하면 나중에 별도 선택한다.

## 5. UI 원칙

기본 메뉴는 현재 상태·수동 시간/시작·종료·전체 일시 중지·분리 결과를 앞에 둔다. 고급 자동화는 접힌 진입점과 별도 편집 화면에서 다루고, 기존 설정 3개 탭을 기능 수만큼 늘리지 않는다. 조건 설명은 기본 상태와 상세 원시 근거를 분리한다.

선택한 **그래파이트 + 블루** 방향과 컴팩트한 글자·간격을 유지한다. 메뉴바 아이콘 폭은 원격 앱·규칙 수 때문에 변하지 않는다. 확장 시안에는 규칙 없음·참·거짓·미확인·권한 거부·중지·보호·프로세스 종료·전원 분리·긴 한영 문자열·펼침/스크롤 끝 상태를 포함하고 앱 적용 전에 검토한다.

## 6. 구현·검증 순서

1. **단계 0:** 종료 권한 30초와 원복 재시도 30초의 충돌, 센서 실패와 분리 사건 우선순위, legacy 화면 복구의 소유 확인·실제 재시도 경로를 수정한다. AC-only·분리 모두 종료를 정책·CLI·lease·설정 이관·진단·테스트에 함께 적용한다.
2. **단계 1:** E01/E02/E03/E04/E10/E11/E12/E14/E15/E16/E21/E22를 공통 입력·명령·관측 경로에 추가한다. 설정 스키마·구버전 앱/도우미 조합은 새 계약을 모르는 경우 제한 상태로 실패하며 옛 승계 writer로 fallback하지 않는다.
3. **단계 2:** 네트워크·기기·부하·다운로드·AI·미디어 등의 관측을 기능별로 추가하고 권한 누락·오탐·샘플링 비용을 검증한다. 조건 편집 UI 승인과 provider별 실제 관측 전에는 지원 완료로 표시하지 않는다.
4. **단계 3:** 위젯·제어 센터를 같은 명령 경로에 연결하고 서명·패키징·실제 시스템 노출을 따로 확인한다.

| 검증 | 자동으로 확인할 계약 | 별도 실제 확인 |
|---|---|---|
| 공통 정책 | 조건 개수와 무관한 AC gate, 빈/unknown 조건 거부, 수동/자동 독립 수명, 한 번의 사건 소비 | 없음: 순수 정책 자체는 격리 검증 가능 |
| 전원 경합 | GUI-first/helper-first 분리, 직후 스케줄/프로세스/heartbeat 도착, 배터리→AC→재분리, 늦은 ACK·재접속·재시작 | 닫힌 덮개 실제 AC 분리·Sleep/Wake |
| 시간 | 자정·요일·DST·시간대/벽시계 변경, 명시적 연장 이외의 마감 불변, 배터리 최초120분 상한, 연장/만료/분리/이전 ACK 경합 | 장시간 실제 작업·수면 후 복귀 |
| 프로세스·작업 | 정상/실패 종료·PID 재사용·관측 실패·자식 생존·상한 도달·분리 우선 종료 | 실제 빌드/다운로드·에이전트의 정확한 시작/종료 |
| 조작 접점 | 단축키/Intent/CLI/URL의 동일 명령·오류·보호 동작, 중복 시작/종료 | 전역 키 전달·Shortcuts/위젯/제어 센터 노출 |
| 종료 알림 | 허용 전 요청 없음, 기본 꺼짐·설정 보존, 사건 중복 방지, 수동 만료/다른 유지 지속/실제 Sleep 미확인의 문구 구분, 오래된 사건의 표시 제한 | 실제 OS 허용·집중 모드·잠든 상태의 전달 지연 |
| 설정·이관 | 이전 v5 배터리 자동/승계 제거, 사용자 off/보호 보존, 손상/과대 입력 거부, runtime/토큰 복사 금지 | 설치본 업데이트·실제 도우미 교체는 마지막 별도 인수 |
| 관측·UI | 거부/미지원/미확인 구별, 모의 상태·다국어·고정 폭·접힘/스크롤 | 실제 권한·연결된 기기·화면·원격 입력·잠금 |

기존 테스트가 구정책을 강제하는 경우 기대 계약부터 바꾼다. 과거 통과 수·Fixture의 명령 성공·표본 공백을 새 기능 또는 실기기 Sleep의 합격으로 재사용하지 않는다.

연장 회귀에는 `20분→35분 승인 뒤 옛20분 ACK`, `승인 직후 옛 만료 콜백/예약 알림`, `분리/만료 관측이 연장보다 먼저`, `배터리 시작→AC 이동→연장해도 최초+120분 이하`를 포함한다.
