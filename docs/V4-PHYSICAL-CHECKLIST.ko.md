# v4 후속 설치·물리 인수

이번 구현에서는 미실시다. 사용자가 설치·물리 시험을 요청한 뒤 진행한다. 아래는 계획이며 통과 기록이 아니다. 사용자는 조작만 하고, 시각·정상/실패 판단과 로그 대조는 에이전트가 맡는다. 한 조작의 완료 근거를 확인한 뒤 다음 조작을 안내한다.

## 먼저 에이전트가 할 일

- [ ] 동결한 앱·도우미·CLI·복구 실행기 해시와 실제 설치본·실행 프로세스의 일치를 확인한다.
- [ ] 기존 OFF·보호·화면 선택을 보존하고 이전 수동·설치 예약이 부활하지 않았는지 확인한다. 관리자 인증은 macOS 정상 경로로만 진행한다.
- [ ] 일반 사용자로 도우미 로그·진단 보고서를 읽는지 확인하고, 현재 전원·덮개·실제 유지 요청·원격/외장 화면 조건을 기록한다.
- [ ] 현재 허가·소유권·원복 저널·화면 관측·공통 요청과 OS Sleep/Wake를 같은 시간축으로 수집한다. 명령 성공·표본 공백·SleepDisabled 하나만으로 Sleep을 통과시키지 않는다.

## 사용자가 꼭 해야 하는 물리 조작

| 시험 | 안내할 조작 | 에이전트가 판정할 결과 |
|---|---|---|
| AC 덮개 유지 | 전원 연결을 유지하고 덮개 닫기→90초 뒤 열기 | 수집 이후 닫힘 연속80초 이상, 유효한 요청·도우미·소유권·보호·관측 유지, 조회 성공한 OS 로그에 해당 구간 Sleep 없음. 장시간 내구성 통과와 구분 |
| 핵심 분리 종료 | AC에서 닫기→20초 뒤 닫힌 채 전원 분리→60초 뒤 열기 | 전환→기존 요청 소비→자체 해제·원복→해당 사건의 Sleep 요청→OS의 실제 Sleep→열림 Wake. 옛 수동/이벤트 비부활. 타사 차단이 있으면 자체 해제와 실제 Sleep을 별도 판정 |
| 배터리 수동·AC 왕복 | 열린 배터리에서 고정 시간 수동 시작→확인 후 닫기→AC 연결→닫힌 채 재분리→열기 | 새 수동의 실제 승인·최초 상한, AC 방문 후에도 원래 마감 유지, 재분리 시 전체 소비. 승계 예약·늦은 ACK·옛 명령 재전송의 부활 없음 |
| 닫힌 배터리 자연 만료 | 배터리 수동을 실제 시작한 뒤 덮개 닫기→선택한 고정 시간이 지난 뒤 열기 | 자연 만료·자체 원복·한 번의 Sleep 요청과 실제 Sleep, 열림 뒤 타이머 비부활. 단순 시간 선택은 시작으로 세지 않음 |

열·배터리 보호는 자동 실패 주입 결과와 실제 센서 인수를 구분한다. 시험을 위해 과열·강제 방전을 만들지 않는다. 원격 접속 유무·외장 화면·알림 표시·macOS26 대상 기기와 장시간 사용은 필요한 조건별로 별도 기록한다. 화면 꺼짐 관측을 패널 전력0이나 무잠금 보장으로 표현하지 않는다.

결과는 [v4 검증 체크리스트](VALIDATION-CHECKLIST.ko.md)의 G1~G4에 연결한다. 설치와 물리 인수가 끝나기 전까지 [구현·자동 검증 결과](IMPLEMENTATION-V4-20261015.ko.md)의 미실시 표시는 유지한다.
