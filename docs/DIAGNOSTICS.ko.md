# 진단과 디버그 기록

빌드 50 후보의 공통 작업 유지 상태는 앱 조정자의 같은 빌드·현재 응답으로 확인한다. `doctor`, 앱의 문제 해결 점검과 진단 보고서는 수동 유지·자동 조건·직접 배터리 예약·원래 마감·보호·덮개 지원을 구분한다. 레거시 도우미의 `enabled`를 현재 사용자의 켜기 선택으로 대신 읽지 않는다. 데스크톱의 공통 작업 유지에는 덮개 도우미나 감시 장치를 설치하도록 요구하지 않는다.

유지가 요청됐는데 자체 유휴 절전 방지 요청이 확인되지 않으면 정상으로 판정하지 않는다. 공통 응답·OS 관측이 없거나 오래되면 미확인으로 남기며, 조회 실패를 열린 덮개·꺼진 설정·기본 배터리 한도 적용으로 바꾸지 않는다. 두 관측 출처가 다르면 잠자기 규칙 판정을 보류하고 상세 기록·온도 진단은 계속 표시한다. 조회 중 갱신된 응답은 수집 완료 시각과 대조한다. 배터리가 없는 Mac에는 배터리 한도를 해당 없음으로 표시한다.

새 보호 정책은 macOS 발열 상태와 잔량·시간 한도를 사용한다. 아래 빌드 39의 온도·저전력 모드 설명은 이전 설계 기록이며 현재 설정으로 제공하지 않는다. 일반 요청 활성화·OS 화면 꺼짐·잠금·실제 Sleep/Wake·원격 화면/입력은 각각 다른 근거가 필요하다. 진단을 저장해도 물리 동작이나 원격 준비가 검증된 것은 아니다.

보고서는 사용자가 저장 위치를 선택하거나 복사할 때만 내보낸다. CLI는 `--out`이 없으면 표준 출력만 사용한다. 별도 자동 보고서나 바탕화면 파일을 생성하지 않는다. CLI `--record`는 기존 도우미 기록이며 공통 조정자의 연속 샘플 수집으로 확대해 표현하지 않는다.

공통 작업의 최근 동작·상세 기록·시점 표시는 덮개 도우미 없이도 사용할 수 있다. 기본 판단 변화는 macOS Unified Log에 남기며, 최근 128개 사건은 현재 앱 실행 동안만 메모리에 보관하고 화면에는 최신 20개를 표시한다. 매 3초 달라지는 잔여 시간·배터리 잔량만으로 기본 로그를 반복 생성하지 않는다. 앱을 다시 시작하면 메모리 기록과 상세 기록 선택은 초기화되고, 이전 사건의 macOS 로그 보관 범위는 OS가 결정한다.

상세 기록은 15분·1시간·4시간 중 선택하며 연속 시간으로 종료한다. 시스템 시계를 바꿔도 기록 시간이 연장되지 않는다. 관측·판단·자체 요청 확인/해제를 구분하고, 자유 형식 오류·계정·접속 주소·프로세스 인수는 메모리 기록에 넣지 않는다. 기록과 시점 표시는 절전 정책·설정·배터리 예산을 바꾸지 않는다. GUI 보고서 복사/저장에는 선택 기간의 메모리 사건을 원래 관측 순서대로 포함한다. CLI 호출자가 이 버퍼를 제공하지 못하면 그 범위를 미수집으로 명시한다. 별도 공통 로그 파일은 자동 생성하지 않는다.

개발용 물리 시험에는 [연속 기록과 분석](PHYSICAL-TEST-LOGGING.ko.md)을 사용한다. 명시적으로 시작한 수집기가 앱·native 관측·실시간 도우미·OS Sleep/Wake를 제한된 시간 동안 `.build/verification/physical-tests`에 저장한다. 사용자는 덮개·전원 조작만 하고 시각 메모·문제 표시·성공 판정을 맡지 않는다. `tether diagnose --snapshot-json`은 설정을 변경하지 않는 관측 전용 경로이며 기존 CLI `--record`와 구분한다.

## 앱·시스템 절전 영향

점검 화면은 Tether의 덮개 유지 준비 상태, 다른 앱의 일반·화면·네트워크 유지 요청, macOS의 전원별 유휴 잠자기·화면 끄기 시간을 구분한다. 원격 앱 실행 여부는 Tether의 유지 조건이나 덮개 허가가 아니다. 전역 `SleepDisabled`와 유휴 잠자기 `sleep=0`은 다른 설정이며, 값만으로 작성자를 특정하지 않는다.

최근 입력과 macOS 프로세스의 유지 요청은 처음에 접혀 있다. `UserIsActive`는 화면 대기 시간을 갱신하는 사용자 활동 보고이며, `InternalPreventDisplaySleep`는 관측된 OS 화면 지연 정보다. 이를 작업 유지 이유나 전원 분리 잠자기를 막는 허가로 사용하지 않는다. 알려진 WindowServer 입력 기록은 숫자 PID만 읽고 현재 프로세스 식별 정보를 대조해 이름을 표시한다. 입력 성공·인증된 원격 연결을 증명하지는 않는다. 형식이 바뀌면 출처를 추정하지 않는다.

화면 캡처·영상 재생은 정확히 일치하는 제한된 요청 이름만 범주로 변환한다. 자유 형식 요청 이름·탭 제목·문서·대화 내용은 화면과 보고서에 포함하지 않는다. 보고서의 앱 이름은 기존 명시적 포함 선택을 따른다. 조회 실패·시간 초과·중복 설정·불완전한 출력은 ‘미확인’으로 남기며, 과거 결과의 시각을 표시한다. 별도 타이머·입력 생성·다른 앱 종료·타사 설정 변경·자동 로그 파일은 추가하지 않는다.

화면 유지 요청은 해당 앱을 열어 화면 유지·캡처·공유 설정을 확인하고, macOS 대기 설정은 시스템 설정에서 확인할 수 있다. 값은 읽기만 한다. 닫힌 전원 분리 시 Tether의 자체 유지 해제와 명시적인 잠자기 요청은 이 진단과 별개이며, 실제 Sleep/Wake는 물리 시험의 OS 로그로 판정한다.

## 원격 관측의 현재 범위

GUI 보고서의 원격 상세는 제품·host/viewer·설치 버전과 관측 출처를 구분한다. 앱 실행·가상 화면·다른 앱 절전 요청은 힌트이며 접속·프레임·입력·인증 성공이 아니다. 현재 Probe가 실제로 확인하지 못하는 metric은 미관측으로 내보내며 각 metric의 자기 시각·가용성·이유를 기록한다. 보고서에 sessionKey·접속 주소·계정·인증 정보·화면·입력 내용은 추가하지 않는다. 설치 metadata를 읽어도 원격 준비 성공으로 표시하지 않는다.

화면 revision·GUI 세대가 바뀌거나 비동기 수집 뒤 실제 화면 ID·해상도·구성이 달라졌으면 화면 보고서와 원격 context를 함께 폐기한다. 새 점검을 시작하거나 취소할 때도 이전 화면 연결 이유를 지워 오래된 ‘가상 화면 연결’ 설명에 새 점검 시각이 붙지 않게 한다. 전원 요청과 그 기존 조회 시각은 별도로 보존한다. CPU 사용량 분석은 필수 기능 정리에서 제거했다. 화면 목록 조회의 성공한 빈 결과는 headless 관측이고 조회 실패는 별도 미확인이다. 기존 공개 정보 조회와 사용자가 선택한 저장/복사 경로를 사용하며 원격 상세 때문에 별도 자동 로그 파일을 만들지 않는다. CLI 진단의 공통 작업 판정과 GUI의 공급자 metadata를 서로 같은 실측으로 표현하지 않는다. [관측·화면 협력 계약](MAC-REMOTE-COOPERATION.ko.md).

## 앱 설정 → 문제 해결 → 진단과 보고서

1. 문제가 반복된다면 **상세 기록 15분**을 선택하고 **기록 시작**을 누른다. 더 오래 재현해야 하면 1시간·4시간을 선택한다.
2. 증상이 보이는 즉시 **문제 발생 시점 표시**를 누른다. 시각과 짧은 식별자가 표시되고, 전체 식별자가 helper 로그에 남는다. 같은 요청을 재시도해도 표시는 중복되지 않는다.
3. 재현을 마치면 **기록 끝내기**를 누른다. 잊어도 선택한 종료 시각 뒤에는 상세 기록을 수집하지 않는다. helper를 재시작해도 종료 시각을 보존한다.
4. **로그 수집 기간**을 최근 1·6·24·72시간 중 고른다. 현재 상태·설정과 기존 최근 사용 요약도 보고서에 담긴다. 기간은 로그 필터이며 그 기간의 기록이 반드시 남아 있다는 뜻은 아니다.
5. **보고서 저장…**에서 위치를 고른다. 저장을 완료하면 해당 파일을 Finder에서 표시한다. **보고서 복사**도 가능하다.

이전 버전에서 사용자가 명시적으로 켜 둔 무기한 상세 기록은 마이그레이션 시 보존한다. 화면에 ‘직접 끝낼 때까지 기록 중’이라고 표시한다. 한 번 끝낸 뒤 새로 시작하면 시간 제한을 적용한다. 새 기록은 전원 관리가 꺼져 있어도 시작할 수 있으며, 기록 자체가 클램쉘을 켜지는 않는다.

### 기록 내용과 용량

- 기본 기록: 전원·덮개·화면 관측 변화, 선택한 전원 조건, override 소유 상태, 보호 중지·적용 오류, 명령 요청과 결과, 문제 시점 표시. 같은 관측 상태는 반복 기록하지 않는다.
- 빌드 46부터 화면 조회 실패의 시작·복구와 중지 순간의 값·출처를 기록한다. 화면 절전을 확인한 뒤의 일시 미확인은 기존 확인 한도 10초 안에서 다시 읽고, 실제 켜짐 또는 지속 실패는 중지한다. 이 한도는 기기 안전 인증값이 아니다.
- DarkWake 횟수는 도우미 시작·Full Wake 뒤 macOS 전원 로그와 비동기로 대조한다. 읽기는 회당 8초·최근 출력 4MiB로 제한하며 기록 지연을 고려해 한 번만 재시도한다. 수면 시작·깨움 끝 경계를 확인하지 못하면 `unverified`로 남기며 0회를 확정하지 않는다. 기존 기록은 시각·배터리 값을 보존한 채 횟수와 확인 여부만 보정한다.
- 상세 기록: 평가 시점의 센서 값과 정책 판단. 선택 시간 동안만 활성화한다.
- helper 로그: `/Library/Logs/Tether/helper.log`, 이전 파일 `.1`~`.3`. 2MB를 넘으면 다음 회전 점검에서 최신 최대 2MB를 보존한다. 약 8MB 규모이며 점검 사이에는 현재 파일이 더 커질 수 있다. 보관 기간은 이벤트 양에 따라 달라진다.
- 빌드57 설치는 로그 폴더0755·활성/기존 회전 로그0644를 준비해 일반 사용자도 진단에 포함할 수 있게 한다. 쓰기 소유권은 root에 남고 전원 제어 기록의 권한은 바꾸지 않는다. 기존 로그 바이트·활성 inode를 보존한다. 심볼릭/하드 링크·확장 ACL·위험한 소유권/쓰기 권한은 조용히 완화하지 않고 설치 전에 거부한다. 아직 생성되지 않은 회전 파일은 실제 읽기 오류와 구분한다.
- 현재 파일의 inode를 유지해 launchd의 열린 stdout/stderr가 계속 같은 로그에 기록되도록 한다. 보관 복사에 실패하면 현재 로그를 비우지 않는다. 심볼릭 링크·다른 파일을 가리키는 descriptor는 거부한다.
- 앱 이벤트: macOS 통합 로그의 `io.github.jukqaz.tether` subsystem. macOS가 정하는 보존 범위를 따른다.
- 보고서: helper 최신 1,200줄, macOS 전원 로그·앱 로그 각각 최신 300줄. 해당 기간에 남아 있는 문제 표시 최대 30개도 따로 모은다. 기록 누락·조회 실패·출력 제한을 구분해 적는다.
- 미리보기: 임시 디렉터리의 모의 helper 로그만 읽으며, 보고서에 `SIMULATED dry-run`을 표시한다. 실제 전원·다른 앱 요청을 수집한 것처럼 보이지 않게 한다.

### 공유 범위

자동 업로드는 없다. 보고서는 로컬 파일 또는 클립보드로만 내보낸다. 사용자·Mac 이름을 가리고, 앱 경로와 자유 입력인 유지 출처는 제외한다. 전원 요청 목록의 앱 이름은 기본적으로 숨기며 필요할 때 포함할 수 있다. **절전 요청의 설명 원문은 항상 제외**하고, 과거 로그의 `tether://` 인수도 내보내기에서 지운다. 앱은 새 딥링크 원문을 기록하지 않는다.

완전한 익명화는 아니다. OS·기기 모델, 시각, 프로세스 PID, 화면 연결 정보와 일부 시스템 이벤트에는 사용 환경이 드러날 수 있으므로 공유할 파일을 직접 확인한다.

## CLI

```sh
tether diagnose --hours 6
tether diagnose --record --record-minutes 15 --out ./tether-reproduction.md
tether diagnose --hours 24 --include-app-names
```

`--record-minutes`는 1~240분, `--hours`는 0보다 크고 72 이하만 허용한다. 기록을 시작한 뒤 Return을 누르면 보고서를 내보내고 이전 상세 기록 설정을 복원한다. 그 사이 앱에서 새로 선택한 기록 설정은 덮어쓰지 않는다. CLI가 강제 종료되어도 새 기록의 종료 시각은 남는다.

`--out`을 생략하면 표준 출력으로만 표시한다. 재현에 파일이 필요한 경우에만 명시한 경로에 저장하며 데스크톱을 기본 저장 위치로 사용하지 않는다.

## 다음으로 가치 있는 작업

1. **실기기 전원·덮개·화면 검증:** 케이블 연결 순서를 바꿔 가며 실제 잠자기와 화면 절전을 관측한다. 개발용 연속 수집기로 원격·다른 앱의 요청과 사건 시각을 대조한다. 패널 전력 0은 별도 측정 대상이다.
2. **실제 이전 버전 업데이트·복구:** 기존 설정을 가진 설치본에서 앱·helper가 함께 교체되고 오류 시 복구되는지 확인한다. 오프라인 마이그레이션 테스트와 구별한다.
3. **장시간 소비전력 측정:** 기본·상세 기록의 CPU·wakeups·디스크 쓰기와 장시간 실행 시 메모리 추이를 비교한다.
4. **접근성 마무리:** 키보드만으로 전체 동선, 시스템 고대비·투명도 줄이기의 실제 화면을 확인한다.

명령 성공이나 override 해제는 물리적 잠자기·디스플레이 전원 차단의 증거가 아니다. 서명·공증과 위 실기기 검증이 끝나기 전까지는 개발 빌드로 제공한다.

## 빌드 39: 현재 상태와 최근 동작

### 진단 결과를 믿을 수 있는 조건

- 도우미 연결은 인증된 소켓의 **실시간 응답**으로 확인한다. 최근에 저장된 상태 파일만으로 연결 정상이라고 표시하지 않는다. 보고서에서 파일을 대신 읽었으면 그 출처와 실시간 미확인 상태를 밝힌다.
- 마케팅 버전뿐 아니라 빌드 번호와 통신 규약도 대조한다. 같은 2.2.0이라도 앱과 도우미의 빌드가 다르면 업데이트가 끝나지 않은 상태다.
- 관측 시각이 없거나 90초 이상 오래됐거나 현재보다 미래이면 현재 정책에 대한 정상 판정을 내리지 않는다. 깨어나는 중이거나 전원·덮개·화면 관측이 서로 다를 때도 판정을 보류한다.
- 감시 장치는 파일 존재, launchd 등록, 이번 부팅의 최근 점검 완료를 구분한다. 기존 30초 예약 점검이 끝날 때 `watchdog-status.json`에 시각·부팅 ID·종료 코드를 원자적으로 기록한다. 새 상시 프로세스는 추가하지 않는다.
- `launchctl print`의 문장이나 PID 배치를 파싱하지 않는다. 해당 작업 조회의 성공만 등록 근거로 사용한다. 등록만 되어 있고 최근 완료 기록이 없으면 경고로 남긴다.
- 완료 기록 저장 실패는 기존 복구 처리를 막지 않는다. 감시 점검 완료와 실제 잠자기 성공은 별개다.

### 최근 동작

**앱 설정 → 문제 해결 → 최근 동작**에서 보관된 helper 로그의 최근 20개 주요 이벤트를 시간 역순으로 확인한다. 전원·덮개 변화, 예약·취소, 시간 종료, 배터리·발열 보호 중지, 잠자기 방지 적용·해제, 문제 발생 표시 등을 읽기 쉬운 문구로 보여 준다.

패널을 펼치거나 새로고침할 때만 백그라운드에서 읽는다. 원문 로그, 앱 요청 내용이나 임의 오류 문자열을 화면에 그대로 노출하지 않는다. 로그 회전으로 빠진 시간은 복원하지 않으며, 잠자기 요청을 절전 완료로 표시하지 않는다.

### 사용 시간 선택

- 메뉴의 **수동 유지 → 유지 시간**에서 15분·30분·1시간·2시간 중 선택한 뒤 **시작**을 누른다. 무제한은 전원 연결 중에만 제공한다.
- **설정 → 작업 유지**에서도 수동 기본 시간·자동 배터리 시간·전원 분리 후 계속 유지 시간을 같은 프리셋으로 고른다. 설정의 선택은 바로 시작하거나 진행 중인 마감을 바꾸지 않는다.
- 직접 입력과 전용 편집창은 제공하지 않는다. 이전에 저장한 임의 시간은 ‘기존 설정’으로 표시하고 새 프리셋을 고르면 그 임시 선택지가 사라진다.
- 배터리 최대 2시간·잔량·열 보호와 원래 마감은 계속 적용한다. 전원 분리 후 수동 유지를 계속하려면 시작 전에 별도로 허용해야 한다.
