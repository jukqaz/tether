# LLM 앱과 절전 방지 요청의 공존

앱 이름이나 모델 로딩 여부로 충돌을 추정하지 않는다. macOS IOKit의 활성 전원 요청을 읽고 **작업 유지**와 **화면 켜짐 유지**를 구별한다.

| 관측 | Tether의 처리 |
|---|---|
| 시스템 유휴 절전 방지 | 화면 절전과 함께 사용할 수 있다는 정보 표시 |
| 화면 유휴 절전 방지 | 현재 Tether가 화면 절전을 요구할 때만 상충 안내 |
| 네트워크 작업 유지 | 화면 켜짐과 구별. 실제 유지 여부는 시스템 판단에 따름 |
| 구형 PreventSystemSleep | 관측은 표시하되 최신 macOS의 효과를 단정하지 않음 |
| 디스크 유휴 방지 / 사용자 활동 | 시스템 절전 방지 앱으로 분류하지 않음 |

기존 GUI 갱신 주기를 이용해 최소 15초 간격으로 읽는다. CPU와 상세 디스플레이 조사는 점검 화면에서만 수행한다. 조회 실패와 요청 없음도 구분한다. 화면 상충 표시는 현재 의도와의 관계이지, 실제 절전 실패의 증거가 아니다.

Electron 보조 프로세스는 실행 파일이 현재 실행 중인 앱 번들의 `Contents/` 내부에 있을 때 앱 이름과 연결한다. 동명 앱의 여러 인스턴스, PID 재사용, 비슷한 경로, 독립 실행한 `caffeinate`는 임의로 연결하지 않는다. 앱 열기 직전에도 원래 프로세스와 소유 앱의 시작 시각을 다시 검사한다.

다른 앱의 요청을 대신 해제하거나 프로세스를 종료하지 않는다. 화면 켜짐 요청이 상충하면 해당 앱에서 화면 유지 설정을 확인하도록 안내한다. 요청 이름에 사용자 문장이 들어갈 수 있으므로 GUI에서 원문 요청 이름을 제거하며, 인자·환경변수·모델 이름·대화 내용은 수집하지 않는다.

## 보호와 작업의 우선순위

LLM 작업 중이어도 전원 조건, 시간 한도, 배터리 하한, 발열 보호를 자동으로 무효화하지 않는다. 닫힌 덮개 유지가 끝나 시스템이 잠들면 LLM 작업도 중단될 수 있다. 필요한 경우 전원 분리 전에 한시 유지를 예약한다. LLM 앱의 유휴 절전 방지만으로 덮개 닫힘과 명시적 시스템 잠자기를 막는다고 보장하지 않는다.

## 근거

- [Electron powerSaveBlocker](https://www.electronjs.org/docs/latest/api/power-save-blocker): `prevent-app-suspension`은 화면 꺼짐을 허용하며 `prevent-display-sleep`은 화면도 유지한다.
- [Apple IOKit 유휴 절전 방지](https://developer.apple.com/documentation/iokit/kiopmassertiontypepreventuseridlesystemsleep) 및 macOS 27 SDK `IOPMLib.h`: 사용자 유휴, 화면, 디스크, 네트워크 요청의 의미가 다르며 덮개 닫힘·명시적 잠자기 등의 조건은 별도다.

## 확인 범위

추가 회귀 검사 10개를 포함해 단위 검사 240개가 통과했다. 실제 앱과 같은 읽기 모듈을 별도 읽기 전용 실행기로 실행해 Amphetamine·Splashtop Streamer의 화면/시스템 요청과 sharingd의 시스템 요청을 확인했다. 해당 시점에 LLM 앱의 활성 요청은 관측되지 않았다. 특정 LLM 앱의 모든 버전·모든 추론 단계에서 요청을 생성한다는 뜻은 아니다.

미리보기의 LM Studio 및 LLM 화면 켜짐 예시는 모의 데이터다. 모의 덮개 닫힘/열림에 따라 점검 화면의 상충 라벨이 갱신되며 메뉴 패널의 안내에서 점검 화면으로 이동하는 것을 확인했다. 실제 LLM 추론 중 덮개·전원·절전을 전환하는 물리 검증은 별도로 남는다.
