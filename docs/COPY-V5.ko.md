# Tether v5 표시 문구

2026-10-21 · **P0 추천 규칙의 표시 문구 계약, 앱 미적용.** 이번 정리는 문서뿐이며 앱·HTML·이미지·설치본·설정·문구 사전을 변경하거나 실행 시험을 한 결과가 아니다. 동작 계약은 [V5 기능명세](PRODUCT-SPEC-V5.ko.md), 화면 구성은 [디자인 계약](DESIGN-V5.ko.md)을 따른다. 2026-10-16 문구·시안 기록은 보존하되 현재 후보의 화면 완료로 취급하지 않는다.

## 현재 기본과 보존할 설계

- 추천 기본은 **자동 시작의 전원 범위는 AC, 전원 분리 시 기존 Tether 유지 전체 종료, 배터리에서는 직접 시작·최대 2시간**이다. 자동 허용을 임의로 ON으로 바꾼다는 뜻이 아니다. ‘자동 시작 허용’ OFF와 사용자가 직접 해제할 때까지 지속하는 ‘모두 중지’는 다르다.
- N05/N06의 전원 범위·배터리 상한·분리 3정책, N31의 높은 열 중단 기준 선택 등 승인된 확장 설계는 보존한다. 현재 구현, 미구현 설계, 조건부 실행 불가를 구분하며 기본값으로 덮어쓰거나 구현 완료로 표시하지 않는다. 분리 안내는 현재 선택한 정책과 유효 작업에 맞춰 표시한다.
- 후속 명시 제외는 **전역 사용자 단축키, 규칙 예행연습, 설정 변경 이력·복원, 특정 PID 종료 연동, 작업 후 업데이트 예약**이다. 아래 남은 해당 문구는 과거 기록이며 재도입 요구가 아니다. 일반 키보드 조작, 앱 실행 조건, CLI/URL, 프로필·설정 이관, 일반 업데이트와 복구 등 같은 N묶음의 나머지 설계는 삭제하지 않는다.
- 최신 native의 설정 3탭 `잠자기 방지 / 자동 시작 / 앱 설정`을 기준으로 한다. 메뉴는 하나이며 Graphite + Blue 방향을 유지한다. 문서와 후속 시안의 배치 차이는 앱 기능 결함이나 완료로 바꾸어 세지 않는다.

## P0 상태별 문구와 조작

아래 상태 ID·주표시는 `DESIGN-V5.ko.md`와 함께 유지한다. 예시 앱명·시각·전원은 실제 관측이나 선택값으로 대체한다. 논리적인 작업 종료, 자체 유지 해제 확인, 원복, OS Sleep 관측은 별도 사실이다.

| ID·상태 | 주표시·보조 문구 | 필요한 조작과 의미 |
|---|---|---|
| S00 대기 | **유지 꺼짐** / `자동 시작 꺼짐` 또는 `자동 조건을 기다리고 있어요` | 시간 선택기 + `직접 시작`. 자동 OFF만으로 수동 시작을 막지 않음 |
| S01 자동 유지 | **자동 유지 중** / 실제 충족 조건, 예: `전원 연결 · Xcode 실행 조건 충족` | 수동 타이머를 추가할 수 있음. 현재 정책이 전체 종료일 때만 `전원을 빼면 Tether 유지가 모두 끝납니다` |
| S02 수동 유지 | **수동 유지 중** / 남은 시간·끝날 시각 | `30분 추가` / `타이머 끝내기`. 자동이 꺼졌거나 조건 미충족인 경우이며 종료 후 실제 남는 작업에 맞춰 안내 |
| S03 자동+수동 | **자동 + 수동 유지 중** / 자동의 실제 근거·타이머 남은 시간 | `30분 추가` / `타이머 끝내기`. `타이머를 끝내도 자동 유지는 계속됩니다`는 자동이 유효할 때만 표시 |
| S04 모두 중지 | **모두 중지됨** / `수동 유지 종료 · 자동 시작 중지` | `중지 해제`. `켜 둔 자동 규칙을 다시 확인합니다. 끝난 타이머는 복원하지 않습니다.` 자동 OFF와 구분 |
| S05 Tether 명시 Sleep 뒤 차단 | **잠자기 요청 후 자동 시작 대기** / `깨어난 것만으로 자동 유지를 다시 시작하지 않습니다` | 출처가 확인된 Tether 잠자기 명령 수락 때 차단 저장. 실제 Sleep 실패 시 실패 이유도 표시. 명시 재개 또는 새 실제 연결·조건 false→true에서만 재평가. 모두 중지 차단이 있으면 먼저 직접 해제해야 함 |
| S06 전원 관측 공백·유한 허가 유효 | **전원 상태 확인 중** / `기존 허용 시간 안에서 상태를 다시 확인하고 있어요` | 새 시작·연장·덮개 유지 획득 비활성. 확정 분리·배터리 전환으로 표시하지 않음 |
| S07 전원 확인 기한 만료 | **전원 상태를 확인하지 못해 유지를 끝냈어요** / `안전 상태를 확인한 뒤 중지를 해제하세요` | 확인 실패 보호 차단. 정상 표본만으로 소비된 요청·타이머 복원 금지, 기본 직접 재개 |
| S08 보호 종료 | **보호로 중지됨** / 실제 이유: `열 상태가 높아요`, `배터리가 보호 기준에 도달했어요`, `저전력 모드 중단 설정이 적용됐어요` | 자체 유지 해제를 즉시 시도하고 새 허가 차단. 원인 미확인을 과열로 단정하지 않음 |
| S09 안전 상태·회복 확인 | **안전 상태 확인 중** / `열 상태를 확인하지 못했어요` 또는 `정상 상태가 이어지는지 확인하고 있어요` | 재개 비활성. 회복 대기와 관측 실패를 보조 문구로 구별하고 확인되지 않은 경과 시간을 성공처럼 표시하지 않음 |
| S10 회복 확인 완료 | **다시 시작할 수 있어요** / `기본은 직접 재개입니다. 끝난 타이머는 복원하지 않습니다` | 기본 `중지 해제`. 선택 자동 회복은 유효한 자동 조건만 재평가하며 모두 중지 차단은 해제하지 않음 |
| S11 마지막 자체 유지 해제 확인 | **Tether 유지 끝남** / 실제 종료 원인 | 자체 유지 해제가 확인된 경우의 표시. 해제 미확인이면 `유지 해제 확인 중`. 다른 앱 영향·macOS 판단은 별도 |
| S12 원복 진행·실패 | **설정 되돌리는 중** / 실패·조회 공백이면 `설정 되돌리기 확인 필요` | 성공 재조회 전 완료 표시 금지. 해당 범위의 새 획득은 차단하고 복구 진입 유지 |
| S13 Sleep 요청 수락 | **잠자기 요청됨** / `실제 잠자기 여부는 아직 확인되지 않았어요` | 요청 수락까지만 확인된 상태. 요청 실패이면 실패 이유를 표시하며 ‘잠들었음’으로 바꾸지 않음 |
| S14 실제 OS Sleep 관측 | **OS 잠자기 확인** / 관측 시각·대상 | 실제 OS 전이 근거가 있을 때만 표시. Wake 뒤에는 과거 관측으로 표시하며 현재 잠들어 있다고 하지 않음 |
| S15 덮개 준비 필요 | **덮개 유지 준비 필요** / `일반 잠자기 방지는 도우미 없이 사용할 수 있어요` | MacBook에서 덮개 기능을 선택할 때 `도우미 준비…`. 인증만으로 자동/덮개 ON이나 새 유지 시작 없음 |

**표시 우선순위:** 활성 보호·확인 실패(S07~S09) → 미확인 자체 해제·원복(S11~S12의 미확인) → 모두 중지·명시 Sleep 차단(S04~S05) → 유한 관측 대기(S06) → 확인된 종료·원복·Sleep 단계(S11~S14) → 유지·대기(S00~S03)다. S10은 해당 회복 조건을 모두 만족하고 미확인 해제·원복 차단이 없을 때만 S08/S09를 대신한다. 보호가 해소돼도 모두 중지가 남아 있으면 S04가 우선한다. 함께 유효한 제한과 종료 원인은 보조줄에 남긴다.

덮개 열림/닫힘·외장 화면·원격 연결은 상황 설명이며 종료 원인이나 보호·복구 상태를 덮어쓰지 않는다. 타이머가 끝나도 자동이 유효하면 `타이머 종료 · {실제 조건} 자동 유지 중`으로 표시한다. 수동 종료·자연 만료·분리·보호·확인 실패를 모두 같은 ‘덮개 닫힘’ 문구로 바꾸지 않는다. S07/S08에서 요청을 소비했어도 자체 해제 결과가 미확인이면 `유지 해제 확인 중`을 함께 표시해 OS 적용 성공으로 오인시키지 않는다.

## P0 시간·재개·종료 안내의 경계

### 시간과 전원 · K01/K02

- 모든 기간의 연속 마감은 수면 시간을 포함한다. 전원 연결만으로 원래 타이머 마감이 늘어나거나 다시 시작하지 않는다. 기간 타이머의 남은 시간과 벽시각으로 표시한 끝날 시각은 같은 마감을 가리킨다.
- 별도 배터리 상한의 기본은 **최초 배터리 실행 시점 + 120분**이며 배터리에서만 집행한다. AC 방문으로 기준점을 초기화하지 않는다. 원래 수동 마감은 AC에서도 계속 흐른다. AC에서 명시적인 연장은 가능하지만 자동 연장이나 배터리 기준점 초기화가 아니다.
- 기본 분리 안내는 `전원을 빼면 Tether 유지가 모두 끝납니다`. N06의 다른 정책을 선택한 설계에서는 `전원을 빼면 자동 유지는 끝나고, 허용된 직접 시작 작업은 남은 시간만 계속합니다` 또는 `작업별 전원 설정과 남은 한도에 따라 계속합니다`로 바꾼다. 실제로 계속할 작업이 없으면 종료 결과를 함께 표시한다.
- 배터리 최대 시간은 잔여 배터리 수명 예측이나 하드웨어 안전 보장이 아니다. 현재 배터리에서 실제 적용되는 마감·상한 중 이른 기한을 안내한다.

### 중지·Sleep 이후 재평가 · K04

- `모두 중지`는 수동을 포함한 기존 Tether 유지를 모두 끝내고 사용자가 직접 해제할 때까지 자동 시작 차단을 유지한다. 새 연결·조건 변화·Wake로 해제되지 않는다. `자동 시작 허용` OFF는 자동만 끄며 같은 전체 차단을 뜻하지 않는다.
- **출처가 확인된 Tether의 명시 Sleep**은 명령 수락 때 차단을 저장하고 실제 Sleep 실패 후에도 유지한다. Wake·새로고침·heartbeat·앱 재실행만으로 해제되지 않는다. 그 뒤의 새 실제 연결, 조건 false→true, 명시 재개만 새 평가 사건이다. 계속 참인 조건·놓친 사건을 재생하지 않으며 보호·모두 중지·복구 차단을 우회하지 않는다.
- 일반 또는 출처 미확인 OS Sleep은 옛 수동·연결 작업 허가를 소비한다. 기존 모두 중지·Tether 명시 Sleep·보호·복구 차단과 분리·배터리 상한 종료 뒤의 자동 재시작 차단이 없고, 정상 fullWake와 신선한 전원·규칙·보호 관측, 사용자가 선택한 자동 규칙의 전원 범위, 유효한 유한 예산·실행 소유권, 해당 GUI/서비스의 새 자동 시작 허가가 모두 확인되면 **새 자동 ID**만 평가할 수 있다. 전원 범위의 기본은 AC이며 배터리 자동을 명시적으로 선택했을 때만 배터리에서도 평가한다. 같은 자동 활성 사건은 새 ID라도 최초 배터리 기준점과 상한을 재사용하며, 원래 상한이 지났으면 시작하지 않는다. 백그라운드 새 자동 시작이 OFF인 서비스를 Wake만으로 허용하지 않는다. DarkWake·관측 공백·표본 재생·GUI 재실행은 이 허가가 아니다.
- 분리·배터리 상한 종료 뒤의 자동 재시작 차단은 **종료 이후 신선한 실제 조건 false→true, 선택한 새 실제 전원 사건 또는 명시 새 시작·재개**에서만 재평가한다. Wake·새 ID·캐시로 해제하지 않는다. 분리 정책이 새 시작을 금지한 경우에는 종료를 일으킨 그 분리 사건 자체로 시작하지 않는다. ‘작업별 전원 설정에 맞춰 계속’과 배터리 자동의 분리 시작 사건을 모두 명시 선택한 경우만 K01의 별도 시작 허가를 평가한다. 일반 fullWake와 선택 자동 보호 회복은 같은 자동 활성 사건의 최초 배터리 기준점·상한을 보존한다. 실제 조건 false→true나 명시 사용자 새 시작·재개는 새 활성 사건이 될 수 있지만 K01 분리 정책·보호 등 나머지 차단과 시작 허가를 먼저 적용한다.
- macOS 메뉴나 다른 앱이 보낸 Sleep의 출처를 항상 구별할 수 있다고 하지 않는다. ‘모든 수동 Sleep 뒤 자동 시작 방지 보장’ 대신 지속 차단이 필요하면 Tether의 `모두 중지` 또는 `잠자기…`를 사용하도록 설명한다.
- 끝난 수동 타이머는 어떤 회복·재평가에서도 복원하지 않는다. 별도 수동 새 시작은 새 작업임을 표시한다.

### 관측 공백과 회복 · K03/K05

- GUI의 전원 unknown은 확정 분리가 아니다. 기존 유한 허가의 끝, 원마감, 마지막 정상 표본 시각 + 15초 중 **가장 이른 시점까지만** 기존 유지를 허용한다. 새 시작·연장·덮개 획득은 막는다. 공백 중 시간 흐름은 멈추지 않는다.
- 이 15초 제한은 전원·열·소유 허가처럼 해당 실행에 필수인 표본의 공백에 적용한다. 화면 관측이나 선택 제공자가 unknown이면 영향을 받는 규칙·자원만 제한하며 무관한 일반 유지를 모두 끝내지 않는다. 영향을 받는 항목과 실제 제한 범위를 함께 안내한다.
- 실행 소유자가 신선한 확정 분리·열 위험·기한 만료를 확인했다면 즉시 해당 정책을 우선한다. GUI unknown의 15초는 보호·종료를 늦추는 유예가 아니다. 기한 뒤에는 S07과 확인 실패 보호 차단으로 전환하고 정상 표본만으로 끝난 요청을 복원하지 않는다.
- 보호 중에는 자체 유지 해제를 즉시 시도하고 새 허가를 차단한다. 열은 **선택한 중단 기준(기본 serious/critical)** 도달 시 적용하며 critical 대응은 항상 유지한다. N31의 높은 열 중단 기준 선택을 삭제하지 않는다. 전원·열 관측 공백을 ‘과열’로 단정하지 않고 해제 미확인도 숨기지 않는다.
- 회복은 **열 상태 정상/주의가 60초 유지 AND 현재 전원에 맞는 조건**을 모두 만족해야 한다. 실제 배터리 공급 중이면 하한+5%p 이상을 60초, AC이면 정상 AC를 60초 확인한다. 데스크톱에는 존재하지 않는 배터리 잔량 조건을 요구하지 않는다. 설정된 저전력 중단 원인도 해소되어야 한다.
- 회복 표본 간격은 최대 15초다. 명시 unknown, 표본 간격 15초 초과, Sleep 또는 회복 상태의 재설정 때 회복 누적 시간을 다시 시작한다. 유효 표본 사이의 짧은 간격 자체는 초기화 사유가 아니며 수면 중 경과는 정상 관측으로 세지 않는다. 이 회복 누적과 수면을 포함하는 작업 마감은 다른 시간 계약이다.
- 기본은 회복 확인 후 직접 재개다. 선택 자동 회복은 현재 유효한 자동 조건만 재평가한다. 보호로 소비된 연결 작업 허가(lease)는 TTL이 남아 있어도 복원하지 않으며 새 명시 요청이 필요하다. 승인된 lease 설계 자체를 제외하는 뜻은 아니다. 끝난 수동은 복원하지 않으며 확인 실패 보호 차단도 기본 직접 재개다.

### 마지막 유지와 Sleep · K06/K07

- 종료 원인을 보존하고 자체 해제·원복을 확인한다. 정리의 최대 60초는 추가 유지 허가가 아니다. 진행 중에는 S12, 확인 실패에는 복구 필요를 표시한다.
- 정리 확인 뒤 현재 유효 작업 0개와 전원·덮개·소유권·세대를 다시 확인한 경우에만 **15초 동안 1회 사용 가능한 Sleep 권한**을 부여한다. 신규 유효 작업·전원 세대 변경·권한 상실·기한 만료는 옛 행동을 취소한다.
- 덮개 열림은 **닫힘 조건부 분리·만료·보호 Sleep**을 취소한다. 사용자가 직접 요청한 명시 Sleep은 열린 Mac에서도 가능하므로 열림만으로 무조건 취소한다고 설명하지 않는다.
- 늦은 원복 완료가 취소·만료된 Sleep 행동을 되살리지 않는다. 자체 유지 종료, 설정 원복, 잠자기 요청 수락, 실제 OS Sleep을 각기 S11~S14로 구분한다. 조회가 성공하지 않았는데 ‘잠들었음’이라 표시하지 않는다.
- 이미 OS 호출을 파견한 뒤에는 취소 성공을 보장하지 않는다. 취소 조건 발생과 실제 OS 결과를 별도로 표시하며 늦은 응답 때문에 같은 Sleep을 다시 요청하지 않는다.

### 잠금·원격·도우미 · K08/K09

- 화면 꺼짐·화면 잠금·시스템 Sleep은 별개다. 잠금·암호·영구 에너지 설정을 무단으로 바꾸지 않는다. 사용자가 승인한 Tether 소유의 임시 덮개 전원 변경은 소유 기록과 원복을 전제로 하며 이를 전면 금지한 것처럼 설명하지 않는다.
- 원격·외장 화면만으로 새 실행 정책이나 전용 메뉴를 만들지 않는다. **마지막 유지를 끝내면 Sleep으로 연결이 끊길 수 있는 상황에서만** `유지를 끝내면 Mac이 잠들어 원격 연결이 끊길 수 있어요`를 안내한다. 단순 앱 실행·네트워크 도달 가능성으로 원격 사용을 감지했다고 주장하지 않는다.
- 일반 잠자기 방지는 도우미 없이 제공한다. MacBook의 덮개 기능 선택 때 필수 준비·인증을 요청하고, 인증 완료만으로 자동/덮개 ON·새 작업을 만들지 않는다. 데스크톱에 덮개 도우미 설치를 요구하지 않는다. 이 문서 정리로 기존 도우미를 제거하거나 저장 설정을 초기화하지 않는다.
- 화면·덮개 토글은 현재 적격 ‘앱 기본 따름’ 작업과 다음 기본값에 적용하며 개별 OFF는 보존한다. ON은 준비·권한·적용 확인 뒤 표시하고, OFF는 해당 실행을 즉시 회수한다. ID·마감·전원 범위는 보존한다. 중지 상태에는 `저장된 설정 · 다음 유지 때 적용`을 표시하고, 실행 중에는 `현재와 다음 유지에 적용 · 개별적으로 꺼 둔 작업 제외`를 안내한다.

## 2026-10-16 문구 사전 연결 기록

`outputs/tether-v5-spec-design-20261016/copy.js`는 `window.tetherCopy`에 한국어·영어 사전만 지정한다. `ko`는 원본 한국어, `en`은 원본 영어를 키로 삼는다. 기본 화면, 펼친 설정, 안내·모달, 기능 목록을 포함한다.

원본 `t(ko, en)` 문자열은 바꾸지 않고 해당 언어의 키로 사전을 조회한다. 사전에 없으면 원문을 그대로 보여준다. 동일한 원문을 여러 곳에서 쓰면 같은 표시 문구가 적용되므로, 서로 다른 뜻에 같은 키를 쓰는 문제는 사전만으로 해결할 수 없다. `t()`를 거치지 않는 고정 문자열도 자동으로 바뀌지 않는다.

사전에는 UI 코드, 이벤트 처리, 실행 함수가 없다. 표시 문구의 변경은 설정 저장, 권한 허용, 도우미 설치, 잠자기 방지 시작을 수행하지 않는다. HTML 시안에서 사전 로드와 `t()` 조회를 연결했던 기록이다. 이번 P0 추천 문구가 그 사전이나 실제 앱에 반영됐다는 뜻이 아니다.

| 대기 또는 자동 작업만 실행 중 | 시간 선택기 + 직접 시작 | 유효한 자동 작업은 이유 영역에 계속 표시. 직접 시작 버튼이 자동 작업을 교체하거나 종료한다는 뜻이 아님 |
| 유한 타이머 실행 중 | 타이머 남은 시간 / 끝날 시각 / 30분 추가 / 타이머 끝내기 | 기본 연장 버튼은 하나. 연장은 기존 마감에 가산하며 현재 연장·변경은 최근 시작 선택을 덮지 않음 |
| 현재 타이머의 고급 편집 | 타이머 시간 변경… | 다른 가산량·지금부터의 기간·정확한 종료 시각 변경. 다음 시작 설정과 다른 제목을 사용 |
| 끄기 전까지 실행 중 | 끄기 전까지 / 직접 시작한 작업 끝내기 | 배터리 상한 등 유효한 제한이 있으면 함께 표시. 의미 없는30분 가산 대신 고급에서 시간제로 변경 |
| 보호로 중단·회복 | S08 보호로 중지됨 / S09 안전 상태 확인 중 / S10 다시 시작할 수 있어요 | 회복 60초 확인 전 시작·재개 비활성. 끝난 타이머를 실행 중처럼 표시하거나 시간 선택만으로 보호가 해제된다고 안내하지 않음 |
| 타이머 종료 뒤 자동 작업이 계속 유효 | 타이머 종료 · 전원 연결 자동 유지 중 | 실제 전원 연결 자동 조건이 유효할 때의 예시. 다른 근거는 실제 조건 이름으로 표시하며 전체 종료·타이머 부활로 표현하지 않음 |
| 부모 기능 꺼짐 | 관련 세부값 접기 + 설정 편집 진입 유지 | 예고가 꺼지면 예고 세부, 화면 기능이 꺼지면 유휴 시간은 기본 화면에서 접고 값을 보존. 세부값 보존은 실행 허가가 아님 |

영어의 해당 기본 문구는 `30 min / 1 hour / 2 hours`, `Until turned off`, `Add 30 minutes`, `End timer`로 같은 의미를 유지한다. `Until turned off`는 배터리 상한·기기 보호를 무시한다는 약속이 아니다. 다음 시작과 현재 타이머 편집에는 서로 구별되는 제목을 사용한다.

‘끄기 전까지’는 직접 시작 시간 문맥에만 쓴다. 배터리 최대 시간·프로필 상한의 ‘무제한’까지 같은 말로 바꾸지 않는다. 같은 원문 사전 키를 공유한다면 문맥별 키를 분리해야 하며, 전역 문자열 치환으로 서로 다른 설정의 의미를 합치지 않는다.

## 의미를 보존하는 기준

- **잠자기 방지와 잠자기 요청:** “잠자기 방지 중”은 Tether의 유효한 유지 상태를 뜻한다. 실제 시스템의 모든 잠자기를 막거나 물리적 동작에 성공했다는 보장은 아니다. “잠자기 요청”을 “잠자기 완료”로 바꾸지 않는다.
- **화면과 잠금:** “화면 끄지 않기”, 화면 숨기기·가림, macOS 로그인 잠금은 별개다. 가림을 보안 잠금이라고 부르거나 이미 잠긴 Mac의 자동 잠금 해제를 약속하지 않는다.
- **자동 전체와 개별 조건:** “자동 시작 허용”은 자동의 전체 허용이고 개별 조건의 켬·끔은 별개다. 자동 OFF는 수동을 끝내거나 모두 중지 차단을 만들지 않는다. 허용 표시만으로 실제 실행·권한·도우미 준비를 완료라고 말하지 않는다.
- **타이머 종료와 전체 중지:** “타이머 끝내기”는 해당 타이머만, “모두 중지”는 자체 유지 전체 종료와 직접 해제 전까지의 새 자동 차단이다. 다른 앱·명령·빌드 프로세스를 강제로 종료하지 않는다. “중지 해제”는 켜 둔 자동 조건 재평가이며 끝난 타이머를 되살리는 조작이 아니다.
- **시작 선택과 현재 타이머:** 기본 시작 선택기는30분·1시간·2시간이며 첫 값30분, 최근 유한 선택을 기억한다. ‘끄기 전까지’는 보조 옵션이다. ‘30분 추가’, 현재 종료 시각 변경, 알림의 연장은 최근 시작 선택을 덮지 않는다. 끝난 타이머와 아직 유효한 자동 작업을 함께 설명하고, 유효 자동이 있는데 전체가 종료됐다고 말하지 않는다.
- **접힌 세부값:** 부모 기능이 꺼지면 관련 세부값을 접되 보존하고 설정 편집 진입은 남긴다. 예고OFF·화면OFF의 세부값을 숨긴 것을 삭제·실행·권한 허용으로 표현하지 않는다. 다시 켤 때의 실제 적용은 현재 권한과 보호 조건을 따로 확인한다.
- **전원과 시간:** 기본 분리 전체 종료와 N05/N06 확장을 구분하고 현재 정책에 맞는 안내를 사용한다. 연속 마감은 수면·AC에서도 흐르며 연결만으로 연장되지 않는다. 최초 배터리 기준점은 보존하고 별도 상한은 배터리에서만 집행한다. 명시 연장과 자동 연장은 다르다.
- **기기 보호:** `serious`·`critical`은 macOS의 열 상태이며 섭씨 온도가 아니다. 전원·열 공백을 과열로 단정하지 않는다. S08/S09/S10과 K05의 전원별 회복 60초·표본 간격 조건을 따른다. 사전의 단순 치환만으로 이 상태 분기를 구현했다고 하지 않는다.
- **첫 설정:** 일반 유지는 무도우미, MacBook 덮개 선택 때 필수 준비·인증이다. 선택 초안·인증·저장·실행을 구분하고 데스크톱에 덮개 설치를 요구하지 않는다. 인증만으로 자동/덮개 ON·새 유지 시작·기존 도우미 제거·설정 초기화가 발생한다고 안내하지 않는다.
- **설정 되돌리기:** 되돌리는 대상은 설정이다. 끝난 작업·명령이나 이전의 권한 승인을 복원한다는 뜻이 아니다. 확인하지 못한 결과를 성공했다고 바꾸지 않는다.
- **추가 기능:** 쉬운 이름을 붙였다고 구현 완료·지원 확정으로 승격하지 않는다. 기기·macOS·권한 확인 안내와 기본 꺼짐 상태를 유지한다. 입력·포인터 이동·BlackOut 등의 기능도 서로 다른 선택으로 남긴다.
- **다른 앱 영향:** 확인된 절전 영향만 설명한다. 프로세스가 실행 중이라는 이유만으로 원인이라고 단정하거나 Tether가 다른 앱을 종료한다고 말하지 않는다.

## 검수 범위

이번 2026-10-21 작업은 두 문서의 상태 ID·주표시·우선순위·수치·제외 이력과 링크를 정적으로 대조하는 범위다. 사전이나 시안 로직의 실행 시험을 포함하지 않는다. K00~K09와 `V5-P0-00~09`의 근거 연결은 [수락 체크리스트](V5-VALIDATION-CHECKLIST.ko.md)를 따른다.

분리·배터리 상한 종료 뒤 차단이 Wake·새 ID·캐시로 해제되지 않고, 같은 자동 활성 사건의 상한 보존과 새 활성 사건의 선행 조건이 COPY/DESIGN에서 같은 뜻인지 확인한다. 이 정의는 보조 설명·검증 조건이며 메뉴 정보나 조작을 추가하지 않는다.

사전 구문, `t()` 연결, 문맥별 표현, 접힘·스크롤·밝은 화면·영어 줄바꿈에 대한 [2026-10-16 HTML 재검수](V5-REVIEW-20261016.ko.md)는 그 당시 산출물의 기록으로 보존한다. 이번 문서가 현재 웹/native UI·설치·물리 동작을 통과시킨 것은 아니다. 기존 유효 근거는 해당 후보에 남기되 새 P0 추천 규칙의 미실행 수락을 `pass`로 승격하지 않는다.
