# Tether 디자인 계약 · v3

색·컴포넌트·Liquid Glass·치수·입력·검증의 현재 기준은 저장소 루트 [DESIGN.md](../DESIGN.md)를 따른다. 이 문서는 기능의 표시 의미와 조작 계약을 설명한다.

2026-10-08 · macOS26 이상 / Apple Silicon. 설치본53의 설정·메뉴 구조에 맞춘 디자인 계약이다. **기능·물리 동작·전체 접근성의 합격 기록은 아니다.** 실제 확인과 미확인은 [디자인 리뷰](DESIGN-REVIEW.ko.md)의 최신 항목에 둔다. 이전 독립 디자인 시안의 사이드바는 현재 설치 UI의 탐색 구조가 아니다.

[기능 정의](PRODUCT-SPEC.ko.md), [실행 설계](ARCHITECTURE-REDESIGN.ko.md), [현재 조사](COMPETITOR-DEEP-RESEARCH.ko.md)를 따른다. 실제 미확인 항목은 [디자인·출시 게이트](DESIGN-GAPS.ko.md)에 둔다.

## 1. 일상 조작의 중심

사용자는 지금 작업이 유지되는 이유를 먼저 확인하고, 필요하면 시간을 골라 명시적으로 시작한다. 자동 전원 조건과 수동 요청은 서로 바꾸지 않는다. 일반 유지와 덮개 유지도 별도 기능이다.

- 대표 상태 하나와 핵심 이유를 먼저 보여 준다. 자동·수동이 모두 유효하면 두 이유와 각 마감을 함께 설명한다.
- 메뉴는 대표 상태/이유 → 자동 조건·덮개 → 수동 시간 선택·시작/종료 순서다. 설정은 자동 규칙 → 덮개 → 수동 기본값으로 구성한다. 시간 선택 자체는 시작이 아니다.
- 정상 상태에 큰 경고나 도우미 내부 정보를 반복하지 않는다. 필요한 제한·실패 이유는 해당 기능 옆에 둔다.
- 원격 연결은 진단 정보이며 작업 수명·자동 조건·메뉴 아이콘 폭을 바꾸지 않는다.
- 데스크톱에는 덮개 조작을 숨긴다. 덮개 관측 실패는 데스크톱이나 닫힌 MacBook으로 추정하지 않는다.

## 2. 메뉴 패널과 설정 창

| 화면 | 크기·구성 | 조작 우선순위 |
|---|---|---|
| 메뉴 패널 | 고정360pt 폭, 내용에 맞는 높이·본문 스크롤·고정 상하단 | 대표 상태/이유 → 자동 조건·덮개 → 수동 선택/시작 → 전체 중지 |
| 설정 창 | Scene 기본800×660pt, 본문 최소760×600pt, 읽기 열 최대700pt, 상세 영역 세로 스크롤. native 제목·툴바 크기는 별도 | 실제 `Settings` Scene + grouped `Form` |
| 설정 탐색 | 툴바의 native segmented `Picker`. 반복 소개와 별도 사이드바 없음 | 작업 유지 / 기기 보호 / 앱 설정 |
| 세부 점검 | 요청한 경우에만 sheet 또는 접힌 상세 영역 | 관측 시각/실패 → 실제 요청 → 제한과 근거 |

SwiftUI [Picker](https://developer.apple.com/documentation/swiftui/picker), [Form](https://developer.apple.com/documentation/swiftui/form), Apple [Settings](https://developer.apple.com/design/human-interface-guidelines/settings)와 [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)을 기준으로 사용한다. 치수는 제품의 배치 선택이며 Apple이 정한 의무 규격이나 실렌더 합격값이 아니다. 섹션 표면·구분선·대부분의 행 여백은 native Form에 맡기고 중복 카드/외곽 padding을 더하지 않는다.

메뉴에는 자동·수동의 남은 시간을 분리한다. 숫자 클릭으로 종료하지 않으며 `수동만 끝내기`를 이름 있는 버튼으로 제공한다. 상태 설명은 필요한 만큼 줄바꿈하고 중요한 실패·시간을 말줄임표로 숨기지 않는다.

창은 이름·값·설명·조작의 정렬을 공유한다. 좁은 폭이나 긴 번역에서는 행을 세로로 바꾸고 버튼의 동작명을 보존한다. 로그·PID·revision·lease·원본 복구 기록은 기본 화면에 펼치지 않는다.

## 3. 상태와 문구

| 관측 또는 의도 | 기본 표현 | 표시해서는 안 되는 결론 |
|---|---|---|
| 자동 AC 조건만 선택 | `전원 연결 시 자동 유지` | 선택만으로 `유지 중` |
| 자체 일반 assertion 확인 | `작업 유지` + 자동/수동 이유 | 덮개·화면·원격까지 정상 |
| 덮개 기능 준비 중 | `덮개 유지 준비 중` | 명령 완료만으로 `닫아도 유지` |
| 지원 조건과 실제 적용 확인 | `덮개 유지 확인` + 적용 조건 | 모든 Mac/원격 앱에서 무조건 유지 |
| 일반 유지 중, 도우미 실패 | `작업 유지` / `덮개 기능 사용 불가` | 앱 전체 실패 또는 일반 시작 금지 |
| 전체 일시중지 | `지금 모두 중지됨` + `다시 시작` | 전원 왕복·Wake로 자동 재개 |
| 자체 자원 해제 확인 | `자체 해제 완료` | 실제 Sleep 확인 |
| Sleep 요청 후 실제 사건 미확인 | `OS 잠자기 미확인` | 프로세스 성공·표본 공백만으로 잠듦 |
| 화면 절전/잠금 조회 실패 | `확인 필요`와 실패 시각 | 값 없음 → 화면 꺼짐/잠금 해제 |
| 원복 실패 | `원복 확인 필요` + 해당 기능 제한 | 설정 삭제·도우미 종료 → 원복 성공 |

하나의 녹색 표시로 모든 상태를 묶지 않는다. 작업 유지, 덮개 적용, 화면 절전 관측, 앱의 잠금 선택, OS 암호 요구, 실제 잠금, 인증된 원격 화면·입력은 독립 정보다. 상세 관측에는 출처와 시각을 붙인다.

선택값은 ‘설정’, 진행 중 명령은 ‘준비 중’, 확인된 결과는 ‘확인’으로 표현한다. 예시 미리보기에는 `예시 데이터`를 항상 표시하고, 관측 실패·보호 상태도 예시임을 구별한다.

## 4. 수동 시간과 중지의 범위

| 조작 | 의미·표시 계약 |
|---|---|
| `수동 시작` | 선택한 기간/무제한을 새 요청으로 시작. 자동 조건은 그대로. 시간 선택은 마지막 값만 기억 |
| AC에서 `무제한` | 어댑터 범위. 전원 분리 시 기본 종료임을 바로 아래 표시 |
| `전원 분리 후 수동 유지 계속` | 시작 직전에 별도 선택. 실행 중 바꿀 수 없음. 원래 마감/최초 배터리 전환+120분 중 이른 때 종료 |
| 배터리에서 수동 시작 | 1~120분. 무제한은 제공하지 않음 |
| `수동만 끝내기` | 수동 요청만 종료. 자동이 유효하면 계속 유지됨을 버튼 아래 설명 |
| `자동 트리거 ON/OFF` | 자동만 시작/중지. 조건·시간을 기억하고 실행 중 수동 요청·마감은 보존. 전체 중지·보호를 ON으로 해제하지 않음 |
| `지금 모두 중지` | 수동 종료 + 전체 일시중지. 명시적 다시 시작 전까지 보존 |
| `잠자기` | 자체 유지·변경 해제 뒤 한 번 시스템 Sleep 요청. `모두 중지`와 다른 동작 |
| `다시 시작` | 해당 사용자 일시중지/허용된 보호 해제 후 현재 조건 재평가. 만료 수동 시간을 복원하지 않음 |

배터리 자동 모드도 별도의 1~120분 활성 구간이다. 수동 타이머가 끝나도 AC 자동 조건은 계속 유효할 수 있다. 자동 배터리 구간이 끝났다면 남은 시간 0과 다시 시작 범위를 표시하며 반복 통지로 시간을 다시 채우지 않는다.

AC 왕복·잠금·원격 접속·창 열기·IPC 재연결은 기존 배터리 마감을 바꾸지 않는다. 진행 표시와 종료 시각은 같은 모델의 마감에서 계산하고, UI 표시 갱신을 정책 timer로 쓰지 않는다.

`잠자기`는 다른 앱 작업도 잠재울 수 있다는 영향을 이름 있는 조작 가까이 설명한다. 실제 Sleep→FullWake를 확인한 경우에만 해당 잠자기 일시중지가 해제된다. 실패·미확인·재실행에서는 `다시 시작`을 제공하며 전체 중지·보호 이유를 함께 지우지 않는다.

## 5. 세 페이지의 정보 순서

| 페이지 | 항상 보이는 내용 | 기본 접힌 내용 |
|---|---|---|
| 작업 유지 | 자동 ON/OFF·전원 조건 → 덮개·분리 동작 → 수동 기본 시간·배터리 예외. 실제 시작/종료는 메뉴 | 덮개 유지 제한·배터리 시간 규칙. 미지원 잠금 실행 토글은 숨김 |
| 기기 보호 | OS 열 상태, 저전력/잔량 관측, 사용자 배터리 하한, 중지 이유·재개 조건 | 보호 근거·추가 진단 |
| 앱 설정 | 로그인 실행, 버전·업데이트 확인 | 베타 채널, 로그·진단 내보내기, 도우미 관리·제거 |

작업 유지의 덮개 그룹은 해당 기기에서만 보인다. `덮개를 닫아도 유지`는 자동과 수동의 적용 범위를 구별하고, 열린 상태에서 도우미 준비·인증을 끝내도록 안내한다. 도우미 미설치·인증 취소·비관리자 상태에서도 가능한 일반 유지를 사용할 수 있다.

자동 유지에는 `자동 트리거 사용` 스위치와 전원 조건 선택기를 따로 둔다. OFF에서는 선택한 전원 조건·시간을 기억하고 조건 편집을 비활성으로 표시한다. 수동 시작은 전원·배터리 모두 제공하며 자동 OFF 때문에 비활성으로 만들지 않는다. 메뉴 패널에도 같은 스위치를 제공한다. 전원 무제한을 선택해도 기본은 분리 종료이며 배터리 계속 유지 예외를 조작 가까이 안내한다.

설정의 수동 기본 시간 바로 아래에 배터리 예외 선택을 두며 실행 중 비활성으로 표시한다. 현재 확인되지 않은 덮개 잠금 실행은 토글로 제공하지 않고 진단의 정책 조회·설정 링크를 사용한다. `로그인 상태 유지` 역방향 스위치를 만들지 않는다. 외관·고정 아이콘 폭은 조작할 수 없는 설정 행으로 노출하지 않는다. 종료 시각 지정·빠른 연장·통계·여러 종류의 트리거 편집기는 이번 화면에 넣지 않는다.

전원 분리 동작은 `잠자기 요청(추천)` / `macOS에 맡기기` 두 가지다. 추천은 유효한 자동·수동 배터리 요청이 없는 닫힌 분리에서 자체 해제 후 한 번 요청한다. macOS에 맡기기는 자체 해제만 하며 다른 앱 요청 때문에 계속 깨어 있을 수 있음을 설명한다.

최초 문제의 필수 경로는 닫힌 AC 분리 뒤 실제 잠자기다. 전원 재연결로 이미 잠든 Mac을 깨우는 기능은 제공하지 않는다. 실패/미확인 때 계속 돌아가는 상태를 `클램쉘 해제 완료`라고 표시하지 않으며 실제 Sleep 근거와 자체 원복 결과를 구별한다.

전역 SleepDisabled 후보를 쓰는 덮개 설정에는 **macOS 메뉴의 수동 잠자기도 차단할 수 있는 전역 효과**, 타사 동일 값 작성의 구별 한계, 자체 잠자기 경로를 설명한다. 이 제한을 깊은 진단에만 숨기지 않으며 실증 전 활성 지원으로 표시하지 않는다.

화면은 `macOS 화면 절전 허용`이 기본이다. 밝기 0을 화면 끄기로 제공하지 않고 전체 display sleep 명령을 내장 화면 전용으로 설명하지 않는다. 외장/가상 화면 존재만으로 덮개 책임이 끝났다고 표시하지 않는다.

잠금 선택은 `덮개를 닫을 때 Tether가 잠금 요청`이다. 꺼짐은 앱이 요청하지 않는다는 뜻이며 OS 자동 잠금을 막지 않는다. `잠금 화면 설정 열기`를 제공하되 암호 요구 정책은 조회·설명만 한다. 별도 로그인 유지 선호는 저장하지 않고 실제 무잠금·원격 결과는 검증한 조합에 한해 안내한다.

OS 정책·MDM·iPhone Mirroring과 실제 잠금이 확인되지 않으면 `무잠금 보장`·`원격 준비됨`이라고 표시하지 않는다. 원격 앱 설치/프로세스/화면 요청은 인증된 접속·프레임·입력과 별도다. 원격 상태는 기본 메뉴 배지로 쓰지 않는다.

보호는 근거 없는 CPU 온도 숫자·안전 시간 보증 대신 OS 상태와 사용자 잔량 하한을 보여 준다. 열 보호는 `항상 적용`으로 표시하며 전원·배터리 모두 자동·수동보다 우선한다. serious/critical에서 자체 유지를 종료하고 닫혀 있으면 잠자기를 한 번 요청하며, 냉각만으로 다시 켜지지 않음을 같은 그룹에서 설명한다. OS 열 상태의 nominal 보고만으로 모든 센서 정상·안전 온도라고 표시하지 않는다. 조회 실패를 정상으로 위조하지 않는다. 120분은 제품 한도다.

## 6. 시각·접근성 기준

기본은 앱 내부 다크 외관이다. OS 전역 외관은 바꾸지 않는다. Apple [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)의 탐색/조작층 원칙에 따라 native 탭·toolbar·주요 조작에 Liquid Glass를 사용한다. 긴 설명·상태·Form 내용에는 안정적인 기본 배경을 둔다.

커스텀 효과는 SwiftUI [Applying Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)를 따른다. 유리 카드 중첩·상태별 배경 이동·반복 반짝임을 추가하지 않는다. Reduce Transparency·Increase Contrast·Reduce Motion을 존중하며 실제 OS 렌더로 확인한다.

| 항목 | 제품 시작값 |
|---|---|
| 섹션 제목 / 대표 상태 | 시스템 `.headline` / `.title3` 중심 |
| 본문 / 보조 설명 | 시스템 `.body` / `.callout`·`.footnote`, macOS 기본 본문13pt |
| 시간·주요 숫자 | 시작값24pt·`ScaledMetric`·monospaced digit |
| 자간 / 설명 행간 | SF와 semantic style의 시스템 기본. 강제 자간 없음 |
| 설정 여백 / 행 높이 | native Form 여백, 상하 scroll margin12pt, 컨트롤 최소22pt |
| 메뉴 그룹 간격 / 컨트롤 | 본문 그룹12pt, native 컨트롤 크기·첫 기준선 정렬 |

수치는 제품의 배치 선택이다. [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography)의 macOS 기본 본문13pt와 semantic style을 따른다. 행 최소22pt는 native Form의 실제 상하 padding을 포함한 클릭 영역 크기가 아니다. 작은 창·한국어/영어·긴 이유를 검사하며 native regular 크기와 기본 포커스 표시를 유지한다.

Apple [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)를 따라 일반 텍스트 대비 4.5:1을 목표로 측정한다. 반투명 배경·밝고 어두운 배경·고대비를 실제로 측정하기 전 통과를 주장하지 않는다. 색뿐 아니라 이름·선택 상태·기호·설명으로 상태를 전달한다.

키보드의 Tab/방향키/Space/Return/Escape, 메뉴 열림·닫힘 후 포커스, 긴 번역의 배치와 가독성을 확인한다. 2026-10-07 사용자 결정으로 VoiceOver 전용 기능·낭독·검증은 지원 범위에서 제외한다. macOS 기본 컨트롤 이름과 상태는 유지한다.

기존 앱 아이콘 자산과 18pt 흑백 template 메뉴 아이콘을 재사용한다. 원격 배지·카운트다운으로 status item 폭을 늘리지 않으며 앱 아이콘을 이번 작업에서 다시 만들지 않는다.

## 7. 미리보기와 출시 앱의 경계

현재 배치 검토는 `scripts/build-preview.sh`의 `Tether Preview.app`에서 설치 앱과 같은 `SettingsView`·`TetherPanel`을 사용한다. private helper·모의 OS 효과이며 설치본53과는 별도 실행이다. native 캡처와 정적 렌더의 증거를 [최신 디자인 리뷰](DESIGN-REVIEW.ko.md)에 연결한다. 아래 독립 Design 시안의 기록은 당시 역사이며 현재 설치 UI와 동일한 화면으로 취급하지 않는다.

`Sources/Tether/DesignPreview/`의 네이티브 SwiftUI 미리보기는 예시 상태와 메모리 내 선택·시작·중지만 다룬다. runtime·helper·OS 설정·실제 Sleep/잠금·진단 저장·업데이트 설치에 연결하지 않는다. 표시된 전원·시간·원격·보호는 기기 관측이 아니다.

예시 상태는 AC 자동, 수동 배터리, 자동+수동, 전체 중지, 보호 중지, 도우미 실패/일반 유지, 데스크톱을 구별한다. 미리보기 조작은 배치·문구·선택 흐름 확인이며 순수 정책 회귀나 실제 assertion 시험을 대신하지 않는다.

설정과 메뉴 비교 렌더는 [redesign-v3.png](images/redesign-v3.png) 하나로 관리한다. 2026-10-06 생성·열기 확인을 완료했다. 이미지 내 사이드바는 AppKit vibrancy가 bitmap에 누락되는 문제를 피하기 위한 저장 렌더 전용 행이며, 실제 창은 native `List`를 사용한다. 저장 이미지에는 불투명 재질 대체가 적용되어 실제 Liquid Glass·OS26·VoiceOver·외장/원격 입력의 성공 증거가 아니다. 별도 렌더·시험 파일을 Desktop에 저장하지 않는다.

`scripts/build-preview.sh --design --run`으로 독립적인 `build/Tether Design.app`을 연다. 이 번들의 기본 실행은 항상 디자인 예시로 진입하며 설치 앱·도우미를 교체하지 않는다. 창의 `예시 데이터` 메뉴에서 상태를 바꿀 수 있다.

현재 로컬 네이티브 창에서 세 페이지 탐색, 수동 시간 선택만으로 시작되지 않음, 명시적 시작, 수동 종료 뒤 자동 유지 보존, 전체 중지·다시 시작, 도우미 없음에서도 일반 시작을 제공하는 예시를 확인했다. 빌드와 PNG 저장도 통과했다. 실제 타이머·assertion·잠자기·잠금은 시험하지 않았다. 최소 창과 일부 한국어/영어 흐름의 [디자인 리뷰](DESIGN-REVIEW.ko.md)를 추가했고, 모든 긴 문구 조합·VoiceOver·macOS 26 실기기 확인은 남아 있다.

추가로 자동 OFF→수동 시작, 자동 ON/OFF 왕복 뒤 `둘 다` 조건·60분 배터리 선택 보존, 수동 유지의 별도 활성 표시를 네이티브 예시 창에서 확인했다. 기기 보호 페이지의 항상 적용·전원/배터리 적용 범위·닫힌 잠자기·냉각 후 직접 재개 문구도 확인했다. `swift test --filter DesignPreviewStateTests`의 메모리 표시 상태 회귀 7개가 통과했으며 이는 v3 실행 정책·실기 보호의 시험 결과가 아니다.

인터랙티브 예시에도 `--narrow`, `--page sessions|protection|app`, `--english`, `--light`를 적용할 수 있다. 예를 들어 `open -n 'build/Tether Design.app' --args --narrow --english --page app`으로 최소 크기 영어 앱 설정을 연다. 기본 외관은 계속 다크이며 외관 선택은 예시 실행에만 적용된다. 개별 패널/설정 PNG에도 예시 표기를 포함한다.

## 8. 완료 판정

문서 정합성 → 예시 렌더/메모리 조작 → 출시 UI의 실제 모델 연결 → 정책/종료·복구 회귀 → macOS 26 실기기 → 접근성·원격 조합의 근거를 구별한다. 예시에서 보기 좋다는 이유로 지원·무잠금·완전 공존을 약속하지 않는다.

로그·진단은 기본 접고 필요한 실패만 해당 기능에서 바로 안내한다. 내보내기는 명시적 사용자 요청과 저장 위치 선택을 거치며 비밀번호·토큰·환경 전체·화면 내용을 포함하지 않는다. 구체적 미확인 조건과 증거는 [DESIGN-GAPS](DESIGN-GAPS.ko.md)에 기록한다.
