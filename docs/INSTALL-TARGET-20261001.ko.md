# 기기별 도우미 설치 판정

2026-10-01 · **빌드 50 미배포 후보**. [Apple Silicon 지원 #8](https://github.com/jukqaz/tether/issues/8)과 [업데이트 #1](https://github.com/jukqaz/tether/issues/1)의 일부 보완이다. 설치본 49와 시스템 전원·잠금 설정은 변경하지 않았다.

데스크톱 앱은 이미 관리자 도우미 없이 사용자 세션의 공개 assertion으로 일반 작업을 유지한다. 이전 설치기는 덮개 키가 없거나 조회에 실패하면 모두 “MacBook을 열어 주세요”로 안내했다. 기기 판정을 먼저 적용해 이 두 상황을 구별하며, 데스크톱에 덮개 도우미를 추가하지 않는다.

## 판정과 실행 순서

| 현재 관측 | 새 도우미 설치 경로 |
|---|---|
| 지원 플랫폼, 내장 배터리·덮개 모두 확인 | MacBook 경로. 현재 덮개 열림도 확인해야 진행 |
| 지원 플랫폼, 내장 배터리·덮개 모두 없음 확인 | 도우미가 필요 없다고 안내하고 기존 서비스·파일을 유지 |
| 배터리 또는 덮개 관측이 불명확·불일치 | 관측을 확인하지 못했다고 안내하고 교체 보류 |
| 지원 플랫폼 밖 | Apple Silicon·macOS 15 이상 조건 안내, 교체 거부 |

`MacCapabilities.helperInstallTarget`를 앱과 도우미의 공통 판정으로 사용한다. 앱은 관리자 인증 요청 전에 최신 관측을 읽는다. 설치 스크립트는 인증 뒤 처음 검사하고, 기존 서비스를 종료하기 직전에 기기와 덮개를 다시 검사한다. 첫 판정이 성공했어도 두 번째 관측이 달라지면 기존 서비스를 종료하지 않는다. 두 번째 검사 전에 만든 복구 사본은 남길 수 있다.

포장된 도우미의 `--validate-settings --helper-install-target`는 `helper-install-target-v1` 응답만 반환하고 종료한다. helper 초기화·상태 파일 생성·전원 변경을 수행하지 않는다. 이미 알려진 종료 모드를 사용하므로 구버전의 `settings-valid` 응답을 설치 가능으로 잘못 인정하지 않는다. 판정 기능이 없는 실행기는 교체 전에 거부한다.

설정 schema 3·IPC protocol 2와 기존 저장값은 그대로다. 전원 조건, 사용자 끄기, 이관·원복의 소유권 소비 규칙을 변경하지 않는다. 데스크톱 앱의 일반 업데이트는 기존 덮개 없는 경로를 유지한다.

| 포장 설치 대상 조회 | 통과 | 현재 호스트에서 portable 응답, 없는 control 경로에도 종료·상태 파일 미생성 |

새 설치 시나리오는 데스크톱, UPS를 내장 배터리로 세지 않는 분류 결과, 불명확한 기기, 배터리/덮개 개별 관측 누락, 미지원 플랫폼, 손상 facts, 위험한 권한, symlink/hardlink, 구버전 probe와 검사 도중 기기 판정 변화를 포함한다. 첫 검사에서 거부한 경우 백업·서비스 명령·전원 명령이 없고 원본 설정·바이너리·plist·lock inode가 유지되는지 확인했다. 두 번째 검사에서 거부해도 서비스·전원 명령이 없고 기존 파일은 유지된다.

모의 하드웨어 facts는 non-root의 0700 임시 설치 경로에서만 읽으며 파일은 현재 사용자 소유·0600·단일 링크여야 한다. root는 이 fixture 환경값을 무시하고 실제 관측을 사용하도록 구현했다. 실제 root 실행을 시험한 결과로 표현하지 않는다. 테스트 데이터는 배포 앱에 들어가지 않는다.

이 기기 판정 단계의 포장 helper SHA-256은 `9a943b666f875b93040447b256db5e98ffcbc1825ab7c8df90dbcdba175094f3`다. 앞선 [GUI 작성자 단계](GUI-WRITER-GATE-20261001.ko.md)의 결과와 포장 해시는 그 시점의 기록으로 보존한다.

## 실제 이전 helper를 사용한 후속 검증

2026-10-01 후속 단계에서는 기존 34개에 실제 빌드 49 helper를 실행하는 7개를 더해 최종 포장으로 **총 41개** 설치 시나리오를 통과했다. 이전 34개의 old helper는 텍스트 fixture이므로 실제 이전 프로세스의 교체 근거와 구별한다. 추가 검사는 꺼짐·활성·detach 뒤 49→50 교체, watchdog/서비스 시작 실패 뒤 49 복구, 정지된 이전 PID가 살아 있을 때 교체 거부를 포함한다. 종료 확인 후 마지막 설정 백업, 실행 파일·최신 소켓·epoch·설정 보존, 임시 타이머와 소비된 소유권의 재생 방지를 대조했다. watchdog 등록·launchctl/pmset는 모의 구현이며 모든 helper는 dry-run이다. 시험 디렉터리·프로세스는 종료 뒤 제거했다.

실제 이전 실행 파일은 설치본 `2026.9.1` 빌드 49의 복사본이며 SHA-256은 `606eb2bcb046fd70d6c017dbcef8905b60a2cf2796399c497d9b83562df37475`다. 설치본은 dirty source 표시가 있어 특정 커밋의 소스와 같다고 단정하지 않는다. 후속 최종 후보의 helper SHA-256은 `36bb84b4908380a859c4c4e0b2fbd9bdbc8fcba50ec0aa4297a649514ae934d2`이며 macOS 15 arm64 ad-hoc 포장을 확인했다. 같은 소스의 Swift **611개(Core 500 + 앱·업데이트 111, native 7개 포함)**는 실패·건너뜀 0이다. 설치본 49는 교체하지 않았고 현재 미배포 후보다. 새 공통 세션의 예산 이관·관리자 launchd·GUI 서명 검사·물리 전원 효과·전체 Sparkle UI 성공으로 확대하지 않는다. [설정 백업·제거 및 상세 범위](UPDATES-AND-MIGRATION.ko.md).

## 남은 검증

실제 관리자 설치, 물리 데스크톱·UPS, macOS 15 런타임, 여러 Apple Silicon 기종, 실제 Sparkle 전체 업데이트와 잠자기·원격 협력은 아직 완료 근거가 없다. 기기·덮개 검사와 OS 이벤트를 원자적으로 묶지 않으므로 최종 검사 직후의 물리 변화를 전부 배제했다고 하지 않는다. UI 문구와 기기 판정은 컴파일·회귀로 확인했으며 데스크톱 화면의 직접 실행 검증은 남아 있다.

커밋·푸시·원격 CI·릴리스 게시 및 피드/ZIP 서명 검증은 이번 단계에서 하지 않았다. #1/#8과 [남은 설계 조건](DESIGN-GAPS.ko.md)을 완료 처리하지 않는다.

GitHub에는 [#8 진행 기록](https://github.com/jukqaz/tether/issues/8#issuecomment-5918816691)을 컴퓨터유즈로 게시하고 재조회했다. 보드는 대기 4·진행 6·완료 0이며, 실제 지원 검증이 남아 #1/#8을 닫지 않았다.
