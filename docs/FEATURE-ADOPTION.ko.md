# Tether 기능 채택 결정

> **문서 분류 · 2026-10-21: 역사 자료 — 앱별 기능 비교·채택 이력.** 본문은 당시의 선택·근거로 보존한다. 현재 범위·기본값은 [기능명세서](PRODUCT-SPEC.ko.md), 새 수락 조건은 [현행 검증표](V5-VALIDATION-CHECKLIST.ko.md)를 따른다. 아래의 ‘현재·최신·최종’과 합격 수는 당시 대상에 한정하며 현재 전체 기능의 완료를 뜻하지 않는다.

**후속 결정본:** [V5 기능명세](archive/2026-10-21-spec-cleanup/PRODUCT-SPEC-V5.ko.md)에 41개 기능 묶음의 채택 형태·기본값·충돌 정책을 정리했다. V5 시안이며 앱 구현은 보류한다. 아래 후보58 비교와 당시 결정은 구현 근거로 보존한다.

**최신 방향 · 2026-10-16:** 사용자는 아래 비교 이후 기존 유지 규칙을 잠시 제외하고 다른 앱의 장점을 넓게 통합하도록 지시했다. 차기 조사·정책 선택지는 [기능 수집·통합안](FEATURE-SYNTHESIS-20261016.ko.md)을 따른다. 아래 ‘핵심 규칙 유지’는 당시 결정과 현재 후보58의 비교 기준이며 새 설계를 제한하지 않는다. 앱 코드·설치본은 변경하지 않았다.

## 현재 판단 · 2026-10-16

현재 비교 대상은 Keepresso 정식 **v1.27.0 / `16a5fe8aeac6caf981feb9e920d8d13e2de0764a`**와 Tether **후보58 / v4**의 소스다. 공식 최신 릴리스도1.27.0으로 확인했다. Keepresso 개발 브랜치의 이후 변경을 정식 기능에 섞지 않는다. 이 비교는 공식 문서·고정 코드와 Tether의 구현 근거를 대조한 것이며 두 앱을 같은 환경에서 실측한 성능/안정성 시험이 아니다.

사용자는 ‘다른 앱들처럼 옵션을 많이 제공’하길 요청했고 **‘핵심 규칙 유지, 나머지 옵션 확장’**을 선택했다. AC 자동만 허용·전원 분리의 전 요청 종료·최초 배터리 시작+120분은 유지한다. 추가 UI는 시안 검토 후 적용한다. 새 편의 옵션8개 범위와 검증은 [v4 §14](archive/2026-10-21-spec-cleanup/PRODUCT-SPEC-V4.ko.md#14-편의-옵션-확장-요구--2026-10-16)에 반영했다. 이번 문서 변경으로 앱 코드·설치본·실제 전원 상태를 바꾸지 않았다.

현재 후보58은 소스·격리 자동49단계와 실제 UI 고유15/24 경로 근거가 있고, 수정9개 UI 재검증·새 후보 설치·물리 인수는 미완료다. 아래 ‘있음/제공’은 **소스상 연결된 기능**이며 모든 실제 환경 통과를 뜻하지 않는다. 상세는 [구현·검증 결과](IMPLEMENTATION-V4-20261015.ko.md)를 따른다.

Keepresso는 **AC 규칙+Only while brewing+자연 종료 Sleep**으로 단순 자동 사용을 비슷하게 구성할 수 있다. 그러나 수동/lease까지 분리 때 예외 없이 끝내고 최초 배터리 상한·비부활을 강제하는 계약은 같지 않다.

예를 들어 `(회사 Wi-Fi AND 빌드 앱) OR (외장 화면 AND 평일 시간대)`는 Tether의 두 단계 그룹이 더 직접적으로 표현한다. Keepresso의 Add 메뉴 분류를 중첩 논리 그룹으로 세지 않는다. 반대로 Tether의 조건 enum에 이름이 존재한다는 이유로 회의·음악·다운로드 감지가 구현됐다고 세지 않는다.

원격 preset의 의미도 구분한다. Keepresso의 `Remote Control`은 이 Mac에서 TeamViewer/AnyDesk/Parsec가 전면인 클라이언트 사용 조건이고, 원격 호스트에 사용자가 연결됐다는 확인은 아니다. SSH preset은 연결 프로세스를 근거로 추정한다. Tether의 원격/가상 화면 관측도 연결 성공·화면 사용 가능의 보증으로 확대하지 않는다.
