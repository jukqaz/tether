# Tether 기능 통합 명세

2026-09-28 · 기준 소스 `ad46bbaf587a35d2578d589600960f766bd731d3` · Tether 2.0.1

**목표는 경쟁 앱에서 확인한 유용한 기능을 폭넓게 제공하는 통합 전원관리 앱이다.** 케이블 기본 동작에 작업 세션·자동화·화면·원격 작업·절전 진단·배터리 관리를 더한다. 기능을 기본 메뉴에 전부 펼치지 않고, 필요한 모듈을 켜서 사용한다. 기능 수를 줄이는 대신 같은 일을 하는 기능은 공통 엔진으로 합친다.

50개 앱·도구의 공식 제품 설명과 공개 저장소를 조사하고 **10개 영역, 86개 항목**으로 통합했다. 아래는 그 조사에서 추린 요구사항과 Tether에 맞게 설계한 동작이다. 특정 경쟁 앱이 표의 모든 세부 동작을 이미 제공한다는 의미는 아니다. 경쟁 앱 실측, 배터리 소비 비교, 물리적인 덮개·전원 전환 테스트는 수행하지 않았다.

**현재 구현과 계획을 구분한다.** `기존`은 기준 소스에 기능이 있다는 뜻이며 실기기 보증을 뜻하지 않는다. `확장`은 기존 흐름에 추가 구현이 필요하다. `신규`는 도입 대상으로 정한 미구현 기능이다. `조건부`는 지원 API·기기·OS별 복원 동작을 먼저 확인해야 한다. 이 문서의 대부분은 구현할 명세이며, 현재 배포판의 기능 목록이 아니다.

## 제품 흐름

처음 실행할 때 기본 사용 목적을 고른다. 이후 메뉴바에서 바꿀 수 있다.

| 모드 | 기본 동작 | 작업 종료 후 |
|---|---|---|
| 케이블 | 현재 Tether처럼 AC에서 덮개 유지. 배터리는 명시적 예외만 허용 | AC 기본 규칙 유지. 작업 하나가 끝났다는 이유만으로 절전하지 않음 |
| 작업 | 실행 중인 작업·세션·규칙이 요구하는 동안 유지 | 마지막 유지 사유가 사라지면 정상 절전 허용 |
| 발표·회의 | 선택한 앱·화면·마이크 활동 동안 화면 또는 시스템 유지 | 화면·밝기 등 이 세션이 바꾼 설정만 복원 |
| 이동 | 닫힌 덮개는 절전 우선. 배터리 작업 유지 허용을 끔 | 이동 모드가 자동 규칙의 재활성화를 차단 |
| 원격·서버 | 선택한 원격 연결이나 작업이 진행 중일 때 유지 | 연결 해제·작업 종료 후 사용자 지정 유예 적용. 데스크톱 지원은 별도 검증 |

메뉴바 기본 패널은 **현재 상태 / 유지하는 이유 / 남은 시간 / 중지 / 화면 어둡게 / 잠자기**를 보여준다. `빌드 2개 때문에 유지 중`, `충전 중이라 유지`, `배터리 보호로 중지됨`을 구별한다. 눌러서 상세 세션을 펼치고, 설정은 `일반·작업·규칙·화면/원격·보호·기록·연동·시스템`으로 나눈다. 새 기능은 UI와 CLI에서 같은 정책을 사용한다.

## 기능이 서로 충돌하지 않게 하는 규칙

**우선순위는 보호 제한 → 사용자의 즉시 절전/모두 중지 → 명시적 세션 → 자동 규칙 → 기본 모드다.** 보호 상태에서는 어떤 훅이나 새 lease도 유지 상태를 복구할 수 없다. 사용자의 즉시 잠자기는 모든 유지 요구를 종료하며, 보통의 작업 완료는 해당 작업 하나만 종료한다.

1. **유지 사유를 합산한다.** 세션은 시스템·화면·덮개 요구를 각각 낸다. 정책 엔진이 합쳐 한 번만 시스템에 적용한다. 여러 기능이 직접 `pmset`을 쓰지 않는다.
2. **전원 모드를 존중한다.** 케이블 모드에서 마지막 작업이 끝나도 AC 기본 동작은 유지된다. 작업 모드에서는 마지막 사유 해제로 절전을 허용한다. UI는 이 차이를 표시한다.
3. **배터리 유지 상한은 공통이다.** lease 교체·갱신·자동 규칙 재발동으로 현재 4시간 상한이나 잔량·온도 제한을 초기화할 수 없다. 전원 상태 변경은 헬퍼가 판정한다.
4. **안전 중지는 붙잡아 둔다.** 냉각·재충전·대기 시간이 충족되기 전에는 자동 재개하지 않는다. 사용자가 누른 재개도 보호 제한을 우회하지 못한다.
5. **미확인 상태를 성공으로 만들지 않는다.** 활동 감지 불가·센서 누락·권한 거부·지원하지 않는 OS는 이유가 있는 미확인 상태다. 자동으로 새로운 배터리 덮개 유지를 시작하지 않는다.
6. **유예와 만료를 구분한다.** 출력이 잠시 없는 작업의 유예는 제품 정책이고, heartbeat를 잃은 클라이언트의 TTL은 장애 복구다. 잠자기 동안 흐른 시간도 만료에 포함한다.
7. **설정은 소유한 변경만 복원한다.** 이전 값과 Tether가 적용한 값을 기록한다. 그사이에 사용자나 다른 앱이 바꿨다면 무조건 예전 값을 덮어쓰지 않는다.
8. **종료 이벤트는 한 번만 실행한다.** 중복 훅·lease 갱신·앱 재시작 때문에 완료 알림이나 스크립트가 반복 실행되지 않게 이벤트 ID와 결과를 기록한다.

## 구현 구조

현재 `TetherCore`의 순수 정책과 root helper 분리를 이어간다. 기능 추가마다 새 상주 프로세스를 만들지 않는다.

| 구성 | 역할 | 완료 기준 |
|---|---|---|
| SessionStore | 수동 세션·CLI·훅의 lease 관리 | 동시성·소유권·만료·프로세스 사망·중첩 `run` 테스트 |
| RuleEngine | 상태 입력을 읽고 세션 요구를 계산 | AND/OR/제외·유예·시간대·불명 상태·중복 발동 테스트 |
| ActivityProvider | 에이전트·앱·기기·네트워크의 상태 수집 | 출처/시간/신뢰도 표시, 실제 읽는 데이터와 권한 문서화 |
| PolicyEngine | 세션 합산·프로필·보호 제한·수동 중지 판정 | 모든 충돌 사례를 시간 주입 가능한 순수 테스트로 검증 |
| HelperProtocol | 제한된 요청을 인증하고 시스템 변경 수행 | 요청별 응답·버전 협상·손상 설정 복구·원자적 영속화 |
| EventStore | 요청·적용·실제 sleep/wake 증거 기록 | 로테이션·보관 기간·중복 제거·내보내기·개인정보 삭제 |
| IntegrationRunner | Shortcuts·MCP·스크립트·webhook·예약 | 사용자 권한, 취소·시간 제한·실패 격리·범위 있는 복원 |

일반 사용자 영역에서 에이전트 활동과 규칙을 계산한다. root helper는 필요한 전원 변경과 보호를 담당한다. 현재의 admin 쓰기 가능한 설정 파일은 0단계 잠금으로 경쟁을 막고, 이후에는 인증된 제한 요청을 헬퍼가 원자적으로 저장하는 구조로 옮긴다. 임의 셸 명령을 root 요청에 넣지 않는다.

세션에는 최소한 `id`, `owner`, `source`, `requestedCapabilities`, `createdAt`, `heartbeatAt`, `expiresAt`, `endReason`이 필요하다. 표시용 이름을 유일 식별자로 쓰지 않는다. 갱신은 자신의 세션에만 적용하고, 동일 요청의 재전송은 새 세션을 중복 생성하지 않아야 한다. 살아 있는 작업 lease를 재부팅 후 자동 부활시키지 않는다.

| 단계 | 제공할 사용자 기능 | 선행 조건 | 실제 완료 기준 |
|---|---|---|---|
| 0 | 설정 저장·헬퍼 장애 복구 보강 | 현재 소스 확인 | 회귀 테스트·빌드, 물리적 절전은 별도 확인 |

기능이 많아도 0→1→2의 기반 순서를 건너뛰지 않는다. 그 이후 원격·진단(4)과 범용 규칙(3)은 제품 우선순위에 따라 순서를 조정할 수 있다. 지원이 불명확한 충전·팬·가상 화면 기능 때문에 다른 모듈의 완성을 막지 않는다.

## 검증과 이번 변경 상태

각 기능은 **정책 테스트 → 임시 파일/모의 장치 통합 테스트 → 실제 앱 화면/CLI → 해당 하드웨어 동작** 순으로 확인한다. `SleepDisabled=No`, 성공 종료 코드, 서명 검사만으로 물리적인 절전·공증·배포 성공을 선언하지 않는다.

물리적 시험 항목에는 AC→배터리에서 덮개 열린 상태/닫힌 상태, 전원 분리 후 닫기/닫은 뒤 분리, 외부 화면 연결·해제, sleep/full wake/Dark Wake, 앱 종료, 클라이언트 무응답, 헬퍼 장애, 절전 요청 실패, 잠금·VPN·밝기 복원을 포함한다. 원격 제어 세션이 관찰 결과에 영향을 줄 수 있으므로 시험 조건에 기록한다.

이번 코드 변경은 **0단계의 두 결함 수정과 설명 정정**이다. 경쟁 앱 코드를 복사하지 않고 Tether 코드에 직접 구현했다.

- `ControlStore.update`에 읽기–변경–쓰기 전체 파일 잠금 적용. 읽기는 공유 잠금을 사용한다. 250ms 안에 잠금을 얻지 못하면 실패하여 헬퍼 안전 루프가 무기한 멈추지 않게 한다.
- 깨진/빈/큰 설정 파일을 기본값으로 저장하지 않는다. inode·소유자·권한과 기존 링크 거부 규칙을 유지한다. JSONWatch는 실패 시 마지막 정상 값을 유지하고 다시 읽는다.
- watchdog이 배터리에서 오래된 헬퍼 상태를 발견하면 절전 금지를 해제하고, 새로 확인한 전원·덮개·일반 깨움 조건이 맞을 때 명시적 절전을 요청한다. Dark Wake·충전기 재연결·헬퍼 회복·상태 불명일 때는 강제 요청을 생략한다.
- README의 Amphetamine 비교와 확인되지 않은 OS별 충전 차단 단정을 정정한다.

인플레이스 쓰기 도중 프로세스가 강제 종료되면 파일이 손상될 가능성은 남는다. 이번 잠금은 동시 변경·중간 읽기를 해결하며, 영속 저장의 강제 종료 내구성은 향후 HelperProtocol의 원자적 저장으로 해결한다. watchdog 역시 절전 요청을 추가한 것이며 실제 잠듦을 확인한 결과는 아니다.

검증 결과: `swift test` **179개 통과**(기존 163개 + 회귀 16개), 셸 문법 검사 통과, `scripts/build.sh` 통과, 생성 앱의 `codesign --verify --deep --strict` 통과. 추가로 실제 TetherCore를 사용하는 독립 프로세스 4개가 160번 변경한 결과를 확인했다. 160건 모두 남았고 비활성 상태와 배터리 하한 50%가 보존됐다. 이 빌드는 기존과 같은 ad-hoc 서명이며 공증 결과가 아니다.

**1–6단계 기능은 아직 구현 완료가 아니다.** 이번 로컬 변경은 GitHub에 게시하거나 사용자의 설치된 앱·헬퍼에 적용하지 않았다. 배포 완료판이 아닌 후속 개발의 명세와 검토 가능한 기반 변경이다.
