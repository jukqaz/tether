# Tether 직접 조작 체크리스트

현재 빌드57의 최소 조작·에이전트 준비·판정은 [최신 물리 체크리스트](END-RECOVERY-PHYSICAL.ko.md)를 따른다. 아래는 빌드53 당시 기록이며 현재 사용자가 해야 할 추가 작업으로 합산하지 않는다.

2026-10-08 · **2026.10.1 Beta 1 · 앱·도우미53**의 직접 시험 계획이다. 최종 디자인 수정본을 설치했으며 현재 GUI SHA는 `d197b7ff99a1b514d77ad9e6ce4ae4e8bd25058afd9848854a004126b536ed4c`다. 같은 버전·빌드 번호라도 hash로 구별한다. 최종 기능 시험에서는 열린 덮개·AC의 실제 수동 1분 시작·재요청 마감 보존·만료·무제한 시작·명시 종료와 자동 유지 지속, 기존 설정 보존을 확인했다. 물리 덮개·전원 분리 수집은 아직 시작하지 않았다. 배포·업데이트 시험은 사용자 결정대로 마지막에 진행한다. **사용자는 조작만 한다. 성공/실패·시각·로그 판정은 에이전트가 담당한다.**

## 준비

- [x] 관리자 인증을 거쳐 앱·도우미53 설치, 현재 실행 파일·빌드·응답을 확인했다. 실제 ON/OFF·수동1분 만료의7개 검사도 통과했다.
- [x] 최종 UI 교체 뒤 새 GUI hash·프로세스·도우미53 응답을 확인했다. UI 변경에서는 동일한 도우미·CLI·복구를 보존했다.
- [ ] 물리 시험 직전에 검증 후보와 설치 앱·도우미의 hash를 대조한다. 교체가 필요할 때 정상 종료·원복 후 진행한다. 새 관리자 인증이 필요하면 macOS 인증창에서만 처리한다.
- [ ] 에이전트가 실행 앱·도우미·전원 상태·원복 소유권과 수집 상태를 확인한 뒤 시작한다.
- [ ] 자동 유지 조건은 전원 연결, 덮개 유지 ON, 배터리 예외 OFF로 기본 시험을 준비한다. 사용하는 원격 앱·외장 화면/독은 에이전트가 관측한다.

최종 UI 적용 뒤 관측에서는 전체/자동 유지ON·AC 조건·덮개 지원ON·수동/배터리 예외OFF였다. 안전한 교체를 위한 자체 해제 뒤 이전 선택으로 다시 시작했다. 이 열린 덮개의 상태 확인은 실물 덮개 합격이 아니다. 물리 시험 직전에 에이전트가 다시 관측하고 새 로그 수집을 준비한다.

## 필수 조작

| 완료 | 조작 | 에이전트가 확인할 결과 |
|---|---|---|
| ☐ | 전원 연결 상태로 덮개 닫기 → 에이전트의 2분 관측 완료 안내 후 닫힌 채 전원 빼기 → 1분 대기 → 덮개 열기 | 닫힌 AC를 **120초 이상 연속 관측**, 분리 후 자체 해제, 실제 OS Sleep, 열림 Wake. 유효한 배터리 예외 없이 유지가 계속되지 않음 |
| ☐ | 덮개가 열린 상태로 전원 연결 → 전원 빼기 | 자체 AC 유지 종료, Tether가 강제 Sleep을 요청하지 않음 |
| ☐ | 배터리에서 수동 15분 선택 → 시작 → 덮개 닫기 → 20초 뒤 AC 연결 → 에이전트의 수동 만료 관측 안내 후 닫힌 채 전원 빼기 → 1분 뒤 열기 | 수동만 만료, AC 자동은 계속 유지, 최종 분리 때 만료 수동 부활 없이 실제 Sleep |
| ☐ | AC에서 수동 시간은 무제한, 분리 후 배터리 예외는 15분 선택 → 시작 → 닫기 → 전원 빼기 → 안내 때 다시 연결/분리 → 최초 기한 뒤 열기 | 유효한 예외에서만 유지, 전원 왕복으로 최초 배터리 기한이 늘어나지 않음, 만료 뒤 자체 해제·실제 Sleep |
| ☐ | 평소 쓰는 다른 기기에서 원격 인증 → 지정한 빈 시험 창에 문자 입력 → 재접속 → 연결된 채 첫 번째 분리 조작 반복 | 실제 화면/입력/재접속을 각각 확인. 원격 때문에 분리 종료나 기한이 바뀌지 않음 |

- [ ] 잠금·macOS 메뉴 잠자기·Tether 잠자기는 각각 별도 시험으로 기록한다. 원격 접속이 끊길 수 있는 실물 조작은 해당 시험을 시작할 때만 수행한다. 에이전트가 조작·로그 비교를 맡고 사용자는 필요한 로그인·깨우기만 한다.
- [ ] 후보 설치 후 실제 메뉴·설정의 픽셀·입력 확인. 시간 선택지는 15분·30분·1시간·2시간이며 전원 연결 중 수동 유지에만 무제한을 제공한다. 직접 입력창은 없다. 기존 설치본은 Computer Use 조회 -10005 시간 초과로 시각·마우스/키보드 미확인이었다. 공유 Scene·정적 렌더·Tab 포커스만으로 설치본 검사를 통과시키지 않는다. 후보별 자동 검사 근거는 [검증 체크리스트](VALIDATION-CHECKLIST.ko.md)에서 구별한다.

물리 수집기의 전체 `verdict=pass`만으로 위 항목을 한꺼번에 체크하지 않는다. 자동 분석은 AC 유지 또는 분리 중 한 조건만 통과해도 `pass`이며 `completeAcceptance=false`다. 각 `checks`와 연속 관측 시간을 따로 읽는다. 현재 분석기의 80초 최소 관측은 진단 기준이고, 이 체크리스트의 AC 합격 기준은 120초다. Sleep 명령 성공이나 표본 공백은 실제 Sleep이 아니다.

보호 시험은 실제 과열·가방 속 실행·배터리 소진 없이 모의 입력으로 검증한다.

## 사용하는 환경에서만 추가

- [ ] macOS 26 기기가 있으면 같은 기본·원격 시험과 설치 승인/취소·업데이트·실패 원복을 확인한다. 최신 OS에서의 통과만으로 최소 OS를 합격시키지 않는다.
- [ ] 외장 화면·독을 사용하면 그 연결 상태로 기본 분리 시험을 반복한다.
- [ ] 데스크톱 Mac을 사용하면 도우미 설치 없이 일반 유지/해제와 화면 절전이 동작하고 덮개·내장 배터리 옵션이 없는지 확인한다.
- [ ] 알림을 사용할 경우 OS 권한 요청에 응답한다. 허용/거부/집중 모드의 결과·실제 표시 판정은 에이전트가 한다. 알림 권한은 보호 동작의 조건이 아니다.
- [ ] 짧은 기본 시험을 통과한 뒤 전원 연결·통풍이 되는 환경에서 30~60분 평소 작업을 관측한다. 실제 화면·잠금·원격·전원 표본을 확인하며 과열을 유도하지 않는다. 2분 유지 통과를 장시간 안정성이나 기기 수명 보장으로 표시하지 않는다.

## 결과 뒤 결정할 것

- **덮개 backend:** 실제 분리 Sleep·자체 원복·macOS 메뉴 잠자기의 영향을 보고 현재 실행 수단을 채택한다. 전역 덮개 유지 중 native Sleep도 막힐 수 있다는 한계를 숨기지 않는다.
- **로그인·원격 조합:** 화면 꺼짐·잠금·원격 입력을 따로 관측한다. 앱은 자동 잠금 해제나 전역 암호 설정 변경을 하지 않는다. 해당 OS 정책에서 가능한 조합만 지원으로 표시한다.
- **일상 사용 승격:** 필수 조작, 설치·이관·원복을 통과한 결과로 결정한다. 자동 검사 개수나 성공한 Sleep 명령만으로 승격하지 않는다.

전체 기능 계약과 층별 근거는 [검증 체크리스트](VALIDATION-CHECKLIST.ko.md)에 보존한다. 미실시 조작과 확인 불가능한 관측은 미확인으로 남긴다.
