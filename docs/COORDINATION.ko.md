# Tether 2.2.0 빌드 29 — 최종안 적용

> 빌드 49 반영: 이 문서의 과거 조사·검증 기록 이후 확정된 현재 동작은 [최종 기능](FINAL-SCOPE.ko.md)과 [보호 기준](PROTECTION-EVIDENCE.ko.md)을 따른다.

> 현재 빌드 30은 [화면 연결·원인 판정](DISPLAY-DIAGNOSTICS.ko.md)을 추가했다. 아래는 빌드 29의 변경·검사 이력이다.

2026-09-28. 합의한 핵심 기능을 유지하면서 다른 전원 앱과의 공존, 종료·복구, 디스플레이 확인과 진단 UX를 구현했다. 소스·격리 실행·미리보기 검증 결과이며 관리자 설치·물리 전원 시험 완료를 뜻하지 않는다.

## 실제 동작

| 상황 | 빌드 29 동작 |
|---|---|
| AC·외장 화면 없음 | 조건에 맞으면 유지. 열린 덮개는 ‘닫아도 유지 준비’, 닫힌 덮개는 ‘덮개를 닫고 유지 중’ |
| AC·외부 화면 관측 | Tether 추가 유지·전체 디스플레이 절전은 해제하고 macOS에 맡김. 주변기기 승인·실제 기본 클램쉘 성공은 OS/실기기 사항 |
| 전원 연결/분리 순서 | 최종 공급원·덮개·타이머 조건으로 판단. 이미 잠든 기기를 강제 깨우지 않음 |
| 배터리만·둘 다 | 기존 제한 시간 유지. 취소·만료 후 조건이 그대로면 자동 재시작하지 않음 |
| 순간 AC·미확인 전원 | 기존 예산 보존. 30초 이상 연속 AC 관측 뒤에만 예산과 다음 자동 진입을 준비 |
| 화면 절전 | 덮개 세션당 최대 3회, 최소 10초 간격으로 화면 끄기를 요청. 일시적 재점등은 회복을 기다리며, 지속 충돌·10초 연속 관측 불가는 보호 중지 |
| 외부 앱이 전역 값을 변경 | 반복 재적용 중단. 기존 다른 주체의 값은 인수·해제하지 않음 |
| 앱 종료 | 현재 유지·예약을 끝내고 응답을 확인한 뒤 종료. 저장된 스위치·전원 조건은 보존 |
| GUI crash·로그아웃 | PID 종료 및 시작 시각 재확인으로 연결 수명 종료. 타이머·예약 소비, Tether 변경 해제 |
| 정상 잠자기 | 프로세스가 살아 있으면 UI 응답 공백을 crash로 판단하지 않음. sleep 이벤트는 소유한 override를 해제 |
| 손상 설정·저장 실패 | 유지 차단, 원본 보존 및 오류 표시. 종료 정리에서 저장 실패가 후속 평가에 가려지지 않음 |
| 업데이트·제거 | 현재 부팅의 Tether 변경만 복구. 제거 시 도우미 종료 확인, 저전력 복원 미완료 시 파일 보존 |

30초·10초·2초 CPU 표본은 제품의 초기 공학적 설정이다. USB-C 독의 실측 전환 한계, 제조사 안전 온도 또는 배터리 수명 보증이 아니다. 기존 보조 온도·잔량·시간 한도는 완화하지 않았다.

## 충돌·부하 점검과 디자인

클램쉘 / 배터리·과열 보호 / 시스템·진단의 3개 화면을 유지한다. 보호와 시스템 화면에서 ‘앱 충돌·부하 점검’을 열고, 충돌 중에는 클램쉘 화면에도 바로가기를 보여준다.

점검 화면은 현재 전원·발열·잔량, 실제 절전 방지 요청, 최근 CPU 사용, 실행 중인 전원 앱을 구분한다. CPU는 화면을 열거나 재점검할 때만 약 2초 표본을 읽어 상위 5개를 보여준다. 100%는 논리 CPU 하나이며 에너지·온도 인과관계가 아니다. 읽기 실패·일부 프로세스 누락·측정 시각을 표시한다. kernel_task는 열 대응일 수 있음을 안내한다.

앱 이름만으로 충돌로 판정하지 않는다. 현재 화면 절전 의도에 반대되는 요청만 상충으로 표시한다. ‘앱 열기’, ‘활동 모니터’, ‘Tether 중지’, ‘다시 점검’을 제공하며 자동 강제 종료·타 앱 설정 편집·프로세스 인수 수집·목록 저장/전송은 하지 않는다. 앱을 열기 전에 PID와 시작 시각을 다시 확인한다.

상태 문구와 심벌로 준비·유지·OS 위임·보호·충돌을 구분한다. 앱 아이콘·작은 메뉴바 아이콘의 기존 단순화 방향을 유지하고 밝은/어두운 화면, 한국어/영어, 최소 창 너비의 배치를 검사한다. 저장 이미지의 전원·앱·CPU 값은 미리보기 자료다.

## 아키텍처

- `PowerOwnership`: 적용 전에 내구성 있게 기록하고 해제 후 기록을 소비한다. 현재 부팅 기록만 유효하다. 실제 global 값은 적용 후 다시 읽는다.
- `DisplaySleepGate`: 제한된 요청 횟수·회복·관측 불가·실패 상태. `StablePowerGate`: 연속 전원 관측과 예산 갱신.
- `Helper+Ownership`: 직렬 OS 적용, 외부 변경 보류, 앱 프로세스 수명, 복구. 소켓은 UID 및 커널 제공 PID를 검증한다. 요청 JSON의 PID는 신뢰하지 않는다.
- `PowerActivityInspector`와 `ProcessCPUProbe`: UI 밖에서 비관리자로 짧은 조사. 관리자 도우미에는 앱 강제 종료 같은 기능을 넣지 않는다.
- protocol 2/schema 2에 선택 필드를 추가했다. 앱과 도우미는 빌드까지 맞춰야 정상 제어한다.

전역 SleepDisabled에는 배타적 소유권 API가 없다. Tether와 다른 앱이 같은 값을 설정한 상황을 완벽히 분리할 수 없다. 기록은 충돌·복구를 개선하는 근거이며 완전한 잠금이 아니다. 공개 화면 목록도 물리 외장·가상/간접 화면을 확정하지 못해 ‘유형 미확인’을 유지한다. 조회 실패는 별도의 unknown으로 취급한다.

## 남은 실기기 합격 조건

1. 관리자 도우미 설치와 구버전 앱 → Sparkle 재시작 → 도우미 교체 → 사용자 설정 재조회 전체 경로.
2. 두 케이블·덮개 순서에서 실제 sleep 로그와 전원 공급원 시각 대응. SleepDisabled=false만으로 합격하지 않음.
3. 실제 내장 패널 절전·덮개 열기 복귀, AC 외장 모니터와 입력 장치, 독·KVM·DisplayLink·가상 화면 전환.
4. Splashtop 등 원격 앱별 패널 절전·연결 유지의 양립 여부. 무제한 화면 끄기는 방지하지만 원격 무중단을 보장하지 않음.
5. 모델별 센서 검증과 평상시 CPU·wakeups·배터리 비용 장기 측정. 높은 온도를 일부러 유발하는 시험은 수행하지 않음.
6. 공개 배포 전 Developer ID 서명·공증, 공개 feed/릴리스 URL 배포. 현재 앱은 ad-hoc 개발판이고 Ed25519 업데이트 서명은 별도 검증됨.
