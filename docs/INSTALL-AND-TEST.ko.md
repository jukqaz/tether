# Tether 설치·실물 시험

Apple Silicon과 macOS 26 이상이 필요합니다. [GitHub 릴리스](https://github.com/jukqaz/tether/releases)에서 버전, ZIP, SHA256을 확인하세요. 시험 전에는 실제 설치된 앱과 도우미 빌드를 확인합니다. 검증 범위와 직접 조작은 [검증 체크리스트](VALIDATION-CHECKLIST.ko.md)와 [물리 확인](END-RECOVERY-PHYSICAL.ko.md)에 있습니다.

## 현재 후보의 시작 준비

1. 검증된 `Tether.app`을 응용 프로그램 폴더에 둡니다. 실제 시험 전에 실행 앱과 도우미 빌드를 확인합니다.
2. MacBook에서 덮개 유지가 필요하면 덮개를 열고 시작 화면에서 **덮개 닫고 사용 허용 → 준비…**를 선택합니다. 관리자 인증은 macOS 창에서 완료합니다. 도우미 응답이 확인되면 선택을 저장합니다.
3. 일반 유지나 데스크톱 Mac에서는 도우미 준비 없이 시작할 수 있습니다.
4. 자동 유지와 덮개 허용을 각각 선택합니다. 설치 후에는 **설정 → 전원·덮개**에서 변경합니다.
5. 원격 사용에는 화면 절전·잠금·실제 수면을 구별합니다. Tether는 OS 암호 요구를 읽어 설정으로 안내하며 자동 잠금 해제를 하지 않습니다. 조작 결과는 로그와 실제 원격 프레임·입력으로 판정합니다.

일반 절전 방지는 앱이 처리하고, 도우미는 승인된 덮개 요청을 처리합니다. 로그·보고서는 **설정 → 보호·진단 → 로그와 보고서**에 있습니다.

## 이전 빌드 49 기록

아래는 **2026.9.1 Beta 7·빌드 49** 배포·시험 절차를 보존한 기록입니다. 현재 후보의 메뉴·설정 계약은 위 절차와 [기능 정의](PRODUCT-SPEC.ko.md)를 따릅니다. 이전 49의 확인 결과를 현재57의 설치·실물 통과로 재사용하지 않습니다.

이 베타는 ad-hoc 서명이며 Developer ID 서명·Apple 공증이 없습니다. 체크섬과 Sparkle 서명은 파일 무결성을 확인하지만 Apple 공증을 대신하지 않습니다. 회사의 관리 정책이 실행·도우미 설치를 금지하면 IT 승인 또는 공증된 버전이 필요합니다.

## 1. 내려받기

빌드 49는 로컬에서 빌드·검증한 사설 배포용 후보입니다. 이 문서 갱신으로 GitHub에 새 버전이 게시되는 것은 아닙니다. [GitHub 릴리스](https://github.com/jukqaz/tether/releases)에 해당 빌드를 게시한 뒤 배포 파일과 체크섬을 함께 받습니다. 아래 파일명은 배포 시 사용할 형식입니다.

- `Tether-2026.9.1-beta.7-arm64.zip`: 실제 전원 제어 앱. Preview가 아닙니다.
- `Tether-2026.9.1-beta.7-arm64.zip.sha256`: 다운로드 무결성 확인용.
- `release-manifest.json`: 소스 커밋·빌드·검증 범위·서명 상태.

선택적으로 두 파일이 있는 폴더에서 확인합니다.

```sh
shasum -a 256 -c Tether-2026.9.1-beta.7-arm64.zip.sha256
```

`OK`는 다운로드가 배포 파일과 같다는 뜻이며 설치·실기기 동작 성공을 뜻하지는 않습니다.

## 2. 처음 설치하기

1. ZIP을 열어 `Tether.app`을 **응용 프로그램** 폴더에 옮깁니다. 다운로드 폴더에서 도우미를 설치하지 않습니다.
2. `Tether.app`을 실행합니다. macOS가 개발자 확인 경고로 차단하면 **시스템 설정 → 개인정보 보호 및 보안**에서 이 앱에 대한 **확인 없이 열기** 허용 여부를 확인합니다. 회사 정책상 허용되지 않거나 악성 코드 경고라면 진행하지 않습니다. [Apple 공식 안내](https://support.apple.com/ko-kr/102445).
3. **도우미 설치…**를 누르고 시스템 관리자 인증창에서 인증합니다. 암호는 Tether에 저장하지 않습니다.
4. **앱 설정 → 문제 해결 → 전원 관리 도우미**에서 앱과 도우미가 **2026.9.1 (49)**이고 연결됐는지 확인합니다. 단순히 설치 파일이 있다는 표시와 구분합니다.
5. **앱 설정 → 문제 해결**의 시스템 점검에서 오류를 확인합니다. 감시 장치의 첫 점검 완료는 잠시 뒤 반영될 수 있습니다.
6. 첫 시험은 덮개를 연 채 **전원 연결 중만** 조건으로 시작합니다. 다른 전원 앱에서 전역 클램쉘 기능을 동시에 켜지 않습니다. LLM 앱의 일반 작업 유지 요청은 상태 점검에서 별도로 관찰할 수 있습니다.

정식 공증 없는 빌드라서 모든 회사 관리 환경에서 실행된다고 보장할 수 없습니다. 보안 기능을 전역으로 끄거나 quarantine 속성을 지우는 설치 스크립트는 제공하지 않습니다.

## 3. 이전 Tether에서 교체하기

1. 기존 앱의 전원 조건·보호 설정을 기록하고 **유지 중지하고 종료**합니다. 기존 2.0.x에서 메뉴 이름이 다르면 먼저 끄고 종료합니다.
2. 새 `Tether.app`으로 응용 프로그램 폴더의 기존 앱을 교체합니다. **완전히 제거**는 설정·로그를 삭제하므로 업데이트 전에 사용하지 않습니다.
3. 새 앱을 열고 도우미 갱신을 인증합니다. 취소했다면 **앱 설정 → 문제 해결 → 전원 관리 도우미 → 업데이트 마무리…**에서 다시 진행합니다.
4. 앱/도우미 빌드 일치와 기존 선택이 유지됐는지 확인합니다. 보호 중지나 비활성 선택을 자동으로 켜지 않는 것이 정상입니다.

설정 형식 3으로 이관하기 전에 원본 바이트를 별도 백업하고 전원 조건·잔량·시간·앱 기본 설정을 보존합니다. 이전 온도 제한이나 자동 온도 기준을 사용했다면 한 번 중지하고 새 OS 발열 기준을 확인한 뒤 직접 재개합니다. 진행 중이거나 예약된 임시 타이머는 되살리지 않습니다. 도우미 설치 실패 시 이전 파일 복구를 시도합니다. 손상되거나 더 새로운 설정 형식이면 기본값으로 덮어쓰지 않습니다. [상세 계약](UPDATES-AND-MIGRATION.ko.md).

새 앱은 고정 서명 피드에서 선택한 채널의 다음 빌드를 받습니다. 정식 채널은 베타를 제외하고, 정식 + 베타 채널은 둘 다 확인합니다. 공개 2.0.x에서 새 업데이터로의 첫 교체만 수동 설치가 필요합니다. 새 빌드의 온라인 제공 여부는 실제 피드 게시 상태에 달려 있습니다. 합성 업데이트 시험 통과만으로 공개 피드 게시를 확인했다고 하지 않습니다.

## 4. 재현 기록 켜기

**앱 설정 → 문제 해결 → 진단과 보고서**에서 상세 기록 15분을 시작합니다. 시험 후 **최근 1시간 → 보고서 저장…**으로 저장합니다. 로그를 분석하는 세션에서는 사용자가 조작만 수행하고, 전환 시각과 정상/실패는 전원·덮개·도우미·macOS Sleep/Wake 로그를 대조해 판정합니다. 별도 시각 메모나 문제 시점 표시가 필수는 아닙니다. 기록은 자동으로 외부 전송되지 않습니다.

전원 요청의 앱 이름은 기본 제외입니다. 필요할 때만 포함하고 회사 앱 이름·작업 정보가 들어 있는지 확인한 후 공유하세요. 원격 화면 연결은 화면 절전에 영향을 줄 수 있으므로 연결 상태와 실제 전원 요청을 함께 수집합니다.

## 5. 실기기 시험 순서

작업을 저장하고, 통풍되는 책상 위에서 진행합니다. 고온을 일부러 만들거나 팬을 막는 시험은 하지 않습니다. 물리 관측이 불가능하면 미확인으로 남깁니다.

| 시험 | 사용자 조작 | 로그로 판정할 결과 |
|---|---|---|
| 기본 끄기 | 덮개를 연 채 Tether 끄기, 케이블 재연결 | 계속 꺼짐. 다른 앱의 절전 요청은 그대로 |
| 전원 → 덮개 | 외장 화면 없이 전원 연결, Tether 켜기, 덮개 닫기 | 작업 유지와 내장 화면 절전. 이후 전원 분리 시 유지 해제·잠자기 요청 |
| 덮개 → 전원 | 배터리에서 짧은 수동 유지로 깨어 있는 상태를 만든 뒤 덮개 닫기, 전원 연결, 수동 타이머 종료 | 전원 조건으로 유지. 다시 전원 분리하면 해제 |
| 이미 잠든 상태 | 기본 조건에서 배터리로 덮개를 닫아 실제 잠든 뒤 전원 연결 | 케이블 연결만으로 강제 깨우지 않는 것이 정상. 필요하면 직접 깨우기 |
| 다시 열기 | 닫힌 유지 상태에서 덮개 열기 | 화면과 입력 정상 복귀, 이전 자동 잠자기 재시도로 다시 잠들지 않음 |
| macOS 기본 클램쉘 | 전원·외장 모니터·입력 장치 연결 후 덮개 닫기 | macOS 관리 표시. Tether의 일반 끄기/타이머 취소가 외장 작업을 중단하지 않음 |
| 배터리 조건 | 배터리 사용 중만 선택, 전원 연결/분리 | AC에서 비활성, 배터리에서 제한 시간 유지 |
| 타이머 만료 | 안전한 배터리 잔량에서 직접 입력 1분, 배터리에서 덮개 닫기 | 만료 후 유지 해제. 반복 연장·재시작으로 공통 한도를 초기화하지 않음 |
| 타 앱 공존 | LLM 작업 유지 또는 기존 전원 앱을 켜고 화면·앱 상태 점검 | 작업 유지와 화면 켜짐을 구별. 타 앱 요청을 Tether가 삭제하지 않음 |
| 설정 지속 | 조건·시간 선택 후 앱 종료/재실행 | 설정 보존, 끝난 임시 타이머 자동 부활 없음 |

**명령 성공, ‘잠자기 요청’, `SleepDisabled=false`만으로 실제 잠자기 완료라고 판정하지 않습니다.** 실제 OS Sleep/Wake 기록과 연속 표본을 대조합니다. OS 화면 꺼짐 관측은 패널 전력 0의 측정값이 아닙니다. 외장 화면·가상 화면·독·원격 연결 여부를 함께 관찰해야 원인을 비교할 수 있습니다.

과열·필수 상태 누락·충돌·고장 복구 경계는 자동 시뮬레이션으로 검사했습니다. 발열 보호는 공개 macOS thermalState의 심각/위험 상태를 사용하고, 선택적 배터리 온도 센서 미지원만으로 차단하지 않습니다. 실제 닫힘·전원 순서, 모든 독과 앱 조합, 장시간 소비전력은 빌드 49에서 아직 미검증입니다. [현재 기능과 검증 범위](FINAL-SCOPE.ko.md).

## 6. 문제가 생기면

덮개를 열고 Tether를 끈 뒤 보고서를 저장합니다. **유지 중지하고 종료**는 현재 유지·예약을 끝내되 설정을 보존합니다. 설정 창만 닫으면 앱은 계속 실행됩니다.

시험을 마치고 제거하려면 **앱 설정 → 문제 해결 → 고급 관리 → Tether 완전히 제거…**를 사용합니다. 설정과 로그도 삭제되므로 먼저 보고서를 보관하세요. 도우미만 제거하는 선택도 있습니다. 전원 설정 복원이 실패하면 제거기는 복구 기록을 보존하며 실패를 알립니다.

2.0.x 앱만 덮어쓰는 다운그레이드는 새 설정 형식을 이해하지 못할 수 있어 권장하지 않습니다. 구버전 복귀가 필요하면 보고서를 보관하고 현재 앱에서 정상 제거한 뒤 구버전을 새로 설치합니다.
