# macOS 기본 클램쉘 위임 — 2026-10-01

빌드 50 개발 후보에 실제 관측 경로를 추가했다. 종전 `nativeDisplayVerified`는 가짜 시험 입력에서만 설정되어 실제 도우미는 기본 클램쉘 위임을 선택할 수 없었다. 이제 현재 화면·연결 경로·자체 전역 설정 해제·macOS 덮개 절전 정책을 대조한다. 일반 작업 assertion, 공통 세션 ID와 타이머는 이 전환에서 종료하거나 다시 만들지 않는다.

`nativeDisplayVerified`라는 기존 내부 이름은 **현재 OS 정책을 관측해 위임했다는 뜻**이다. 물리 덮개 유지, 패널 전력 0, Sleep/Wake 완료 또는 장시간 안정성을 입증하는 이름으로 해석하지 않는다.

## 연결 근거

`DisplayProbe.inspect()`가 보고한 유선 HDMI/DisplayPort/DVI/VGA/Thunderbolt 연결과 현재 CoreGraphics의 화면 ID·vendor·model을 정확히 대조한다. USB/DisplayLink, AirPlay/Sidecar, 알려진 가상 화면, 이름만 일치한 화면, 읽지 못한 연결은 기본 클램쉘 근거로 사용하지 않는다. 혼합 구성에서도 현재 일치한 유선 출력이 있어야 한다.

프로파일 조회는 도우미 주 큐 밖에서 한 번에 하나씩 수행한다. 원래의 4초 조회 제한을 사용한다. 전원·발열·유한 작업 임대 처리는 계속 진행한다. 화면 구성이나 wake 이후의 오래된 결과는 generation으로 폐기한다. 현재 외장 식별값이 같으면 실패한 상세 조회를 매 타이머마다 재실행하지 않는다. 내장 패널의 온라인 목록 이탈은 외장 화면 교체로 간주하지 않는다. serial·EDID는 이 캐시에 보관하지 않는다.

## 전환 계약

| 현재 조건 | 처리 |
|---|---|
| AC·Full Wake·유선 연결 일치·SleepDisabled=0·AppleClamshellCausesSleep=false | 관측된 OS 덮개 정책에 맡기고 Tether의 일반 작업 유지 계속 |
| 같은 OS 정책이 관측되고 상세 조회 진행 중, 자체 전역 유지 없음 | 조회 동안 신규 전역 설정 적용을 보류. 조회 완료 뒤 확인하거나 기존 정책으로 복귀 |
| Tether 소유 유지 있음·유선 후보·덮개 열림·작업 유효 | 작성자/복구 잠금 안에서 상태를 다시 읽고 자체 유지 해제. 실제 해제와 OS 덮개 정책 확인 |
| 자체 해제 명령 실패 또는 설정 효과 없음 | 소유권·복구 근거·공통 작업 보존. 위임 완료로 표시하지 않음 |
| 자체 해제 후 OS 정책이 덮개 잠자기 허용 또는 조회 불가 | 같은 유효 작업의 자체 덮개 유지 복구. 타이머 tick으로 시험 해제를 반복하지 않음 |
| 이미 닫힌 덮개에서 Tether 소유 유지 중 | 외장 화면 연결만으로 시험 해제하지 않음. 다음 열림에서 위임을 준비 |
| 기본 위임 뒤 가상 화면만 남음 | 현재 작업의 덮개 지원 복구. 일반 요청·시간 제한은 그대로 적용 |
| 다른 앱의 SleepDisabled=1 | 위임 근거로 사용하거나 소유·해제하지 않음 |
| 배터리·조건 해제·유한 임대 만료·보호·사용자 잠자기 | 기존 공통 정책 적용. 위임이 새로운 유지 사유나 예산을 만들지 않음 |

뒤늦은 자동 닫힘 잠자기 재시도는 위임 시 무효화한다. 사용자 또는 보호가 요청한 잠자기는 별도 의도를 유지한다. 화면 전체 끄기, 로그인 잠금 설정, 다른 앱의 프로세스나 요청을 수정하지 않는다. 선택적 상태 필드로 앱에 위임 관측을 전달하며 이전 상태 파일에서 필드가 없으면 위임으로 표시하지 않는다.

## 출처와 한계

Apple의 [M3 듀얼 모니터 안내](https://support.apple.com/en-sg/117373)는 전원과 외장 입력 장치를 포함한 구성을 명시한다. [Apple Silicon 액세서리 승인 안내](https://support.apple.com/en-vn/102282)는 충전과 데이터 연결 승인이 별개임을 설명한다. Tether가 전원 연결만으로 해당 구성·승인을 충족했다고 주장하지 않으며 액세서리 보안 설정을 바꾸지 않는다.

[Apple의 공개 xnu 전원 코드](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/iokit/Kernel/IOPMrootDomain.cpp)의 `shouldSleepOnClamshellClosed`와 `sendClientClamshellNotification`을 참고했다. 덮개 절전 결과에는 desktop/AC 상태 외에도 여러 차단 조건이 관여한다. 따라서 `AppleClamshellCausesSleep=false` 단독을 물리 클램쉘 증거로 쓰지 않고, 현재 연결과 자체 SleepDisabled 해제도 함께 확인한다. 이 값으로 다른 앱의 모든 전역 변경 작성자를 식별할 수는 없다. 특정 Mac/macOS가 이 관측을 제공하지 않으면 현재 작업의 덮개 지원을 유지하는 경로를 사용한다. 외부 소스 코드는 복사하지 않았다.

열린 덮개 재확인 이후에도 사용자가 즉시 닫는 물리 경쟁은 소프트웨어 검사만으로 없앨 수 없다. 실제 macOS의 설정 전파 지연, 승인된 주변기기, 잠금/원격 입출력, 실제 Sleep/Wake, macOS 15 및 모델별 동작은 실기기 확인이 필요하다. 닫힌 상태에서 새 외장 화면을 연결했을 때 기존 자체 유지의 안전한 위임은 다음 열림으로 제한한다.

## 검증

최종 전체 Swift **568개**가 실패 0·skip 0으로 통과했다(Core 479 + App/Update 89). 실제 비관리자 IOKit 요청 시험 7개가 이 합계에 포함된다. 새 Core 회귀 12개는 정확한 연결 대조·OS 정책·소유권·Dark Wake·비동기 결과 폐기·조회 실패 반복 방지를 다룬다. 새 앱 회귀는 기본 위임·가상 화면 복귀·구버전 필드 부재에서 같은 일반 세션과 마감이 유지되는지 확인한다.

`scripts/test-native-handoff.py`는 실제 도우미 프로세스와 Unix IPC를 사용하는 12개 격리 시험이다. 화면/OS 정책과 전원 쓰기는 가짜 입력·dry-run이며 **물리 클램쉘 통과가 아니다**. 기존 공통 작업·원격 화면 회귀도 다시 실행한다. CI에 세 스크립트를 연결했다. 번들 검사 및 최종 실행 결과는 해당 작업의 로컬 결과 보고서에 남긴다.

설치된 앱은 빌드 49다. 이 변경은 미설치 빌드 50 후보이며, 실제 관리자 도우미 실행·새 릴리스·전체 업데이트 완료를 뜻하지 않는다.
