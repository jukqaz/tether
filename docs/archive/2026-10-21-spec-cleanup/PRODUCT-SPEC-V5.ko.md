# Tether V5 제품 기능명세

2026-10-21 · **P0 전원 분리·종료·복구를 로컬 후보에 구현하고 자동 검증 범위를 완료했다.** 앞선 명세·문구·검증표의 문서 전용 통일 작업은 완료했으며, 이후 전원 분리·종료·복구를 우선해 실행 경로를 연결하는 단계로 넘어왔다. 현재 근거와 남은 항목은 [P0 구현·검증 결과](../../../../../outputs/tether-p0-implementation-20261021/RESULT.ko.md)에서 구분한다. 설치·물리 인수는 미실시이며 V5 전체 구현·완료를 뜻하지 않는다. 실행 중 웹 시안의 배포 상태도 이 작업으로 변경하지 않는다.

## 최신 표시·선택 보완 · 심플 + 안정성

2026-10-21 사용자 요청에 따른 **명세 보완**이다. 아래의 밝기 선택과 쉬운 용어는 앱에 아직 적용하지 않았다. 기존 전원 분리·보호·종료 계약과 승인된 고급 선택을 바꾸지 않으며, 과거 확장 기능을 다시 개발 범위에 넣는 근거가 아니다. 화면 표현은 이 절과 [표시 문구](COPY-V5.ko.md)의 최신 용어를 우선한다.

### 덮개와 내장 화면

- 주 스위치: **덮개를 닫아도 계속 사용**. 기존과 같이 유효한 잠자기 방지 작업과 도우미 준비가 필요하며, 이 스위치나 덮개 닫힘만으로 작업을 새로 시작하지 않는다.
- 하위 선택: **덮개를 닫으면 내장 화면을**. 주 스위치가 꺼져 있으면 세부 선택은 접어 보존하며 실행하지 않는다. 다음 세 가지 중 하나만 적용한다.

| 선택 문구 | 의미 | 제공 조건 |
|---|---|---|
| **화면 끄기** · 기본 | 내장 화면의 절전 처리를 요청한다. 밝기 0과 다른 동작이다 | 화면 제어 지원과 적용 여부를 확인. 요청 성공만으로 패널 전력 0을 표시하지 않음 |
| **밝기 0으로 유지** | 화면을 끄는 요청 대신 내장 화면 밝기를 0으로 낮춘다. 원격 화면이 필요한 경우 시험할 수 있는 선택이다 | 원래 밝기 읽기·변경·재조회·원복과 해당 기기/OS 지원을 확인한 뒤 제공. 실제 화면 전원·원격 프레임·잠금은 별도 검증 |
| **변경하지 않기** | Tether가 내장 화면의 밝기나 절전 상태를 별도로 바꾸지 않는다 | macOS·다른 앱의 화면 처리는 계속 적용됨 |

- 기존 **화면 켜두기**는 **덮개가 열려 있을 때 화면 켜두기**로 범위를 명시한다. 닫힌 동안 내장 화면은 위 선택을 따르며, 둘을 독립 실행해 서로 덮어쓰지 않는다. 외장 화면은 이 선택으로 변경하지 않는다. 필수 화면 요구와 충돌하면 기존 K08/N28의 적용 보류 기준을 지킨다.
- 밝기 제어는 유효한 덮개 유지 작업이 실행 중일 때만 적용한다. 내장 화면·닫힘·제어 지원을 확인하지 못하면 새 밝기 변경을 하지 않는다. 지원하지 않는 데스크톱에는 덮개 옵션을 노출하지 않는다.
- 원래 밝기를 읽지 못하면 0으로 낮추지 않는다. 덮개 열림·마지막 덮개 작업 종료·전원 분리로 작업 종료·보호 중지·정상 앱 종료 시 자체 변경만 원복한다. 계속 유지하도록 선택한 분리 정책에서는 전원 분리만으로 별도 밝기 세션을 새로 만들거나 원본을 덮어쓰지 않는다.
- 강제 종료·재실행 뒤에도 복구할 수 있도록 원본과 변경 대상을 지속 기록하는 설계를 요구한다. 사용자가 다른 밝기로 바꾸면 반복해서 0으로 강제하거나 종료 시 과거 값으로 덮어쓰지 않는다. 밝기 변경 실패·재조회 실패는 적용 완료로 표시하지 않는다.
- 밝기 0 미지원·실패 시 **밝기 0을 적용하지 못했어요**와 이유를 표시한다. 화면 끄기 등 다른 선택으로 몰래 전환하지 않으며, 무관한 일반 잠자기 방지를 종료하지 않는다. 실제 원복이 미확인이면 복구 진입을 남긴다.
- 화면 꺼짐·밝기 0·OS 잠금·잠자기·원격 연결은 서로 다르다. **잠금 방지·자동 잠금 해제·원격 연결 보장** 문구로 바꾸지 않는다.

### 다른 앱의 잠자기 방지 요청

- 설치된 앱 이름 목록 대신 **현재 관측한 절전 방지 요청**을 표시한다. 설치/실행만으로 충돌이라고 표시하거나 요청이 실제 Sleep 실패 원인이라고 단정하지 않는다.
- 평소에는 **잠자기를 막는 다른 앱**을 접어 둔다. Tether 중지 후에도 다른 요청이 관측되면 `다른 앱의 잠자기 방지 요청 2개`처럼 요약과 상세 진입을 제공한다. 모든 앱에 경고색을 쓰거나 반복 알림을 보내지 않는다.
- 상세는 확인 가능한 앱/프로세스 이름, **컴퓨터 잠자기 방지 / 화면 꺼짐 방지** 구분, 확인 시각, `앱 열기`를 제공한다. 앱 연결이 불확실하면 프로세스로 표시하고 열기 버튼을 제공하지 않는다. 확인 가능한 설치 위치만 상세에서 연결한다.
- 목록 조회 실패는 `다른 앱의 요청을 확인하지 못했어요`로 표시한다. 조회 실패를 요청 0개로 바꾸지 않는다. 다른 앱 종료·제거·요청 해제는 자동으로 수행하지 않는다.
- 기본 메뉴에는 전체 목록·상세 PID·원격 접속 배지를 상시 표시하지 않는다. 다른 앱 요청과 Tether의 적용/해제 결과는 구분한다.

근거: [Keepresso 덮개 도움말](https://keepresso.com/help/keep-macbook-awake-lid-closed), 로컬 참고 코드 `DisplayPolicy.swift`, `ClosedDisplay.swift`, `BrightnessBackend.swift`. 도움말의 설명은 Tether의 지원/동작 인수 근거가 아니며, 비공개 밝기 API 사용 여부와 기기별 지원·복구를 별도로 검증해야 한다. 연결 검증은 [추가 체크리스트](V5-VALIDATION-CHECKLIST.ko.md)의 SIMPLE-D01~D08을 따른다.

### 적용 순서와 사건의 정의

- 요청/부팅/사용자·실행 소유 유효성 → 확인된 보호·사용자 모두중지/명시Sleep → 확인된 전원 정책 → 마감/lease 만료 → 새 명시 요청 → 자동 규칙 순이다. 먼저 들어온 UI 명령이 높은 우선순위의 종료를 뒤집지 못한다.
- **실제 사건**은 같은 부팅·사용자와 해당 원인 계보에서 확인한 새 전이이며 캐시 재전달·startup 초기값·프로브 재조회·heartbeat·GUI 재실행이 아니다. AC→unknown→AC는 새 연결이 아니며 AC→unknown→배터리는 확정 분리1회다.
- 명시Sleep 차단 뒤에는 그 차단 이후 확인한 새 AC전이 또는 false→true만 새 자동 평가 근거다. 모두중지는 이런 사건으로도 해제되지 않는다. 보호/복구 차단도 먼저 해소해야 한다.
- **자동 활성사건**은 해당 규칙의 확인된 새 false→true·선택한 새 실제 전원 사건 또는 사용자의 명시 새 시작/재개로 생성하는 실행 단위다. K01의 분리 정책과 보호/모두중지 등 선행 제한을 먼저 적용한다. 일반 fullWake·자동 보호 회복·새 요청ID·캐시·GUI 재연결은 새 활성사건이 아니므로 최초 배터리 기준/상한을 초기화하지 않는다. 분리 정책/배터리 상한으로 종료한 자동의 재시작 차단도 Wake만으로 해제하지 않는다. 분리 사건 자체로 새 시작이 가능한 예외는 §3의 ‘작업별 전원 설정에 맞춰 계속’과 배터리 자동의 분리 시작 사건을 모두 명시 선택한 경우뿐이며, 기본/자동만 종료 정책에는 적용하지 않는다.
- **일반 OS Sleep**은 기존 수동·연결 작업을 소비한다. 출처가 확인된 Tether 명시Sleep/모두중지·보호·복구·분리/상한 종료 차단이 없을 때만 정상 fullWake와 선택한 자동 규칙의 전원 범위(기본AC)·신선한 조건·유한 예산·실행 소유·해당 GUI/서비스의 새 자동 시작 허가를 만족할 때 새 자동을 평가한다. 배터리 자동은 사용자가 명시 선택한 경우에만 허용하며, 같은 자동 활성사건이면 새ID에도 최초 배터리 기준/상한을 보존하고 원상한이 만료됐으면 시작하지 않는다. DarkWake·관측 공백·표본 재생은 fullWake가 아니다. macOS 메뉴/타사 Sleep의 사용자 의도를 항상 식별한다고 보장하지 않는다. 지속 중지의 확실한 조작은 Tether의 모두 중지 또는 Tether 잠자기다.
- 전원 공백 중에도 실행 소유자의 신선한 확정 공급원, 확인된 serious/critical, 이미 지난 마감은 즉시 반영한다. GUI만 unknown인 것을 이유로 도우미가 이미 확인한 분리를 미루지 않는다.
- K03의 필수 실행 표본은 전원·열·소유/허가 관측이다. 선택 조건 제공자의 unknown은 해당 규칙을 참으로 만들지 않으며, 화면/선택 모듈 관측 실패만으로 무관한 정상 일반 작업을 모두 종료하지 않는다. 관련 표본의 마지막 정상시각+15초는 **의도적으로 새 허가를 주지 않을 상한**이다. 실제 전역 전원 변경의 원복 성공이나 물리 Sleep이15초 내 보장된다는 뜻이 아니다. 원복 실패는 실패 상태/저널/독립 복구로 추적한다.

### 시간·회복·종료의 경계

- 요청 마감·배터리 상한·허가 TTL은 서로 다른 기한이다. 배터리로 승인된 허가가 unknown이 되었다고 배터리 상한을 제거하지 않는다. 전원 연결/분리는 원마감을 자동 교체하지 않는다. 고급 무제한도 보호·분리·소유권·유한 건강성 허가를 우회하지 못한다.
- 예: 배터리 시작90분 요청이 AC로 옮겨진 뒤 사용자가60분 연장하면 수동 마감은150분이다. AC에서120분이 지났다는 이유만으로 배터리 상한 종료를 만들지 않는다. 계속 정책을 명시 선택했더라도122분에 배터리로 돌아오면 원120분 상한을 넘었으므로 즉시 종료한다. 기본 분리 전체 종료는 이보다 먼저 기존 요청을 끝낸다.
- 기본 잔량 하한20%면 회복은25% 이상 연속60초다. 데스크톱에는 존재하지 않는 배터리 조건을 요구하지 않는다. 선택한 저전력 중단 조건도 해소되어야 한다. 보호가 풀려도 끝난 수동·명령은 자동 재실행하지 않는다.
- 종료 정리기한은 원인 사건 시각+60초, 행동기한은 정리·최종 검사 뒤 발급시각+15초다. 정확히 기한에 도달하면 만료다. 실패한 원복을 늦게 확인하는 것은 허용하되 끝난 행동 권한은 만들지 않는다.
- 덮개 열림이 취소하는 것은 **닫힘을 조건으로 한 분리·만료·보호Sleep**이다. 사용자가 명시한 Sleep는 열린 Mac에서도 유효할 수 있다. 새 유효 요청·전원/소유/부팅/권한 세대 변경·사용자 취소는 해당 사건의 낡은 행동을 취소한다. 원인과 무관한 UI 열림만으로 새 Sleep 권한을 만들지 않는다.
- 새 유효 요청이 남으면 ‘마지막 요청 종료’의 Sleep는 없다. 사용자의 명시Sleep는 자체 요청을 먼저 소비하고, 타사 요청은 건드리지 않는다. 명령 성공과 OS의 실제Sleep은 별개다.

### 근거와 제한

Apple은 [thermalState](https://developer.apple.com/documentation/foundation/processinfo/thermalstate-swift.enum)의 열 단계를 정의한다. [IOPMSleepSystem](https://developer.apple.com/documentation/iokit/1557121-iopmsleepsystem)은 잠자기 요청이며, [PreventSystemSleep assertion](https://developer.apple.com/documentation/iokit/kiopmassertiontypepreventsystemsleep)도 시스템 열/전원 판단보다 무조건 우선하는 권한이 아니다. **15초·60초·120분·20%·5%p는 Tether의 검증할 제품 정책**이며 Apple 공인 안전 수치가 아니다.

후속 시안에서 전원 분리 정책은 현재·미래 작업에 적용할 **명시적 전역 선택**이다. 프로필은 정책 변경을 제안할 수 있으나 선택만으로 현재 전역 정책을 덮어쓰지 않는다. 배터리 최대 시간의 기준점은 보존하되 배터리 사용 중에만 강제하며, AC에서 그 기준 시각이 지났다는 이유만으로 배터리 상한 종료를 실행하지 않는다. 수동 마감과 연결 작업의 유효 기한은 별개다. 보호·복구 실패를 자동화 재개나 전체 중지 해제로 우회하지 않으며, 도우미 미준비는 일반 잠자기 방지와 분리해 안내한다.

Tether V5는 작업 시간, 전원 분리 후 동작, 화면과 덮개, 자동 시작 조건을 사용자가 고를 수 있도록 설계한다. [34개 제품에서 모은41개 기능 묶음](../../FEATURE-SYNTHESIS-20261016.ko.md)을 빠짐없이 연결했다. 기존의 ‘전원 연결 중에만 자동 시작’, ‘배터리에서 최대2시간’, ‘전원을 빼면 모두 종료’는 기본값이나 기존 사용자 설정으로 보존하며 다른 선택도 제공한다. 여기서 정한 수치와 기본값은 제품 추천이며 Apple의 안전 보장이나 실제 기기 시험 결과가 아니다.

작업을 ‘끝낸다’는 것은 Tether의 잠자기 방지를 끝낸다는 뜻이다. 연결된 프로그램·명령·빌드 프로세스 자체를 종료하지 않는다.

기존 사용자는 `V4 호환` 프로필로 이관한다. 자동·화면·덮개 ON/OFF, 잔량 하한, 언어·로그인·업데이트·알림 선택과 기존 시간 목록을 보존한다. 기존 시간 목록은 고급 편집에서 접근할 수 있으며 기본 선택기의 세 항목으로 덮어쓰거나 삭제하지 않는다. 기존 AC 전용·배터리120분 값·분리 전체 종료 설정도 보존한다. 시간의 의미는K02로 통일하되 이관만으로 실행을 복원하거나 원마감·최초 배터리 기준점을 다시 만들지 않는다. 새 설치의 자연 만료 알림ON이나 넓은 전원 범위를 기존 사용자에게 소급 적용하지 않는다. 새 기능과 권한은 OFF이며 이관이 현재 작업 시작·연장·보호 해제의 의사가 되지 않는다. 이관 전 설정 백업과 항목별 차이·되돌리기를 제공한다.

새 설치의 일반 유지에는 관리자 도우미를 요구하지 않는다. MacBook에서 덮개 유지를 처음 선택할 때 해당 준비·인증을 진행하며, 미준비/거절 상태에서는 덮개 허용을 완료 처리하지 않고 일반 유지는 사용할 수 있다. 데스크톱에는 덮개·내장 배터리·도우미 선택을 제공하지 않는다. 과거 ‘MacBook 설치 때 무조건 도우미 필수’는 V5 기본 정책으로 이월하지 않는다.

자연 만료 알림ON은 앱의 선택값이며 OS 알림 권한 획득을 뜻하지 않는다. 첫 유한 수동 시작에서 권한이 미결정이면 알림 목적을 설명하고 정상 OS 요청을 제공하되, 거절·미응답이 작업 시작/종료를 막지 않는다. 거절 상태는 알림 설정 안에 짧게 표시하고 반복 요청하지 않는다.

### 1.1. 시작용 프로필 여섯 가지

프로필은 자주 쓰는 설정을 묶은 것이다. 선택한 프로필은 **다음 작업에 적용**하며, 선택만으로 자동 시작이나 추가 기능을 켜거나 현재 작업을 바꾸지 않는다. 현재 설정과 달라지는 내용을 먼저 보여준다. 반면 기본 화면의 ‘작업 중 화면 끄지 않기’와 ‘덮개를 닫아도 계속’ 스위치는 현재 작업에도 적용하는 별도 조작이다. 기존 사용자 설정을 새 프로필 기본값으로 덮지 않는다.

## 2. 공통 요청·시간·실행 계약

이 절부터는 개발·검증용 계약이다. 사용자 화면에서는 ‘요청’ 대신 ‘작업’, ‘전원 범위’ 대신 ‘작동할 전원 상태’, ‘원복’ 대신 ‘Tether가 바꾼 설정 되돌리기’를 우선한다. requestID·TTL·세대·writer 같은 식별자와 시간 규칙은 내부 계약에서 정확하게 유지하며 화면의 기본 선택명으로 쓰지 않는다.

### 2.1. 요청과 단일 실행 소유자

요청은 `requestID`, 명령 중복 방지ID, 출처, 소유 사용자·부팅·서비스 세대, 프로필 snapshot, 전원 범위, 화면/덮개 등 요구 자원, 시작·마감·상한, 종료 행동, 상태와 관측 근거를 가진다. 상태는 준비 중 / 유효 / 조건 대기 / 사용자 중지 / 보호 중지 / 만료 / 종료 / 적용 제한 / 원복 필요로 나눈다. 설정의ON, 명령 수락, 실제 적용 확인은 다른 사실이다.

메뉴·CLI·URL·Intent·MCP·규칙은 공통 명령 경로로 요청한다. 자원마다 실행 writer는 하나이며 GUI와 서비스가 동시에 독립 assertion·전역 설정을 소유하지 않는다. 정책은 부작용 없는 판정으로 구성하고 실제 OS 호출·관측·권한·복구 adapter를 분리한다. 위젯·CLI·원격 상태 표시는 실행 소유자가 아니다.

기본 수동1개와 여러 연결 작업을 표시하고 개별 선택 종료를 제공한다. 활성 수동이 있을 때 새 일반 수동 시작은 명시적 교체 미리보기를 요구한다. 이미 처리한 ID는 현재 상태와 원래 처리 결과를 반환하고 다시 실행하지 않는다. 개별 작업 종료는 자동·다른 작업·상대 앱 프로세스를 끝내지 않는다.

최종 자원 요구는 유효한 요청의 합집합과 전역 허용·보호·지원 범위의 교집합이다. 한 요청의 화면OFF·덮개OFF·유휴 해제는 다른 요청의 요구를 취소하지 않는다. 수동 우선 모드는 수동이 있는 동안 자동의 실행만 억제하며, 수동 종료와 자동 재평가를 같은 판정 단위에서 처리한다. 계속 유효한 자동이 있으면 마지막 요청 종료 행동을 만들지 않는다.

화면·덮개의 요청별 선택은 `앱 기본 따름 / 개별 켬 / 개별 끔`이다. 새 기본 수동은 앱 기본을 따르고 시작 시 실제 요구값을 저장한다. 프로필을 선택하거나 편집하는 것만으로 현재 요청의 저장값을 다시 계산하지 않는다.

기본 화면의 **작업 중 화면 끄지 않기 / 덮개를 닫아도 계속**은 전역 허용만 바꾸는 토글이 아니라 명시적 `현재+다음 작업 변경` 명령이다. ON은 해당 전역 허용과 다음 작업 기본값을 켜고, 현재 유효한 ‘앱 기본 따름’ 요청의 해당 자원 요구를 갱신한다. `개별 끔`은 바꾸지 않고 `개별 켬`은 기존 선택을 보존한다. OFF는 다음 기본값을 끄고 전역 실행 상한으로 모든 Tether 요청의 해당 실행을 즉시 회수한다. 요청ID·마감·배터리 상한의 최초 기준점·전원 범위·연결 대상은 바꾸지 않으며 종료/보호/중지된 요청을 부활시키지 않는다.

ON 시 필요한 도우미·권한·관측·보호를 새로 확인한다. 거절/부분 적용 실패는 이번 명령이 추가한 자원 요구만 되돌리고 기존 일반 작업과 개별 선택을 보존한다. 성공 확인 전 스위치를 적용 완료로 표시하지 않는다. 화면에는 영향을 받을 현재 작업 수, ‘개별적으로 꺼 둔 작업 제외’, 준비/실패 이유를 짧게 설명한다. 일반 프로필 선택은 이 명령을 대신 호출하지 않는다.

여기서 **적격 요청**은 기존 전원 범위, 같은 요청ID, 유효한 원마감·배터리 상한, 현재 권한·소유자, 최신 보호 관측을 모두 만족하는 요청이다. 계속 유지에도 이 조건을 그대로 적용한다. 미확인 권한이나 만료한 마감을 새ID/새마감으로 대체하지 않는다.

합집합은 일반·화면·덮개 같은 유지 요구의 합성에 적용한다. **밝기 변경·BlackOut·가상 화면 제거·팬 제어는 합집합할 수 없는 자원**이다. 자원별 단일 정책/소유자를 선택하며 상반된 값은 합치거나 마지막 입력으로 덮지 않는다. 유효한 필수 화면 요구나 원격 화면 의존성이 있으면 이를 파괴하는 변경을 보류하고 이유·선택지를 보여준다. 모듈 충돌로 정상 일반 작업을 끝내지 않는다. 전문 앱 소유가 확인되면 새 Tether 제어를 보류하고 명시적인 소유 이전을 거친다.

### 2.2. 시간과 변경

- 기간·마감의 경과·전원/보호 표본·lease TTL·실행 허가는 **수면을 포함하는 연속 시계**를 사용한다. 부팅을 넘긴 연속 시계 값은 실행 권한이 아니다.
- `기간`은 지금부터 경과할 시간이다. `종료 시각`은 날짜·시간대가 보이는 벽시각 입력이며 승인 때 하나의 연속 마감으로 변환한다. 변환 뒤 시스템 시각·시간대 변경은 현재 마감을 바꾸지 않는다. 새 종료 시각을 명시 적용할 때만 다시 변환한다.
- 오늘 이미 지난 시각은 자동으로 내일로 바꾸지 않는다. 날짜를 고르게 하고 최종 날짜/시각을 미리 보여준다. DST 중복 시각은 첫/둘째 발생을 선택하고 존재하지 않는 시각은 거절한다.
- 빠른 시간·기본값·프로필 선택은 **다음 작업**에 적용한다. 현재 요청의 마감·전원 범위·요구 자원·연결 대상을 바꾸지 않는다. `현재 작업에 적용…`은 바뀔 값·새 마감·제한을 미리 보여주는 별도 명령이다. §2.1의 기본 화면 스위치 직접 조작은 명시적 현재+다음 변경이므로 별도로 처리한다.
- 기본 시작 선택기는 `30분 / 1시간 / 2시간`이며 새 설치의 첫 선택은30분이다. 다음 시작 선택기에서 고른 최근 유한 값을 기억한다. `끄기 전까지`는 보조 옵션이며 최근 유한 선택을 덮지 않는다. 현재 요청의 연장·마감 변경·알림에서 연장도 최근 시작 선택을 덮지 않는다. 선택만으로 요청을 시작하지 않고 `직접 시작`을 따로 누른다.
- 직접 기간·날짜/시각·사용자 시간 목록·grid/ring은 고급 진입 안에서 제공하며 기본 선택기를 큰 버튼 행이나 편집 가능한 목록으로 바꾸지 않는다. 날짜/시각은 고급에서 매번 최종 마감을 확인하며 지난 시각을 다음 시작 기본값으로 반복 재사용하지 않는다. 고급 시간 목록의 추가·숨김·정렬·복원과 기존 값 보존은 계속 제공한다.
- `+N분`은 기존 마감에 가산, `지금부터N분`은 마감 교체, `종료 시각 변경`은 명시된 새 마감 적용이다. 어느 명령도 종료된 요청을 부활시키지 않는다. 무제한 요청에는 `시간제로 변경`을 제공한다.
- 기본 실행 중 조작은 유한 타이머의 `30분 추가`와 `타이머 끝내기`다. 가산량 선택·직접 분·지금부터N분·종료 시각 교체는 고급의 `타이머 시간 변경…`에 모은다. `끄기 전까지` 요청에는 의미 없는 가산 연장을 제공하지 않고 고급에서 시간제로 바꿀 수 있다. `끄기 전까지`도 배터리 상한·보호·전원 범위·종료 정책을 무시하는 무제한 허가가 아니다.
- 배터리 상한은 **수동·자동·명시 연결lease를 포함한 모든 유효 요청(후속 제외된 특정 PID 수동 종료 연동 제외)**에 적용하며, 계산은 요청이 처음 배터리 실행을 승인받은 시점+선택한 상한이다. AC 왕복·heartbeat·프리셋 변경·GUI 재연결로 초기화하지 않는다. 배터리 시작 요청이AC로 이동해도 원래 기준점은 보존하며, 다시 배터리로 옮길 때 같은 상한을 검사한다. 각 요청의 실제 종료는 요청 마감·lease TTL·**배터리 사용 중에만 강제하는 상한** 중 먼저 오는 시점이다. AC 사용 중에는 배터리 상한 때문에 종료하지 않으며 수동 마감과 lease TTL은 계속 유효하다.
- **프로필의 배터리 최대 시간 변경은 늘리거나 줄여도 다음 요청에만 적용한다.** 프로필120→30분 선택 때문에 현재 작업을 종료하지 않는다. `현재 작업의 최대 시간 변경…`을 명시 적용하거나 공통 보호 제한을 강화한 경우에만 현재 요청을 즉시 재평가하며, 새 제한을 이미 넘었으면 종료 이유를 보여준다. 현재 상한을 완화해도 최초 배터리 기준점은 보존하고 끝난 요청을 부활시키지 않는다. 추가 분량 전체를 허용할 때만 가산 연장을 승인한다.
- 시작·마감 변경은 필요한 실행기 적용을 확인한 뒤 완료한다. 부분 실패는 새로 얻은 자원만 회수하고 이전 승인 마감을 유지한다. 그 사이 원래 마감이 지났으면 자연 만료한다. 늦은 ACK·옛 타이머·옛 알림은 마감 세대를 바꾸지 못한다.

## 3. 전원·덮개·화면의 충돌 결정

### 3.1. 분리 정책 세 가지

| 정책 | 확인된 AC→배터리에서 기존 요청 처리 | 새 자동 시작 |
|---|---|---|
| Tether의 잠자기 방지 모두 끝내기 — 기본 | 기존 자동·수동·작업lease 모두 종료. 끝난 요청의 지연 입력 소비 | 해당 분리 사건으로 시작하지 않음. 이후 새 실제 조건 사건 또는 사용자 명령 필요 |
| 자동만 끝내고 가능한 직접 시작 작업 계속 | 기존 자동 요청 종료. 수동/명시적 연결 작업은 배터리 범위·원마감·남은 배터리 상한·보호를 허용한 경우 같은ID로 계속 | 분리 사건으로 새 자동 시작 없음 |
| 작업별 전원 설정에 맞춰 계속 | AC전용 종료, 배터리/모두 요청은 같은ID·원마감·상한으로 계속할 수 있음. 자동도 현재 조건을 새로 확인 | 배터리 규칙으로 분리를 시작 사건으로 명시 선택한 경우만 새 요청 생성 |

계속 유지는 새 숨은 시작·상한 초기화가 아니다. 배터리 범위를 허용하지 않은 요청을 이관하지 않으며, 조건과 권한을 새로 확인할 수 없으면 계속 성공으로 표시하지 않는다. 배터리 자동은 프로필의 배터리 시간 상한을 적용하고, 조건이 계속 참이라는 이유로 같은 활성 사건의 상한을 반복 초기화하지 않는다. 상한 종료 뒤 새 시작에는 false→true 같은 새 실제 사건 또는 사용자 재개가 필요하다.

unknown은 분리 확정이 아니다. 마지막 확인 공급원과 관련 표본 유효성을 따로 보관한다. AC→unknown→AC는 새 연결/분리를 만들지 않고 AC→unknown→배터리는 확정 분리1회를 소비한다. K03에 따라 새 시작·연장·새 덮개 허가·기존 허가 갱신을 금지하고, 기존 실행은 원마감·기존 유한 허가·마지막 정상 관련 표본+15초 중 최소까지만 인정한다. 아무 실행 소유자도 신선한 공급원을 확인하지 못한 경우의 제한이며, 실행 소유자가 확인한 실제 분리·보호·만료를 미루지 않는다. 기한 만료 뒤 요청을 소비하고 확인실패 차단을 남기며 정상 표본만으로 끝난ID나 보류 명령을 재생하지 않는다.

### 3.2. 덮개·원격·잠금

덮개 허용은 일반 작업 시작과 독립이다. `다음 한 번 닫기`는 선택한 요청의 다음 open→closed1회에만 귀속하고 다시 열면 소비한다. `요청 동안 계속`은 해당 요청이 끝날 때 해제한다. Option-close는 지원 센서와 modifier 시점을 검증한 기기만 제공하며 미지원 기기에는 같은 의미의 메뉴/단축키를 제공한다. 제스처를 관측하지 못하면 임의 추정하지 않는다.

열림 행동 기본은 추가 동작 없음이다. 선택은 해당 덮개 요청 종료 / 화면 잠금 / macOS에 맡김이며, 다른 유효 요청을 끝내지 않는다. 원격 무잠금 프로필과 열림 잠금을 동시에 고르면 적용 전 충돌을 보여주고 하나를 고른다. 이미 잠긴 화면을 자동 해제하는 기능은 제공하지 않는다.

화면 전역 허용, 요청별 유지, 유휴 해제, 밝기, 화면 잠금, 물리 화면 절전, BlackOut, 가상 화면은 각각 다른 상태다. 밝기0·가림을 패널 전력0·OS 잠금·원격 성공으로 표시하지 않는다. 가상 화면 제거/분리는 마지막 유효 화면·원격 의존성을 확인하며, 확인할 수 없으면 제거하지 않고 복구 경로를 남긴다. 화면 기능 실패만으로 정상 일반 작업·마감을 임의 종료하지 않는다.

잠금 사건 기본은 화면 요청 해제이며 일반 작업과 기한은 계속된다. 기본 입력 유휴는 신뢰할 수 있는 실제 로컬/원격 사용자 입력이며 합성 활동은 유휴 타이머를 리셋하지 않는다. OS가 입력 출처를 구분하지 못하는 기기에서는 입력 리셋과 활동 주입의 동시 실행을 거절하고 설명한다.

Tether가 만든 활동 주입은 자체 이벤트ID/출처로 N40 유휴 타이머와 N20 작업 추정에서 제외한다. N34 디스크 깨움이 만든 파일·쓰기·IO는 N19 다운로드/백업 진행 근거에서 제외한다. 출처를 구별할 수 없는 같은 대상 조합은 동시 실행을 보류한다. 자체 관측이 다시 자신을 유지시키는 순환을 만들지 않는다.

## 4. 종료·중지·수명·보호

### 4.1. 마지막 요청과 종료 행동

판정 순서는 소유자/부팅 유효성 → 보호·사용자 Sleep/모두 중지 → 확인된 전원 정책 → 만료/연결 작업 종료 → 새 명시적 요청 → 자동 조건이다. 한 판정 단위에서 유효 요청을 모두 재평가한 뒤 **마지막 유효 요청이 사라졌는지** 판단한다. 요청 하나 종료를 전체 종료로 바꾸지 않는다.

요청 종료 / 자체 자원 해제 / 원복 확인 / Sleep 요청 / 실제 OS Sleep은 별도 결과다. 최초 종료 사건에는 원인·끝난 요청ID·마감/전원/소유자 세대·정리ID·60초 정리 기한을 기록한다. 처음 끝난 작업의 원인 계보가 계속 유효한 경우에만 정리를 이어간다. 새 유효 요청·마감 변경·전원 세대·소유자 변경이 생기면 옛 종료 행동을 취소하며, 그 새 작업이 나중에 끝나도 취소한 계보를 되살리지 않는다.

종료 결정 즉시 대상 요청을 소비하고 새 실행 허가 갱신을 중단하며 자체 유지 해제·원복을 시도한다.60초는 추가 유지시간이 아닌 복구 정리의 최대기한이다. 정리가60초 안에 끝나고 원인 계보·현재 세대·유효 요청 부재를 다시 확인한 뒤에만 행동ID와15초 Sleep 행동 권한을 발급한다. 실행 직전에도 재검사한다. 60초를 넘긴 원복/eject 완료, 이미 취소된 계보,15초 권한 만료는 옛 Sleep 권한의 생성·연장·재발급 근거가 아니다. 원복 확인 자체는 늦게라도 기록하고 필요한 복구를 계속할 수 있지만 Sleep은 재생하지 않는다. 이미 파견한 OS호출은 취소 가능성을 보장하지 않으며, 늦은 응답을 새 행동으로 재발급하거나 재요청하지 않는다.

| 원인 | 기본 행동 | 사용자가 고를 수 있는 행동과 한계 |
|---|---|---|
| 수동 종료·자동OFF·개별 작업 종료 | 해당 요청만 해제, macOS에 맡김 | 별도 `잠자기…` 명령과 구분 |
| 자연 만료·작업 완료·현재AC | ‘상황에 맞게’: 마지막 요청이면 macOS에 맡김 | 화면 절전 / 보호기 / 잠금 / Sleep / 검토한 후처리 |
| 자연 만료·작업 완료·현재배터리·닫힘 | ‘상황에 맞게’: 마지막 요청이면 원복 후Sleep1회 | macOS에 맡김 또는 원인별 선택 |
| 전원 분리·닫힘 | 분리 정책 적용 뒤 마지막 요청이면 원복 후Sleep1회 | 유효한 계속 요청이 있으면 Sleep 없음 |
| 열린 상태 | 자체 요청 해제, macOS에 맡김 | 사용자가 명시 선택한 종료 행동은 실행 가능 |
| 보호 중지 | 관련 요청 종료·원복, 닫힘이면 보호Sleep1회 | 알림OFF로 보호를 해제하지 않음. 관측 실패를 과열 확정으로 바꾸지 않음 |
| 명시적Sleep | 모든 자체 요청 종료·자동재시작차단·원복 후Sleep1회 | 실제Sleep 실패도 차단 상태 유지 |
| shutdown/restart | 기본 제공 행동 목록에서는OFF | 별도 명시 예약·취소 가능 유예60초·미저장 작업 안내를 거친 시스템 연계만 제공 |

타사 assertion은 존재와 관측 시각만 설명하고 해제하지 않는다. 미소유 전역 설정을 임의0으로 만들거나 자기 소유로 승격하지 않는다. 전역 차단/자체 원복 미확인이면 Sleep 요청 불가·미확인을 보여준다. 명령 성공은 실제Sleep 증거가 아니다.

종료 후처리 순서는 **자체 원복 확인 → 선택 볼륨 안전 해제 → 원인 계보·새 유효 요청/세대 재확인 → 행동 권한 발급 → 선택한 종료 행동**이다. 정리 전체는 최초 종료 결정부터60초, 디스크 단계 전체는 일반30초/보호5초 이내다. 정리용 허가는 사용자 작업의 새 시작/연장이 아니다.

각 볼륨을 해제하기 **직전에도** 새 유효 요청·세대·볼륨 사용 상태를 확인한다. 새 작업이 생기면 아직 시작하지 않은eject와 옛Sleep을 취소한다. 이미 진행 중인 시스템 호출은 가능하면 취소하고, 늦은 응답을 새 행동 허가로 바꾸지 않는다. 사용 중인 볼륨은 강제 해제하지 않는다. 일반Sleep은 안전 해제 실패 시 취소하고 이유를 보여준다. 보호 종료는 최대5초 뒤 실패를 기록하고, 남은 전체 기한과 현재 계보가 유효할 때만 보호 행동을 계속한다. 보호 종료에는 외부 스크립트를 기본 실행하지 않으며 선택hook도 복구/Sleep을 무한 대기시키지 않는다.

### 4.2. 중지와 재개

- `수동만 종료`, 선택 연결 작업 종료, 자동OFF, `모두 중지`, `잠자기`는 다른 명령이다. 모두 중지는 모든 자체 요청을 끝내고 사용자 재개까지 새 자동을 막는다.
- **출처가 확인된 Tether 명시Sleep**는 명령 의사 수락 때 차단을 저장하며 실제Sleep 실패에도 유지한다. Wake·프로브 갱신·heartbeat·GUI 재실행 자체는 이 차단을 해제하지 않는다. 명시 재개 또는 차단 이후 확인된 새AC전이/조건false→true에서만 새 자동을 평가한다. 계속 참인 조건·AC→unknown→AC·startup초기값·놓친 일정은 새 사건이 아니다. 모두 중지는 이 새 사건으로도 해제하지 않는다.
- 일반/출처 미확인 OS Sleep은 실행 중 수동·연결 작업을 소비한다. 사용자중지·Tether 명시Sleep·보호·복구·분리/상한 종료 차단이 없고 정상fullWake와 선택한 자동 규칙의 전원 범위(기본AC)·신선한 규칙/보호·유한 예산·실행 소유·해당 GUI/서비스의 새 자동 시작 허가가 확인되면 새 자동ID만 평가할 수 있다. 명시 선택한 배터리 자동도 같은 자동 활성사건의 최초 배터리 기준/상한을 새ID에 보존하며, 원상한 만료 뒤에는 시작하지 않는다. DarkWake/관측공백/재생표본/GUI 재실행은 대체 근거가 아니다. macOS 메뉴나 타사 Sleep 의도를 항상 식별한다고 보장하지 않는다. 남은 시간으로 새로 시작은 현재 보호/전원·새ID·새마감을 보여주는 명시적 수동 시작이며 자동 복원이 아니다.
- 사용자 `일시정지`는 선택 수동의 자원만 해제하고 남은 기간을 보존하는 별도 조작이다. 기본 표시에서는 숨긴 고급 조작이며, 재개는 명시적 요청이다. 보호·전원 정책으로 종료된 작업을 일시정지로 둔갑시키지 않는다. 배터리 최초 상한은 일시정지 중에도 흐른다.
- 보호 후 기본은 직접 재개다. 열nominal/fair60초 AND 현재 공급이 배터리이면 하한+5%p60초, AC이면 정상AC60초가 필요하다. 기본 하한20%에서 회복은25% 이상이다. 관련 표본은15초 이내여야 하며 명시unknown·15초 초과 공백·Sleep은 해당 안정구간을 초기화한다. 데스크톱에는 존재하지 않는 배터리 조건을 요구하지 않고 선택한 저전력 중단 조건도 해소해야 한다. 선택적 자동 회복은 같은 기준 뒤 다른 재시작 차단이 없는 유효 자동 조건만 새로 평가하며, 같은 자동 활성사건의 최초 배터리 기준/상한은 보존한다. 보호로 소비된 수동·명령·연결lease는 남은TTL이 있어도 복원하지 않으며, 새 명시 요청이 필요하다.15초·60초·5%p는 제품 정책이며 OS 보호를 우회하지 않는다.

### 4.3. GUI·서비스·업데이트

설정 창/패널 닫기는 작업을 끝내지 않는다. 메뉴 앱 종료 기본은 전체 자체 작업 종료·원복이다. `백그라운드에서 계속`은 사용자가 명시 선택한 요청/기능 목록과 마감을 확인한 뒤 작업 서비스로 이전한다. 이 선택만으로 다른 작업·새 자동 규칙이 서비스에 추가되지 않는다. 서비스 상태·남은 시간·즉시 모두 종료를 메뉴 재실행/CLI/시스템 진입점에서 접근할 수 있어야 한다.

GUI 비정상 종료는 미선택 요청을 유한 허가 만료로 회수한다. 선택된 서비스 작업은 같은 부팅·같은 사용자·유효 요청·기존 마감·보호 조건에서만 계속한다. **예기치 않은 작업 서비스 종료·재시작**, 로그아웃·재부팅은 기존 요청을 종료하고 미완료 원복부터 처리한다. 새 서비스가 옛 요청을 재생하지 않는다. 아래의 검증된 계획 업데이트 인계만 이 규칙의 예외다. 자동 규칙은 중지 차단이 없을 때 K04의 새 실제 사건/사용자 재개 또는 차단 없는 정상fullWake와 선택 전원 범위·신선한 조건·유한 예산·새 시작 허가에서 새ID로 평가한다. 같은 자동 활성사건의 최초 배터리 기준/상한은 보존한다.

GUI가 없는 worker는 명시 이전된 기존 작업만 기본 계속한다. `GUI 없이 새 자동 작업 시작 허용`은 별도 OFF 설정이며, 이를 켜고 해당 규칙을 선택한 경우에만 새 실제 조건 사건으로 시작할 수 있다. GUI 종료 시 기존 작업 계속과 새 자동 시작 허가는 같은 동의가 아니다.

예약wake의 OS 등록과 **wake 뒤 작업 실행 허가**도 별개다. 예약에는 소유자·예약ID·예정 시각·작업 대상·허가 세대를 기록한다. 명시Sleep 뒤 예약으로 깨어나는 사실만으로 옛 수동이나 자동을 부활시키지 않는다. 그 Sleep 이후에도 유효한 예약별 작업 실행 허가를 사용자가 명시한 경우에만 새 작업을 승인한다. 허가가 없으면 OS 깨움 결과만 기록하고 작업은 시작하지 않는다. 타사 예약은 수정·취소하지 않는다.

작업 후 업데이트 예약은 후속 사용자 결정으로 제외한다. 일반 업데이트 확인·다운로드만으로 작업을 끝내지 않으며 교체 직전 현재 작업·연장·권한·원복·전원·덮개를 재검사한다. 안전하지 않으면 설치를 보류하고 사용자에게 현재 작업 종료 후 다시 설치할 수 있음을 안내하며 숨은 예약을 만들지 않는다. 별도 승인·인수된 계획 인계 설계는 N10의 조건부 기능으로만 보존한다. 그 경우에도 단일소유 확인·같은ID·원마감·최초 배터리 기준 보존이 필수이고 서비스crash 복원과 혼동하지 않는다. 인계/호환 미확인은 교체 보류이며 새 시작·마감 연장·끝난 요청 복원으로 해결하지 않는다.

### 4.4. 보호·외부 자원 복구

배터리 공급이 확인되고20% 이하이면 기본 중단하며, AC에서 잔량20%라는 이유만으로 배터리보호를 적용하지 않는다. AC 공급 중 잔량 감소는5분 이상·3%p 이상 관측했을 때 안내하고 기본 자동중단하지 않는다. 충전 여부·케이블·현재 공급·UPS를 구분하며 불명확한 공급은unknown이다. 열 수치는 macOS pressure를 우선하며 별도 센서값은 출처·단위를 표시하고 기본 보호의 대체 사실로 쓰지 않는다.

각 확장은 실행 전 읽을 수 있는 원본과 소유권·요청/세대를 durable journal에 기록한다. 읽기/기록 실패 시 새 변경을 시작하지 않는다. 종료는 실제 현재값이 자기 적용값과 일치하는 자원만 원복하며 외부 변경을 덮어쓰지 않는다. 원복 실패를 저장하고 복구 조작을 제공한다. 모듈 해제·권한철회·앱 교체·기기 분리·크래시 각각을 인수한다. 팬 자동복원·화면 복구 같은 긴급 수단은 일반 단축키와 별도로 항상 접근 가능해야 한다.

| 끄기 전까지 | 보조 옵션. 배터리 최대 시간과 보호는 계속 적용 | 무기한 요청이며 전원 범위·상한·보호·종료 계약을 우회하지 않음 |
| 30분 추가 / 타이머 끝내기 | 지금 실행 중인 유한 타이머 조작 | 가산 연장은 전체 분량 승인. 현재 변경은 최근 시작 선택과 독립 |
| 다음 작업에 적용 | 프로필과 기본 시간은 다음에 시작할 작업부터 사용 | 현재 요청 snapshot 보존. 단순 선택은 현재 변경 명령 아님 |
| 현재 작업의 최대 시간 변경… | 지금 진행 중인 작업에 바뀔 제한과 종료 시각을 먼저 표시 | 최초 배터리 기준점을 보존하며 명시 적용 후 즉시 재평가 |

메뉴는 상태에 맞는 조작만 먼저 보여준다. **대기 또는 자동 작업만 실행 중**이면 다음 시작 선택기와 `직접 시작`을, **직접 시작한 유한 타이머 실행 중**이면 남은 시간·끝날 시각과 `30분 추가 / 타이머 끝내기`를, **보호로 중단된 상태**이면 이유와 해결 조작을 우선한다. `끄기 전까지` 실행 중에는 해당 선택과 현재 유효한 제한·끝내기를 표시하고 가산 연장은 고급의 시간제 전환으로 대신한다. 실행 중 다음 시작 시간 선택과 현재 종료 시각 편집을 같은 입력으로 합치지 않는다. 고급의 `다른 시간…`은 다음 시작 초안, `타이머 시간 변경…`은 현재 요청 변경으로 명시한다.

직접 시작한 타이머가 끝나도 유효한 자동 작업이 있으면 `타이머 종료 · 전원 연결 자동 유지 중`처럼 종료한 타이머와 계속되는 실제 자동 근거를 함께 표시한다. 이 문구는 실제 전원 연결 자동 조건이 유효할 때의 예시이며 다른 전원/조건이면 해당 근거로 바꾼다. 끝난 타이머의 남은 시간을 계속 표시하거나 Tether 전체가 끝났다고 표시하지 않는다. 이 경우 마지막 유효 요청 종료나 옛Sleep 행동을 만들지 않는다.

연결한 작업은 펼쳐 골라 종료할 수 있다. `타이머 끝내기`와 `모든 작업 종료`를 구분하고, 뒤에서 작업이 계속 중이면 Tether 종료와 전체 종료를 구별한다. 화면·덮개 스위치에는 현재와 다음에 함께 적용한다는 설명을 가까이 둔다. 부모 기능을 끄면 관련 세부값은 **접되 보존**하고 설정 편집 진입은 남긴다. 예고OFF면 예고에만 속한 시점/소리/연장 버튼 세부를, 화면OFF면 유휴 시간을 기본 화면에서 접는다. 보호·자연 만료 등 다른 알림의 설정과 문제 해결 조작은 함께 숨기지 않는다. 세부값을 보존한 사실이 기능ON이나 실행 허가가 되지 않으며, 다시 켤 때 현재 권한·보호·지원 조건을 재확인한다.

기본/상세·접힘/펼침·스크롤 끝·한영·밝음/어두움·긴 작업명·복수 작업·권한 없음·조건부 미지원·원복 실패를 시안에 포함한다. 버튼 선택·preview·조건값 수정만으로 실행을 시작하지 않는다. 제한이 있으면 바로 옆에 이유와 가능한 조작을 제시한다. 시안의 예시 센서·카운트다운은 모의 표시이며 설치본 상태가 아니다.

화면별 배치·치수·재질과 검수 범위는 [V5 디자인 계약](DESIGN-V5.ko.md), [메뉴·설정 HTML 시안](../../../../../outputs/tether-v5-spec-design-20261016/index.html)에서 확인한다. HTML의 CSS 재질은 native Liquid Glass의 인수 근거가 아니다. 기본 키보드 조작·컨트롤 의미는 유지하되 기존 사용자 결정에 따라 VoiceOver 전용 튜닝·시험은 이 범위에 추가하지 않는다.

## 7. 검증과 출시 판정

수락ID는 [체크리스트](V5-VALIDATION-CHECKLIST.ko.md)에 연결한다. 단계는 문서 완결성 → 순수 정책/adapter 자동 검증 → native UI → 사용자 승인 설치/권한 → 대상 기기 물리 인수 → 배포 후보 순이다. 이전 단계 통과를 다음 단계 통과로 바꾸지 않는다.

조건부 기능은 `미검증·실행 불가` → `검증된OS×기기×권한 조합에서 제공`으로만 승격한다. 지원표 밖은 값을 추정하거나 실험 허용 하나로 우회하지 않는다. 일부 기능이 미지원이어도 다른 정상 기능을 사용할 수 있고, 미지원 제공자를 삭제해AND규칙을 약화시키지 않는다. 미지원은 기능 채택 철회가 아닌 명시된 실행 제한이다.

핵심 완료는K00~K09와 해당 자동/native UI/설치·물리 인수 근거로 판정한다. V5 전체 완료는41개 수락ID의 유효 승인 범위와 공통 불변조건, 해당 수동/물리 경로의 근거가 갖춰진 뒤에만 선언한다. 후속 명시 제외는 제외 사유·범위를 보존하고 통과로 계산하지 않으며 조건부·미구현도 완료로 위장하지 않는다. 앞선 문서 전용 작업은 **41묶음 추적·기본값/충돌 결정·검증 설계 완성**으로 완료했다. 현재 로컬 P0 구현·자동 검증의 결과는 머리말의 별도 결과 기록을 따르며, 설치·실물 합격이나 V5 전체 완료로 승격하지 않는다.
