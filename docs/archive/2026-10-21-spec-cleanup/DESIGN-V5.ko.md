# Tether V5 디자인 계약·검토 시안

2026-10-21 · Graphite + Blue · **P0 동작·옵션 연결과 자동 검증 반영 · 실제 화면 검수 미완료**

기능 의미는 [V5 기능명세](PRODUCT-SPEC-V5.ko.md), 상태 문구는 [표시 문구 계약](COPY-V5.ko.md)을 따른다. 앞선 문서 전용 설계 통일은 완료했으며, 현재는 P0 실행 규칙과 화면의 상태 설명을 로컬 후보에 연결하고 자동 검증하는 단계다. 현재 근거와 남은 항목은 [P0 구현·검증 결과](../../../../../outputs/tether-p0-implementation-20261021/RESULT.ko.md)에서 구분한다. 설치·물리 인수는 미실시이고 실제 화면의 전체 검수·V5 전체 구현 완료를 주장하지 않는다. 기존 `DESIGN.md`의 후보58 기록이나 과거 이미지·검사 결과를 현재 후보의 화면 완료로 승격하지 않는다. 브랜드 방향 **Open Clasp / Graphite + Blue**와 단일 메뉴는 유지한다.

최신 native에 이미 반영된 `잠자기 방지 / 자동 시작 / 앱 설정` 3탭을 배치 기준으로 삼는다. 이를 아직 구현되지 않은 개선으로 되돌리지 않는다. 메뉴의 화면·덮개 토글, 자동 중 수동 타이머 추가 펼침 등 후속 제안과 실제 구현 상태는 [기능 감사](../../FUNCTION-AUDIT.ko.md)에서 별도로 추적한다.

N01~N41의 승인 설계는 기본·고급·연계·조건부·미구현 상태로 보존한다. 후속 명시 제외인 **전역 사용자 단축키, 규칙 예행연습, 설정 변경 이력·복원, 특정 PID 종료 연동, 작업 후 업데이트 예약**은 제외 이력으로 남기며 현재 화면에 재도입하지 않는다. 같은 묶음의 앱 실행 조건·CLI/URL·프로필·설정 이관·일반 업데이트·복구까지 삭제한 것으로 해석하지 않는다.

## 최신 소규모 보완 · 명세 전용

- 용어는 [최신 쉬운 용어](COPY-V5.ko.md)를 따른다. 밝기 0·다른 앱 표시는 설계 추가이며 앱이나 배포 시안에 아직 적용하지 않았다.
- 메뉴의 `덮개를 닫아도 계속 사용` 주 스위치는 유지한다. 세부 선택 세 가지는 하위 메뉴/설정에 두고, 메뉴에 큰 설명 카드 세 개를 추가하지 않는다. 메뉴와 설정은 같은 저장값·실제 적용 상태를 사용한다.
- 설정의 `덮개를 닫으면 내장 화면을` 선택기는 주 스위치 바로 아래에 배치한다. 설명은 선택에 맞춰 한 줄로 바뀐다. 꺼진 주 기능의 세부값은 접어 보존하며 편집 진입을 남긴다.
- `밝기 0으로 유지`를 고르면 짧은 의미 설명을 제공한다. 지원하지 않는 환경에서는 선택 불가 이유를 표시하며 성공 배지를 미리 붙이지 않는다. 열린 상태의 화면 켜두기와 닫힌 내장 화면 선택의 범위를 가까이 표시한다.
- `잠자기를 막는 다른 앱`은 설정의 문제 확인 안에 접힌 항목으로 둔다. Tether 중지 후 다른 요청이 관측되면 메뉴에는 요약 한 줄과 상세 진입만 제공한다. 원격 전용 메뉴·설치 앱 나열·자동 종료/제거 버튼은 추가하지 않는다.
- 한영 긴 앱 이름, 표시할 수 없는 앱 이름, 요청 0/1/여럿, 조회 실패에서도 설명·조작이 잘리거나 상태와 모순되지 않아야 한다. 실제 화면/스크롤 검수는 SIMPLE-D08 인수에 남긴다.

## 화면과 우선순위

| 영역 | 먼저 표시 | 접거나 별도 화면으로 이동 |
|---|---|---|
| 메뉴 | 상태·실제 원인 → 해당 상태의 시간/재개 조작 → 공통 화면·덮개 설정 → 모두 중지·설정·앱 종료 진입 | 작업별 목록·타사 영향·고급 시간/시각·종료 상세. 보호·복구 실패·미해제 영향은 숨기지 않음 |
| 잠자기 방지 | 자동 시작 설정으로 이동, 현재+다음 화면·덮개 설정, 현재 분리 정책·배터리 최대 시간, 보호 요약 | 승인된 덮개 한 번/지속·열림·유휴·보호 수치·원인별 종료/재개 설계. 미구현/조건부 상태 표시 |
| 자동 시작 | 자동 전체 허용, 이름/전원/조건, 조건별 켬·끔·추가, 현재 충족 근거 | 앱 실행 조건·명령·AI/MCP·신호/권한·고급 AND/OR·백그라운드 새 시작. 예행연습과 특정 PID 종료 연동은 후속 제외 |
| 앱 설정 | 메뉴 표시·클릭·알림 요약·앱 종료 시 동작 | 로그인·외관·세부 알림·보존된 확장·일반 업데이트·진단. 전역 사용자 단축키·설정 이력·작업 후 업데이트 예약은 후속 제외 |

자동 스위치는 자동 전체 허용이고 규칙 편집의 스위치는 해당 규칙 사용이다. 메뉴에 빠른 자동 스위치를 제공하더라도 설정과 같은 값을 편집한다. 자동 OFF는 수동을 끝내거나 모두 중지 차단을 만들지 않는다. 수동 종료 뒤 자동이 유효하면 `타이머 종료 · {실제 조건} 자동 유지 중`으로 바뀐다. 모두 중지는 수동을 포함한 기존 Tether 유지를 모두 끝내고 사용자가 직접 해제할 때까지 새 자동을 막는다.

화면·덮개 주 스위치는 현재 적격 ‘앱 기본 따름’ 작업과 다음 기본값을 바꾸는 명시적 조작이다. ON은 준비·권한·실제 적용 확인을 거치고 개별 OFF를 보존한다. OFF는 해당 실행을 즉시 회수한다. ID·마감·전원 범위는 보존하고 중지된 작업을 부활시키지 않는다. 실행 중에는 `현재와 다음 유지에 적용 · 개별적으로 꺼 둔 작업 제외`, 중지 상태에는 `저장된 설정 · 다음 유지 때 적용`을 가까이 둔다. 프로필·다음 시간 선택은 이 현재 변경 명령과 다르다. 3값의 요청별 선택은 설계로 보존하고 현재 Bool 구현이 이미 그 출처를 구분한다고 주장하지 않는다.

41개 묶음의 확장 라이브러리·검색은 보존된 설계이며 현재 native 구현 완료를 뜻하지 않는다. `기본 제공`은 제품 구성이라는 뜻이고 기본 ON과 다르다. 선택 확장은 OFF, 조건부 기능은 지원 확인 전 실행 불가다. 후속 제외는 별도 표시하며 나머지 옵션을 임의 삭제하지 않는다.

**표시 우선순위:** 활성 보호·확인 실패(S07~S09) → 미확인 자체 해제·원복(S11~S12의 미확인) → 모두 중지·명시 Sleep 차단(S04~S05) → 유한 관측 대기(S06) → 확인된 종료·원복·Sleep 단계(S11~S14) → 유지·대기(S00~S03)다. S10은 해당 회복 조건을 모두 만족하고 미확인 해제·원복 차단이 없을 때만 S08/S09를 대신한다. 보호가 해소돼도 모두 중지가 남아 있으면 S04가 우선한다. 함께 유효한 제한과 종료 원인은 보조줄에 남긴다.

덮개·외장·원격 상태가 종료 원인과 보호/복구 문구를 덮어쓰지 않는다. S15는 덮개 기능의 준비 안내로, 유효한 일반 유지 S01~S03 전체를 실패로 바꾸지 않는다. S07/S08의 요청 소비와 실제 해제 확인도 구분하며 미확인이면 `유지 해제 확인 중`을 함께 표시한다. 보호·모두 중지 중 저장된 토글 ON을 현재 실행으로 칠하지 않는다. 메뉴 푸터의 이미 중지된 상태는 비조작 텍스트로 구분하고 필요한 재개는 본문에서 설명한다.

## P0 규칙이 화면에 드러나는 방식

| 계약 | 화면 설명·조작 제한 |
|---|---|
| K00 후보·범위·근거 | 문서·웹 모의 상태·정적 이미지·native 실행·설치·물리 근거를 구분. 과거 화면 승인으로 현재 후보의 클릭·스크롤·글래스·원복을 통과시키지 않음 |
| K01 자동·분리 | 자동 시작 기본 전원 범위 AC·분리 전체 종료·배터리 별도 수동 2시간. 자동 허용을 임의로 ON으로 바꾸는 뜻은 아님. N05/N06의 확장 선택은 보존하되 미구현/조건부 상태 표시. 분리 안내는 현재 정책·실제 생존 작업에 맞춤. 자동 OFF와 모두 중지는 별개 |
| K02 시간 | 모든 기간 마감은 수면을 포함하고 AC에서도 흐름. 연결만으로 원마감 연장 없음. 별도 배터리 상한은 최초 배터리 실행+120분 기본, 배터리에서만 집행·AC 방문으로 기준점 재설정 없음. AC의 명시 연장은 가능하되 자동 연장과 구별 |
| K03 전원 unknown | 확정 분리로 표시하지 않음. 기존 유한 허가·원마감·마지막 정상 표본+15초 중 최소까지 유지, 새 시작·연장·덮개 획득 차단. 15초 제한은 전원/열/소유 허가의 필수 실행 표본에 적용. 화면/선택 제공자 unknown은 영향 규칙·자원만 제한하며 무관한 일반 유지 전체 종료 아님. 실행 소유자의 신선한 확정 분리·열 위험·만료는 즉시 우선. 기한 만료 뒤 S07과 기본 직접 재개, 정상 표본만으로 소비된 요청 복원 없음 |
| K04 중지·Sleep | 모두 중지는 직접 해제 전 지속. 출처 확인된 Tether 명시 Sleep은 명령 수락 때 차단 저장·Sleep 실패에도 유지. Wake/새로고침/앱 재실행만으로 해제하지 않고 새 실제 연결·조건 false→true·명시 재개만 평가. 일반/출처 미확인 OS Sleep은 옛 수동·lease 소비 후, 분리·배터리 상한 종료 뒤의 자동 재시작 차단을 포함한 다른 차단이 없고 정상 fullWake+신선한 전원/규칙/보호+선택한 자동 규칙의 전원 범위+유효 유한 예산/실행 소유권+해당 GUI/서비스의 새 자동 시작 허가가 모두 있을 때 새 자동 ID만 평가 가능. 기본 전원 범위는 AC이며 배터리 자동 명시 선택 때만 배터리 평가 가능. 같은 자동 활성 사건은 새 ID라도 최초 배터리 기준점·상한 재사용, 원래 상한 경과 시 미시작. 백그라운드 새 자동 OFF를 Wake로 우회하지 않음. DarkWake·관측 공백·표본 재생은 불가 |

| K08 화면·잠금·원격 | 화면 꺼짐·잠금·Sleep 구별. 잠금/암호/영구 에너지 설정 무단 변경 금지. 승인된 Tether 소유 임시 덮개 전원 변경은 소유 기록·원복을 전제. 원격·외장만으로 새 정책/전용 메뉴를 만들지 않고 마지막 종료로 Sleep·원격 단절이 가능할 때만 조건부 안내 |
| K09 첫 설정·도우미 | 일반 유지 무도우미. MacBook 덮개 선택 때 필수 준비·인증, 인증만으로 자동/덮개 ON·새 유지 시작 없음. 데스크톱 덮개 설치 요구 없음. 기존 설치 도우미 제거·설정 초기화 없음 |

K04의 일반 Wake 예외를 ‘모든 수동 Sleep 뒤 자동 시작 방지 보장’으로 확대하지 않는다. macOS 메뉴·다른 앱 Sleep의 출처를 항상 구별할 수 없으며, 지속 차단은 Tether의 `모두 중지` 또는 `잠자기…`로 설명한다. K05의 회복 누적은 정상 표본으로 입증하는 시간이고 K02의 수면을 포함한 연속 마감과 다르다.

분리·배터리 상한 종료 뒤의 자동 재시작 차단은 **종료 이후 신선한 실제 조건 false→true, 선택한 새 실제 전원 사건 또는 명시 새 시작·재개**에서만 재평가한다. Wake·새 ID·캐시로 해제하지 않는다. 분리 정책이 새 시작을 금지한 경우에는 종료를 일으킨 그 분리 사건 자체로 시작하지 않는다. ‘작업별 전원 설정에 맞춰 계속’과 배터리 자동의 분리 시작 사건을 모두 명시 선택한 경우만 K01의 별도 시작 허가를 평가한다. 일반 fullWake와 선택 자동 보호 회복은 같은 자동 활성 사건의 최초 배터리 기준점·상한을 보존한다. 실제 조건 false→true나 명시 사용자 새 시작·재개는 새 활성 사건이 될 수 있지만 K01 분리 정책·보호 등 나머지 차단과 시작 허가를 먼저 적용한다.

## Liquid Glass와 native 연결

보존된 HTML은 배치·내용·상태를 검토하기 위한 CSS 표현이다. native Liquid Glass·진동/반사·설치본 성능의 증거가 아니다. 후속 앱 구현에서는 시스템 툴바·탭·Picker·버튼·sheet를 먼저 쓰고, 메뉴와 탐색의 공통 조작층에만 필요한 glass를 적용한다. 본문은 읽기 안정성을 유지하며 카드마다 유리를 중첩하지 않는다. 기존 참고 링크: [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Settings](https://developer.apple.com/design/human-interface-guidelines/settings). 이번 문서 작업에서 새 외부 자료 검증을 한 것은 아니다.

제목/탭/하단 고정 조작과 본문 스크롤을 구조적으로 분리한다. 본문이 제목 뒤로 흘러 희미한 잔상을 만들지 않게 viewport 안에서 자른다. 마우스로 연 화면에는 자동 포커스 링을 만들지 않고 `focus-visible` 키보드 링을 유지한다. 실제 앱에서 모든 포커스를 전역 비활성화하는 방식으로 대체하지 않는다.

기존 사용자 선택대로 VoiceOver 전용 작업을 추가하지 않는다. 이름·역할·값·Tab/방향키·취소/닫기는 기본 컨트롤 계약으로 유지한다. 실제 native 입력·접근성 검사는 후속 단계다.

## 2026-10-16 시안·검사 기록의 보존

[당시 시안 원본](../../../../../outputs/tether-v5-spec-design-20261016/index.html)은 기본4화면, 메뉴 상태14종, 펼침/끝 스크롤, 확장41묶음, 규칙 편집/예행연습, 첫 설정4조합, 밝음/어두움·한국어/영어를 담았던 기록이다. 이후 명시 제외된 예행연습 등이 남아 있어도 현재 범위에 다시 채택한 것이 아니다. 모의 시간은 실제 타이머·현재 Mac의 센서/보호 상태를 입증하지 않는다.

설정 탭별 펼침/스크롤은 시안 내에서 보존한다. 입력·미리보기·저장은 모두 시안 안의 동작이다. 종료·보호·원복·원격 화면은 상태별 설명 예시이며 구현 성공으로 표시하지 않는다.

초기 검수는 [이전 기록](../../../../../outputs/tether-v5-spec-design-20261016/review-checks.json), 당시 문구·펼침·스크롤·밝은 화면 검수는 [재검수 기록](../../../../../outputs/tether-v5-spec-design-20261016/review2-checks.json)과 [검수 설명](../../V5-REVIEW-20261016.ko.md)에 보존한다. 당시 주요 버튼·현재/다음·3종 분리 정책·배터리 무제한·모달/검색·첫 설정 등을 대상으로 한 자료이며 2026-10-21 추천 규칙의 통과 기록이 아니다. 앱 설치·native UI·물리 Sleep/덮개·원격·팬·네트워크·충전의 근거로 이월하지 않는다.

## 쉬운 표현과 안내

[표시 문구 기준](COPY-V5.ko.md)을 적용한다. 기본 탭은 ‘잠자기 방지 / 자동 시작 / 앱 설정’이다. ‘요청·전원 범위·원복·lease·GUI’는 기본 화면에서 쓰지 않고 ‘잠자기 방지 중인 작업·작동할 전원 상태·변경한 설정 되돌리기·연결한 작업·Tether 종료’로 설명한다. 기술 연결 화면에서는 CLI/MCP 같은 식별자를 유지하고 뜻을 덧붙인다.

종료할 대상과 끝난 뒤 동작을 분리한다. ‘타이머 끝내기’는 해당 타이머만, ‘모두 중지’는 자체 유지 전체 종료와 직접 해제 전 자동 차단이다. 다른 앱·빌드·명령을 강제로 종료한다는 표현을 쓰지 않는다. S11~S14로 자체 해제·원복·Sleep 요청·실제 관측을 구분한다. 화면 가리기를 잠금 해제로 바꾸지 않는다.

일반 유지는 도우미 준비를 첫 설정의 필수 관문으로 만들지 않는다. MacBook에서 덮개 기능을 선택할 때만 필수 준비·인증으로 이동하며 준비되지 않으면 덮개 적용을 막는다. 인증만으로 자동/덮개 ON·새 유지를 만들지 않고, 데스크톱에 덮개 도우미 설치를 요구하지 않는다. 기존 설치 도우미 제거·설정 초기화도 하지 않는다. HTML의 ‘준비가 끝난 예시 보기’는 실제 설치·인증 근거가 아니다.

## 기본 조작 단순화 · 보존된 배치 계약

- 기본 시간은 큰 버튼 행 대신 `30분 / 1시간 / 2시간` 선택기와 별도의 `직접 시작`이다. 첫 선택은30분이며 최근 유한 선택만 기억한다. 자동 중 `수동 타이머 추가`로 선택기를 접는 후속 배치 제안은 따로 기록하며 이번 P0 문서 정리로 구현 완료라고 하지 않는다. 선택만으로 유지가 시작되지 않는다.
- 실행 중에는 남은 시간·종료 시각·`30분 추가`·`타이머 끝내기`를 표시한다. 직접 입력·날짜/시각은 더 보기의 현재 타이머 변경으로 이동한다. 현재 시간 변경·연장·끄기 전까지 시작은 다음 유한 선택을 덮어쓰지 않는다.
- `끄기 전까지`와 다른 시간으로 새 시작은 더 보기에서 제공한다. 새 타이머는 개별 화면·덮개 선택을 앱 기본 따름으로 시작한다. 배터리 상한이 선택 시간보다 짧으면 실제 적용 시간을 시작 전에 표시한다.
- 만료 후 자동 작업이 남으면 `타이머 종료 · {실제 조건} 자동 유지 중`으로 표시한다. 마지막 유지가 끝나면 S11~S14의 실제 확인 단계로 표시한다. 보호는 S08/S09/S10을 구분하고 회복 확인 전 시작·재개를 막는다.
- 화면·덮개 세부값은 해당 기능이 꺼지면 접고 보존한다. `저장된 설정 편집`을 통해 기능을 켜지 않고 다음 값을 편집할 수 있다. 관련 기능을 켜면 보존한 값을 다시 표시한다.
- 만료 전 예고가 꺼지면 예고에만 속한 시점·소리·연장 세부를 접고 보존한다. 예고를 켰을 때만 해당 세부를 표시한다. 자연 만료·보호 알림의 설정은 별개이며 함께 숨기지 않는다. 접힌 요약은 현재 선택을 반영한다.
- 조건 카드는 이름·스위치·읽을 수 있는 조건→동작·현재 결과 순서다. 전원 분리 정책 바로 아래에 결과를 표시하고, 배터리 상한에는 다음 작업부터 적용됨을 표시한다.

당시 `#menu`의 점선 영역은 디자인 검토 도구로 제품 UI가 아니다. 선택기 기억은 HTML 브라우저 저장소를 사용한 기록이며 실제 앱의 설정·작업·타이머를 변경하지 않는다. 당시 검수 근거는 [review3-checks.json](../../../../../outputs/tether-v5-spec-design-20261016/review3-checks.json)에 보존한다.

## 다양한 옵션과 상황별 연결 · 후속 시안

[옵션 스튜디오](../../../../../outputs/tether-v5-spec-design-20261016/option-studio/index.html)는 기존 V5·에셋 보드를 보존한 별도 가상 시안이다. [옵션 카탈로그](../../../../../outputs/tether-v5-spec-design-20261016/option-studio/options.js)가 41개 기능 묶음의 개별 필드·기본값·참고 앱·권한/기기 조건·충돌 주의·현재 구현 범위를 가진다. 필드 수를 독립 기능 수로 세지 않는다. `native-v4`도 현재 소스에 해당 범위가 있다는 분류이며 설치본·기기 동작의 합격을 뜻하지 않는다.

기본 메뉴는 앞의 단일 구조를 따른다. 화면·덮개 공통 토글은 현재+다음 계약을 설명하고 설정과 같은 값을 사용한다. 요청별 예외·고급 시간·종료 선택은 작업 상세, 프로필과 오래 유지할 기본값은 설정, 자주 쓰지 않는 보존 설계는 전체 옵션에서 접근하도록 구분한다. 각 ‘옵션…’ 진입은 자동 실행·권한 요청의 동의가 아니다.

이전 최소·표준·덮개·작업·상태 중심의 구성 비교는 이력으로 남긴다. 이번 계약은 한 메뉴의 상태별 표현이며 원격·외장 연결만으로 별도 메뉴나 새 정책을 만들지 않는다. 정보량을 접어도 보호·권한·미해제 영향과 중지·설정 진입을 숨기지 않는다.

메뉴·설정·규칙·첫 설정·접힌 요약은 같은 선택과 관측 근거를 읽도록 계약한다. 시작·연장·수동 종료·자동 OFF·모두 중지의 대상과 결과를 구분한다. 보호·복구 실패는 모두 중지와 독립된 제한이고 재개 버튼으로 우회할 수 없다. 도우미 미준비는 덮개 기능만 제한한다. 권한·기기 확인이 필요한 기능은 선택값 편집과 실제 실행 가능 상태를 구분한다.

배치·색상·이미지 검수 통과를 기능 흐름 완성으로 보고하지 않는다. 팬·가상 화면·네트워크·충전·예약 깨우기 등 승인 설계는 구현·지원 인수 상태를 별도로 표시하며 웹 선택값은 실제 Mac 적용을 뜻하지 않는다. 과거 V4 시험 수·옵션 스튜디오 기록은 해당 산출물에 보존한다.

## 앞선 문서 전용 정리의 완료 기준

- COPY/DESIGN의 S00~S15 주표시와 우선순위가 같고 K00~K09의 추천 규칙과 연결된다.
- 전원 정책별 안내, 연속 마감/배터리 상한, unknown 15초, 회복 60초, 정리 60초 뒤 행동 권한 15초를 서로 다른 계약으로 설명한다.
- 분리·배터리 상한 종료 뒤 차단이 Wake·새 ID·캐시로 해제되지 않고, 같은 자동 활성 사건의 상한 보존과 새 활성 사건의 선행 조건이 COPY/DESIGN에서 같은 뜻인지 확인한다. 이 정의는 보조 설명·검증 조건이며 메뉴 정보나 조작을 추가하지 않는다.
- 승인된 옵션과 후속 명시 제외를 구분하고 3탭·단일 메뉴·현재+다음 설정의 기존 개선을 미완료로 되돌리지 않는다.
- 앞선 문서 전용 단계에서는 정적 텍스트·링크 점검만 수행했다. 현재 로컬 구현·자동 검증은 머리말의 결과 기록과 구분한다. 새 native UI·설치·물리 실행 수락은 [V5 수락 체크리스트](V5-VALIDATION-CHECKLIST.ko.md)의 `V5-P0-00~09`에 대상 후보와 실제 근거가 연결될 때 판정한다. 문서 정리 완료는 그 통과가 아니다.
