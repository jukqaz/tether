# Tether 디자인 가이드라인

## 2026-10-21 자동만 쉬기 · 메뉴바 남은 시간 · 조건 설정 편의

- 자동만 쉬기는 30분/1시간/직접 재개까지이며 저장한 자동 ON/OFF와 분리한다. 메뉴와 자동 시작 설정은 같은 제어를 사용한다. 수동 타이머·현재 마감·모두 중지·보호·전원 분리 규칙을 보존하며 자동 재개는 현재 조건을 새로 확인하는 조작이다.
- 쉬는 중에는 자동 시작 스위치의 선택은 보존하고 종료 시각/직접 재개와 ‘자동 재개’를 표시한다. 그 상태에 ‘선택한 조건을 기다리는 중’ 안내를 중복하지 않는다. 수동 유지가 실행 중이면 주 상태는 수동 유지를 우선한다.
- 메뉴바 표시 기본은 아이콘만이다. 아이콘+남은 시간을 선택한 경우 확인된 수동 유한 타이머만 짧은 분 단위·고정폭으로 표시한다. 보호/중지/미확인/만료와 자동 유지에 수동 남은 시간을 붙이지 않는다. 표시는 절전 요청을 생성하거나 기존 기한을 변경하지 않는다.
- 자동 조건은 업무 시간·특정 앱·외장 화면의 새 초안을 제공한다. 기존 프리셋을 자동 삭제하거나 교체하지 않고 확인 적용에서만 저장한다. 앱은 native 파일 선택기로 고르며 식별값은 고급에 보존한다. 요일과 시각, 전역 전원/화면/덮개·보호 조건의 관계를 같은 시트에서 설명한다.
- 기존 그래파이트·블루, 300pt 메뉴, 560pt 설정, native 컨트롤과 단일 스크롤을 유지한다. 알림·권한·새 절전정책·설치 단계는 추가하지 않는다.

## 2026-10-21 현재 작업과 새 시작 분리 · 메뉴 직접 설정

- Keepresso의 메뉴 직접 조작과 Amphetamine의 현재/새 세션 구분을 참고한다. 현재 작업의 자동 이유·수동 남은 시간·수동 종료/연장·모두 중지는 같은 구역에 둔다.
- 새 수동 시작은 별도 제목 아래 시간 선택과 시작 버튼을 묶는다. 자동 유지 중에는 시작 버튼을 보조 스타일로 표시한다. 수동 실행 중에는 중복 타이머를 시작하는 선택기를 표시하지 않는다.
- 자동 시작·덮개 닫아도 유지·화면 켜 두기를 같은 옵션 구역에 배치한다. 덮개는 지원 MacBook에서만, 도우미 준비 확인 뒤 조작한다. 미준비 시 기존 설정의 준비 위치로 연결한다.
- 메뉴 토글은 기존 AppModel setter에만 연결한다. 보호/중지 해제·새 작업 시작·시스템 암호 정책 변경을 토글에 추가하지 않는다. 선택과 실제 displayHolding을 구분한다.
- 상세에는 자동 전원 범위와 덮개 종료 설명만 남긴다. 기본 화면의 작업 이유·마감·개수를 반복하지 않는다. 그래파이트·블루와 기존 글자 위계는 유지한다.
- 기본 대기 메뉴는 새 덮개·화면 조작과 인라인 도우미 준비를 포함해 320pt 이내로 검증한다. 자동/수동 실행·긴 경고·상세 펼침은 기존 화면 높이 제한 안에서 자연 높이 또는 본문 스크롤을 사용한다.

## 2026-10-21 메뉴바 컴팩트 정리

- 상태 아이콘·현재 상태·유지 방식/전원을 하나의 헤더로 묶는다. 브랜드 제목과 같은 상태 설명을 반복하지 않는다.
- 수동 시간/시작·남은 시간/연장/수동 종료, 자동 시작 스위치, 모두 중지/다시 허용은 기본 메뉴에서 바로 조작한다. 설정3탭과 전원·보호 실행 규칙은 변경하지 않는다.
- 전원 분리 요약은 저장한 세 정책(모두 종료/자동 종료/허용된 유지 계속)에 연결한다. 자동 대기는 선택 전원·고급 조건·보호·중지 상태를 반영한다. AC 전용으로 고정 설명하지 않는다.
- 유지 이유와 자동 전원·덮개 종료의 긴 설명은 단일 ‘상세’ 펼침에 모으고, 더 보기에는 실제 덮개 지원 확인값과 잠자기·앱 종료만 남긴다.
- 300pt 폭, 15/12/11pt 글자 위계, 그래파이트·블루, 단일 메뉴 Liquid Glass와 경고 해결 조작을 유지한다. 모의 렌더의 미리보기 표시는 하단에 항상 남긴다.
- 모의 SwiftUI 렌더/상태별 소스 회귀와 설치본 Computer Use 결과는 구분한다. 빈 캡처를 디자인 검수의 통과 근거로 사용하지 않는다.

## 2026-10-20 핵심 기능 중심 개편 · 현재 우선 기준

사용자가 단축키·규칙 예행연습·설정 변경 이력·특정 프로세스 종료 연동 수동 유지·작업 종료 후 업데이트 예약의 제거를 승인했다. 아래 과거 시안·검증 기록의 해당 기능은 현행 제공 기능이 아니다. 전원 정책을 확대하지 않고 클램쉘·AC 자동 트리거·수동 절전 방지를 중심으로 정리한다.

- 메뉴: 현재 상태 → 30분/1시간/2시간 및 AC 무제한 → 남은 시간·연장·종료 → 자동 시작 → 모두 중지·설정. 시간 선택만으로 시작하지 않는다.
- 잠자기 방지: 덮개·화면 선택 → 전원 분리 동작과 배터리 한도 → 보호·종료 규칙 상세. macOS 잠금 제약과 설정 링크는 옵션 가까이에 짧게 둔다.
- 자동 시작: 전체 허용과 현재 조건 → 조건 편집 → 동작 설명. 같은 AC 조건을 반복 표시하지 않는다. 앱/프로세스 실행 중 트리거는 삭제한 프로세스 종료 연동 수동 유지와 구분해 보존한다.
- 앱 설정: 로그인·언어 → 알림 → 명시적 업데이트 → 충돌 진단·도우미·문제 기록. 예약·이력·예행연습·전역 단축키 조작은 제공하지 않는다.
- 그래파이트·블루, 현재 창 크기, native 기본 키 조작과 스크롤 헤더는 유지한다. ‘모두 중지’는 수동 종료+자동 일시중지이며 다시 허용해도 끝난 타이머는 복원하지 않는다.
- 설치·물리 시험은 보류한다. 정적 렌더, 소스 회귀, native 입력, 설치본 동작을 별도 기록한다.

**2026-10-16 차기 시안:** 조사34개/기능41묶음을 반영한 [V5 디자인 계약](DESIGN-V5.ko.md)과 [기능명세](PRODUCT-SPEC-V5.ko.md)를 작성했다. 메뉴·설정3탭·선택 확장 화면의 검토 시안이며 2026-10-17 기존 기능을 연결하는 native UI 적용이 승인됐다. 아래는 현재 후보58과 이전 승인 디자인의 기록으로 보존한다. V5 HTML을 native 구현·설치 완료로 해석하지 않는다.


## 2026-10-17 V5 native UI 구현 승인

사용자의 구현 요청에 따라 메뉴와 설정3탭을 V5의 컴팩트 정보 구조로 반영한다. 메뉴300pt·좌우15pt·타이머26pt, 설정 최소560×480pt와 단일 본문 스크롤을 사용한다. 자동 전체 허용은 자동 시작 탭에서 관리하며 잠자기 방지 탭에는 이동 링크를 둔다. 보호는 잠자기 방지의 접힌 상세, 알림은 앱 설정에 둔다.

이번 범위는 기존 구현 기능에 연결한 UI와 검증이다. 확장41묶음의 런타임 구현·전원 정책 변경·설치·물리 시험은 포함하지 않는다. 기존 사용자 선택과 자동/수동 종료 범위를 유지한다. 정적 shipping-view 렌더와 실제 native fixture 입력 검증은 따로 기록한다. 최신 검수 보드의 다크 표면#242931·컨트롤#35404E·본문#F2F4F8·보조#BDC7D6·강조#9BC8FF, 라이트 표면#FCFDFF·컨트롤#E5ECF5·본문#20252F·보조#4E5E72를 적용하고 주요 버튼#1552A0를 공통 사용한다. 고대비는 시스템 의미 색을 우선한다.

### 2026-10-20 자동 시작 안내와 영어 표시 보완

- 자동 시작 대기는 저장된 허용 선택과 실제 시작 조건을 구별한다. 고급 조건 사용 시 전원 연결만으로 시작한다고 약속하지 않고, 현재 조건 요약을 사용한다. 모두 중지·보호 중에는 전원 연결만으로 재개되는 안내를 숨긴다.
- 단축키의 native 키 선택기는 번역된 값의 고유 폭을 보존하고 최소112pt의 배치 공간을 확보한다. 보이는 글자와 화살표·여백이 실제 최소 창에 들어가는지 확인한다. AX의 완전한 문자열만으로 시각적 잘림을 통과시키지 않는다.
- 스크롤 헤더는 설정3탭의 상세를 펼친 뒤 실제 상단·중간·끝 캡처와 본문 이동·헤더 고정 프레임을 함께 확인한다. 모의 상태의 native UI 검증이며 설치·물리 절전 결과는 별도다.

2026-10-15 · 기존 승인 컴팩트 기본4화면/상단3탭 + v4 운영 편의 검토 시안 · macOS 26 이상 · Apple Silicon

설정 창과 메뉴 패널은 이 문서의 색·컴포넌트·배치 기준을 따른다. 앱 아이콘 6번과 메뉴바 아이콘 1번을 유지한다. UI를 정리하기 위해 전원 정책이나 macOS 보안 설정을 바꾸지 않는다.

Apple HIG의 원칙과 제품의 수치를 구별한다. 아래 창 크기·여백·폭은 Tether의 선택이며 Apple의 의무 규격이 아니다. 색·서체·배치는 이 문서를 따르며 기능·시작/종료 정책은 [v4 명세](PRODUCT-SPEC-V4.ko.md)가 우선한다. 현재 소스가 v4 구현 완료라는 뜻은 아니며 실제 합격 여부는 같은 후보의 검증 결과에 기록한다.

|---|---|---|
| AC 자동 | 전원이 연결되면 자동으로 작업을 유지합니다. | 자동 시작 여부를 설명. 덮개 유지와 서로 자동 ON 하지 않음 |
| 덮개 유지 | 유지 중인 작업을 덮개를 닫아도 계속합니다. | 기존 자동/수동 작업에 적용하는 허용 범위. 이것만 켜서 새 작업을 시작하지 않음 |

- 첫 설치는 두 선택 모두 OFF다. 도우미 준비/인증/완료 조작이 이 선택을 대신하지 않는다. 기존 설치의 선택은 첫 설치 시안의 기본값으로 덮어쓰지 않는다.
- 적용 전에는 ‘선택한 내용’을 보여주고 확인 버튼에서 저장한다. 저장한 선택과 ‘현재 결과’를 구별한다. AC 자동 ON 확인은 유효한 현재 AC·보호·준비 조건에 따라 작업을 시작할 수 있음을 버튼 가까이에 짧게 안내한다.
- OFF/OFF는 자동 대기, ON/OFF는 일반 AC 유지, OFF/ON은 자동 대기이며 직접 시작한 수동에 덮개 허용, ON/ON은 AC 작업의 닫힌 유지 허용이다. 열린 덮개에서 ‘덮개 유지 중’으로 표시하지 않는다.
- MacBook의 기존 필수 도우미 준비가 끝나지 않으면 설정을 완료/실행 중으로 표시하지 않는다. 데스크톱은 덮개·배터리·도우미 조작을 숨기고 일반 AC 경로를 사용한다. 기기/전원 예시는 검토용 입력이며 실제 장치 상태가 아니다.
- 완료 뒤에는 현재 확인한 결과와 필요한 조작만 남긴다. 전원 분리 시 기존 요청 종료·배터리 수동 별도 시작·화면/잠금 제약을 바꾸지 않는다. 업데이트 때 첫 설정을 자동 재실행하거나 옛 수동을 복원하지 않는다.

제품 인수는 [v4 명세의 V4-G1~G4](PRODUCT-SPEC-V4.ko.md)와 [검증 체크리스트](../../VALIDATION-CHECKLIST.ko.md)를 함께 따른다. 조작 범위·첫 설정 이해도는 시안 검수와 실제 native 조작을 구분하고, 분리·원복·설치·유휴 비용은 HTML 결과로 합격시키지 않는다.

### 최종 검수의 간소화 원칙

- 사용자에게 현재 확인한 결과·남은 시간·가능한 조작을 먼저 보여준다. 확인할 수 없는 앱 귀속/원인을 추정하거나 결과에 영향 없는 미확인 상태를 별도 카드·알림·상시 감시로 늘리지 않는다.
- 내부 세대·owner·TTL·실행 토큰·원복 저널은 사용자 입력이나 기본 화면의 선택지가 아니다. 검토용 장면 선택기는 제품처럼 그린 창 밖의 접힌 도구로 분리한다. 필요한 시작 거절/유지 종료/설치 보류 결과는 짧게 표시하며 확인된 해결 수단만 제공한다.
- 무제한 수동의 연장 버튼과 빈 마감 행을 숨긴다. 연결 작업 없는 무제한 수동에는 ‘작업 후 설치’를 제공하지 않고 기존 ‘지금 설치’로 안내한다. 시간제 연장도 선택한15/30분 전체가 가능한 경우만 제공한다.
- 기본 메뉴에 이미 보이는 유지 이유와 설정 변경 이력을 같은 지름길로 연결하지 않는다. 설정 이력은 앱 설정에 두며 메뉴의 중복 진입점은 생략한다.
- 인증 필요·확인 중 설정 변경·옛 알림의 마감 변경은 실제로 확인한 때의 결과 화면으로 표현한다. 사용자에게 알 수 없는 내부 상태를 직접 진단하도록 요구하지 않는다.

## 승인한 로컬 디자인 작업 방식

Figma·Sketch·Canva 같은 외부 디자인 편집기는 기본 작업 경로에 포함하지 않는다. 디자인을 위해 별도 계정·클라우드 보드·유료 서비스·외부 UI 패키지를 준비할 필요가 없다. 기존 SwiftUI·AppKit, 로컬 시안, 실제 native 화면 캡처와 XCTest를 사용한다. 디자인 스킬은 검토 지침으로 참고하며 새로운 도구 설치를 작업의 전제조건으로 만들지 않는다.

`DESIGN.md`는 정보 구조·표시 의미·색·서체·배치·완료 기준을 관리한다. 구현의 공통 값은 `DesignTokens.swift`·`PanelStyle.swift`·`SettingsMetrics`에서 관리한다. 개별 화면에서 동일한 색·크기를 따로 정의하지 않는다. 과거 생성 시안이나 별도 HTML 보드가 현재 SwiftUI 화면과 다르면 차이를 기록하고 이 문서의 최신 승인 기준을 따른다.

### 통합 디자인 스킬

Tether의 디자인·사용성 작업은 프로젝트의 [tether-design](../../../.agents/skills/tether-design/SKILL.md)을 함께 사용한다. 실제 화면의 문제는 Product Design Audit·Computer Use로 확인하고, Impeccable의 글자 위계·배치·단순화 기준, UI UX Pro Max의 UX 참고 항목, frontend-design의 표현 절제 기준을 필요한 부분만 보완한다. macOS Liquid Glass·SwiftUI Patterns와 SwiftUI Expert 기준은 native 구현의 정확성을 검토한다. 같은 화면·후보의 근거를 재사용하며 역할마다 전체 검사를 새로 시작하지 않는다.

외부 원본을 전부 자동 실행하거나 새로운 디자인 시스템으로 덮어쓰지 않는다. 현재 사용자 선택과 이 문서·macOS 기준을 우선하며 SF 시스템 폰트·native 컨트롤·승인된 컴팩트 밀도를 유지한다. 웹의 16px 본문·모바일 44pt 타깃·CSS/DOM 검사 결과를 macOS의 제품 수치나 native 검증 근거로 바꾸지 않는다. 외부 지침은 [출처와 적용 범위](../../../.agents/skills/tether-design/references/external-criteria.md)에 기록하며, 추가 CLI·hook·클라우드 서비스 설치는 전제조건이 아니다.

| 단계 | 수행할 작업 | 남길 근거 |
|---|---|---|
| 1. 문제 정의 | 해당 화면·상태·언어·창 크기와 사용자가 해야 할 조작을 특정 | 변경 범위와 완료 기준 |
| 2. 로컬 시안 | 기존 시안과 SwiftUI 프리뷰로 기본·펼침·스크롤 끝·오류 화면을 비교 | 필요한 화면만 담은 비교 캡처 |
| 3. 구현 | 같은 화면의 공통 토큰·native 컨트롤·배치를 수정 | 해당 소스 변경. 전원·보호 정책은 디자인 변경과 분리 |
| 4. 소스 회귀 | 변경된 상태·입력·표시 범위에 맞는 빌드와 기존 회귀 검사를 실행 | 명령·범위·종료 결과 |
| 5. 실제 UI 확인 | 격리 앱의 공유 Scene에서 클릭·펼침·스크롤·창 재열기와 포인터·키보드를 확인 | 같은 후보의 캡처·AX·native 검사 결과 |
| 6. 완료 판정 | 아래 체크리스트와 남은 항목을 대조 | 확인·실패·미확인 구분. 설치·물리 시험은 별도 |

기존에 승인한 컴팩트 구성의 여백·정렬·대비·잘림 보완은 계속 진행한다. 화면 구조·기능 노출·아이콘 콘셉트를 크게 바꾸는 경우에는 로컬 시안을 먼저 보여주고 승인 후 구현한다. 문서나 코드 수정만으로 실제 화면 검증을 완료 처리하지 않는다.

시안에는 예시 데이터를 명확히 표시한다. 현재 SwiftUI 뷰를 모의 실행기에 연결한 Fixture와 구조·상태 설명용 시안을 구분한다. ImageGen은 이미 승인한 아이콘·첫 시작 이미지 등의 선택적인 리소스 제작에만 사용하며, 이미지 생성을 매 디자인 수정의 필수 단계로 만들지 않는다.

검증 자료는 해당 작업의 `.build/verification/<작업 단위>`에 필요한 캡처·결과만 둔다. 데스크톱에 저장하지 않고 동일 결과를 여러 보고서로 복제하지 않는다. 실패 원인에 영향을 주지 않은 전체 검사를 반복하지 않는다. 초기화·인증·캡처 문제로 검사가 시작되지 않았다면 제품 실패나 통과가 아니라 차단으로 기록한다.

## 이번 재설계의 기준

- 설정은 상단 native segmented 탭과 아래 옵션으로 나눈다. 페이지 선택과 제목·설명은 본문 스크롤 밖에 둔다.
- 색은 그래파이트·블루 계열이다. macOS의 밝음·어두움 설정을 따르며 전역 dark appearance를 강제하지 않는다. 파랑은 선택·실행·유지 상태에 쓰고 경고·보호 의미색은 유지한다.
- Liquid Glass는 상단 탐색·보조 조작 층과 메뉴 표면에 사용한다. 본문은 불투명 그래파이트 표면으로 읽기를 안정시키고, 흰 글자 주요 버튼은 불투명 블루로 대비를 확보한다.
- 메뉴의 제목·상태·조작 크기를 분명히 구분한다. 상태는 15pt semibold, 본문은 12pt, 보조 정보는 11pt를 사용한다. 전원 분리·잠금·배터리 제약은 12pt를 유지한다. 설정과 다른 동작은 하단에 하나씩 두고 추가 유리 상자를 중첩하지 않는다.
- 설정 기본·최소 본문은 560×440pt이며 세 페이지를 상단 탭으로 탐색한다. 본문 margin은 20pt로 정렬하고 좁은 폭에서는 행의 컨트롤을 아래로 내려 전체 문구를 보존한다. 제목과 탭은 고정하고 긴 상세만 본문에서 스크롤한다.
- 수동 시작은 small 크기의 주요 버튼으로 표시한다. 실제 시작·종료·전체 중지 범위와 안전 제약을 문구 축소로 숨기지 않는다.
- 자세한 설명은 접힌 상세로 모으되 전원 분리 결과·잠금 제약·배터리 제한은 관련 옵션 옆에 짧게 남긴다. 같은 설명을 footer와 상세에 반복하지 않는다.

| 화면 | 기본 순서 | 추가 정보 |
|---|---|---|
| 첫 설정 | 필수 준비 → AC 자동/덮개 유지 독립 선택 → 적용 전 결과 → 확인 | 기존 준비 안내 안에서 제공. 새 설치 OFF/OFF·데스크톱 제외·저장 후 현재 결과를 구분 |

| 작업 유지 | 자동 조건 → 덮개·전원 분리 → 화면 유지 | 수동 배터리 예외, 동작 규칙·잠금 안내. 화면 유지 옆 macOS 잠금 제약은 한 줄 유지 |
| 기기 보호 | 상태·필요한 재개 → 항상 적용하는 열 보호 → 잔량 하한 | 보호 알림·기준 설명 |
| 앱 설정 | 도우미 상태·필요한 준비/복구 → 로그인 시작·언어 → 기록·업데이트 상세 → 절전 영향 | 기록·진단·보고서·업데이트는 기본 접힘. 실행 중 기록·설치 대기는 즉시 노출 |
| 절전 영향 | 결론 → 실제 요청 앱·조치 | 추가 설치 앱·macOS·화면·원격 관측 |
| 시작 안내 | 필수 준비 → 자동 유지·수동 시작 요약 → 완료 | 작업 유지·보호 상세 |

일상 화면에 PID·lease·revision·원본 복구 기록을 펼치지 않는다. 세부 정보는 `DisclosureGroup`과 시트로 제공한다. 실패 이유와 해결 조작을 가까이 두고, 도우미 준비 안내는 도우미 옵션이 있는 앱 설정 탭으로 연결한다.

메뉴의 `자동 유지`, `수동 유지 종료`, `모두 일시 중지`는 서로 다른 범위다. 일시 중지는 수동 유지를 끝내고 자동 조건도 재개 전까지 멈추는 조작이며 앱 종료와 구분한다. 중지 후에는 `작업 재개`로 표시하며 꺼 둔 자동 조건이나 끝난 수동 타이머를 다시 켠다고 설명하지 않는다. 덮개·전원 분리 결과는 현재 배터리 유지 예외를 반영한 짧은 문구로 상태 아래에 표시하고 긴 설명은 다른 동작 안에서 확인한다. 준비나 복구가 필요하면 조작을 기본 화면에 노출하며 실제 OS 잠자기 완료를 단정하지 않는다. 동일 덮개 오류를 중복 표시하지 않는다. 설정 진입은 하단 버튼 하나를 사용한다.

시간 한도·재연결 후 마감은 작업 유지 탭, 조기 종료·회복은 기기 보호 탭이 상세 설명을 소유한다. 선택 가까이의 짧은 안전 제약은 유지한다. 기능을 숨기거나 글자를 축소해 공간을 확보하지 않는다.

배터리와 덮개 옵션은 지원하는 기기에서만 제공한다. 원격 연결을 감지해도 메뉴바 배지나 아이콘 폭을 바꾸지 않는다.

## Apple 컴포넌트

- 실제 `Settings` Scene 안의 native segmented Picker로 세 페이지를 탐색한다. 짧은 탭 이름과 본문의 전체 제목을 구분하고 선택·페이지별 상세 펼침 상태를 보존한다.
- 자동 생성된 빈 Settings 툴바는 기존 창 bridge에서 숨긴다. native 제목·닫기 버튼을 보존하며 재열기에도 같은 정리를 적용한다. 제목은 본문과 같은 읽기 열에 정렬하고 native titlebar 아래의 공간을 확보한다. 창 전체 툴바를 SwiftUI에서 숨겨 기본 닫기 버튼까지 사라지게 하지 않는다.
- 본문 ScrollView의 상단 scroll-edge 효과를 숨기고 고정 제목 아래에서만 스크롤한다. 상단 탐색·타이틀바의 시스템 재질 위에 별도의 글래스 배경을 중첩하지 않는다.
- 프리뷰 표시는 비조작용 `PreviewIndicator`로 통일한다. 설정에서는 상단 탐색부에, 메뉴에서는 제목 옆에 배치하고 별도 원형 글래스 버튼으로 만들지 않는다. 프리뷰의 기본·최소 본문 크기는 설치본과 같다.
- 정적 상태 샘플의 제목·스위치·타이머는 같은 메모리 세션을 사용한다. 설치된 도우미 상태나 사용자 설정을 샘플 기본값과 섞지 않는다. 일반·화면 요청 모두 모의 실행기를 사용한다.
- 설정은 한 개의 `ScrollView`와 평평한 섹션을 사용한다. native Toggle·Picker·DisclosureGroup과 접근성 식별자는 보존한다. 짧은 행은 이름·조작을 `HStack`으로 좌우 정렬하고, 실제 폭이 부족한 긴 행만 `ViewThatFits`의 세로 배치로 전환한다. native `LabeledContent`가 여유 있는 행까지 세로 적층하는 실제 설치본 문제를 피하며 조작은 시스템 컴포넌트를 보존한다. 목록을 다시 유리 카드나 테두리로 감싸지 않는다.
- ON/OFF는 native switch, 짧은 상호 배타 선택은 segmented Picker, 시간·언어는 menu Picker를 사용한다.
- 설명은 section footer나 기본 접힘 상세로 제공한다. 중요한 오류를 말줄임표로만 숨기지 않는다.
- 시간은 5·10·15·30분·1시간·2시간의 native menu Picker로 제공한다. 수동 무제한은 전원 연결 중에만 표시한다. 직접 입력·별도 시간 편집 창은 제공하지 않는다.
- 수동 시간 선택은 메뉴바가 소유하며 현재 마감의 명시적 연장과 다음 선택을 구분한다. 자동은 AC에서만, 전원 분리 후 승계는 없다. 수동 만료 예고·종료 알림은 독립 기본 OFF 옵션으로 제공하고 별도 사용법 창은 제외한다. 첫 설치 안내·보호 알림·종료 기록은 유지한다.
- 기존 임의 시간은 값을 바꾸지 않고 ‘기존 설정’ 선택지 하나로만 보존한다. 새 프리셋을 고르면 이 임시 항목은 사라진다. 시간 선택은 시작 조작이나 진행 중 마감 변경이 아니다.
- 주요 동작은 prominent 버튼, 보조 동작은 일반 버튼·링크로 구분한다. 시스템의 포커스·hover·disabled 표현을 유지한다.
- 일반 `⌘,` 재열기는 마지막 페이지를 보존한다. 경고 해결 링크는 필요한 페이지를 명시적으로 연다.
- 창 크기는 Scene·본문 제약으로 정한다. native Settings host가 크기 조절을 비활성화하는 경우에만 기존 창 bridge에서 `.resizable`을 보완하며, 시스템이 측정한 본문·툴바 최소 크기를 유지한다. 승인된 v4 compact 설치본은 이전 디자인의 저장 크기를 최초 표시 때 한 번 560×448pt 본문으로 이관한다. 이후 사용자의 resize·재열기 크기는 보존하며 Fixture·Preview에는 이관을 적용하지 않는다. 이관 여부와 별도로 두 축의 실제 resize·최소 크기를 검증한다.
- 시작 안내는 480×680pt의 별도 고정 창을 사용한다. Settings의 최소 크기·크기 조절 정책을 상속하지 않는다.
- 최근 동작은 기록마다 자연 높이를 사용하고 Settings의 바깥 스크롤 하나로 탐색한다. 짧은 기록 목록을 별도 고정 높이·중첩 스크롤에 넣지 않는다.
- 실제 절전 요청이 확인된 앱의 설치 정보는 같은 앱의 상세에 합친다. 설치되어 있다는 이유만으로 실제 요청 앱 목록에 중복 표시하지 않는다.
- 앱별 행은 이름·요청 효과·조정 버튼을 먼저 보여 준다. 상단 결론과 반복되는 옵션 안내·PID·설치 경로는 접힌 기술 정보에 둔다.

[Apple Settings](https://developer.apple.com/design/human-interface-guidelines/settings)

## 색상

다크 graphite 표면과 하나의 파란 계열을 사용한다. 색·서체 토큰은 `LiveUI/DesignTokens.swift` 및 기존 `AppModel.swift`의 `Color` 확장에서 공유한다. 화면별 임의 색을 추가하지 않는다.

| 역할 | 토큰·기준 |
|---|---|
| 표면 | 시스템 window·control 배경 또는 표준 material |
| 주요 글자·값 | `.primary` |
| 보조 설명 | native 컴포넌트의 `.secondary`, custom 작은 글자는 `tetherSecondary` |
| 유지 중·선택·링크·시간 | `tetherAccent`: 다크 `#76ADFF`, 밝은 외관 `#1762BD` |
| 채워진 주요 조작 | `tetherAction`: `#1552A0`; 흰 글자가 읽히도록 구분 |
| 설정·더 보기·종료 등 보조 조작 | `tetherControlSurface`: 적응형 중립 표면; 화면의 파란 tint를 상속하지 않음 |
| 주의·제한·보호 중지 | `tetherWarning`: 다크 `#FFCA58`, 밝은 외관의 진한 주황 |
| 오류·위험 | 시스템 빨강 |
| 확인된 정상·성공 | `tetherSuccess`: 적응형 초록 |

이 팔레트는 Apple `systemBlue`와 동일한 값이 아니다. 기존 appearance·고대비 대응을 유지한다. 파랑은 활동과 선택을 표시하고, 초록은 정상 확인·검사 성공에만 사용한다. 전원 조건 대기와 macOS 자체 관리는 중립색, 실제 보호·주의는 주황이다. 색과 함께 이름·기호·선택 표시를 제공한다. ‘선택됨’, ‘진행 중’, ‘확인됨’은 다른 의미다.

작은 일반 글자의 대비 4.5:1을 검사 목표로 삼는다. 불투명 배경의 RGB 계산만으로 Liquid Glass 가독성을 통과시키지 않는다. 실제 배경·비활성 창·고대비·투명도 감소에서도 읽기를 확인한다.

[Apple Color](https://developer.apple.com/design/human-interface-guidelines/color), [Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)

## Liquid Glass

Glass는 탐색과 조작의 층에 적극 사용하고, 긴 설명은 안정적인 읽기 표면에 둔다.

- native 툴바·segmented Picker·버튼의 시스템 재질을 우선한다.
- 주요 흰 글자 버튼은 `.borderedProminent`, 글자 보조 조작은 임의 배경 tint 없는 `.bordered`를 공통 `actionButton`으로 적용한다. 보조 라벨은 공통 본문색을 명시한다. 흰 글자 뒤의 밝은 그라데이션은 사용하지 않는다.
- 메뉴 하단의 일시 중지·설정·다른 동작은 native 버튼 한 줄로 제공한다. 설정 진입을 상단 기어로 중복하지 않으며 개별 유리 상자를 추가하지 않는다. 실제 클릭 영역과 시스템 포커스를 보존한다.
- custom glass에는 기본 `.regular`를 사용한다. `.clear`로 가독성을 희생하지 않는다.
- 설정 본문은 다크 `#202126`의 불투명 읽기 표면을 사용한다. 메뉴와 상단 탐색 조작은 regular Glass 한 층으로 묶고 밝은 외관·고대비·투명도 감소에서는 적응형 읽기 표면을 사용한다. Glass와 Material을 같은 것으로 설명하지 않는다.
- 유리 카드 중첩·중복 blur·의미 없는 색조·반복 반짝임을 추가하지 않는다.
- Reduce Transparency·Increase Contrast에서는 불투명 native 조작으로 대체하고, Reduce Motion에서 내용을 보존한다.

Glass를 끈 offscreen 이미지는 배치 참고다. 실제 Glass의 합격 증거는 native Scene과 설치 화면에서 얻는다.

설정 본문은 단일 ScrollView 안에 native 컨트롤을 배치하고 창 전체의 읽기 폭을 사용한다. 본문의 최대 폭은 `scrollContent`의 좌우 margin으로 제한하며 제목도 같은 20pt 열을 사용한다. viewport를 clip하고 상단 scroll-edge 효과를 숨겨 본문이 고정 제목 뒤로 그려지지 않게 한다. 고정 제목은 안정적인 읽기 배경, 상단 탐색은 시스템 컨트롤 재질을 사용한다. 각 페이지의 스크롤과 재열기에서 제목·선택 페이지의 가독성을 확인한다. 정적인 본문 캡처만으로 스크롤 헤더를 합격시키지 않는다.

[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

## UI 프레임워크 결정

SwiftUI와 필요한 AppKit bridge를 유지한다. 승인된 compact 구성에 외부 패키지를 추가해야 할 이유는 확인하지 못했다. 아래 표는 기존 후보 조사 기록이며 의존성 도입 결정이 아니다. 릴리스·호환성은 도입을 검토하는 시점에 다시 확인한다. 별 수·기본 브랜치 날짜는 10월 11일의 관측이며 이후 갱신하지 않았다. 현재 헤더·프리뷰·포커스 문제는 호스트와 기본 스타일 구성에서 수정한다. 후보의 별 수는 관심도이며 실제 사용자 수나 품질 점수가 아니다.

| 후보 | 현재 근거 | 적용 판단 |
|---|---|---|
| SwiftUI + AppKit | macOS 26+ Liquid Glass·Settings·MenuBarExtra를 SDK에서 제공 | 채택. 추가 의존성 없이 네이티브 창·입력·접근성을 보존 |
| [Luminare](https://github.com/mrkai77/Luminare) | 정식 0.2.0(2025-12-06), 기본 브랜치 최근 커밋 2026-10-09, 169★; BSD 3-Clause | 섹션·정렬·컨트롤 구성 참고. 확인한 재질은 NSVisualEffectView이며 정식의 Introspect 1.x 의존성이 최신 27.x와 충돌 |
| [SwiftUIX](https://github.com/SwiftUIX/SwiftUIX) | 정식 0.3.2(2026-09-18), 기본 브랜치 최근 커밋 2026-08-20, 8,169★; MIT | 필요한 기능 보충용. 테마 교체가 아니며 CocoaScrollView는 macOS를 지원하지 않음 |
| [SwiftUI Introspect](https://github.com/siteline/swiftui-introspect) | 정식 27.1.0(2026-10-07), 기본 브랜치 최근 커밋 2026-10-03, 6,561★; MIT | AppKit 객체 접근 도구. 디자인 시스템이 아니므로 현재 두 UI 문제 해결을 위해 추가하지 않음 |

라이브러리 소스·릴리스 조사와 실제 도입 시험을 구분한다. 위 세 외부 패키지는 의존성으로 설치하거나 성능·외관 시험을 하지 않았다.

[Apple 툴바 배경](https://developer.apple.com/documentation/swiftui/toolbarcontent/sharedbackgroundvisibility(_:)), [스크롤 경계](https://developer.apple.com/design/human-interface-guidelines/scroll-views), [초기 포커스](https://developer.apple.com/documentation/appkit/nswindow/makefirstresponder(_:))

## 치수·정렬·글자

| 항목 | 제품 기준 |
|---|---|
| 설정 기본 Scene·본문 최소 크기 | 560×448pt; native 제목·툴바 영역은 별도 |
| 설정 본문 최대 폭 | 520pt; 좌우 최소 margin 20pt |
| 설정 scroll content 상하 margin | 위 10pt · 아래 14pt |
| 설정 행 최소 높이 | 30pt; native 컨트롤 고유 크기는 보존 |
| 설정 섹션·행 간격 | 16pt · 6pt |
| 메뉴 폭·좌우 inset | 280pt · 16pt |
| 메뉴 본문 그룹 간격 | 8pt |
| 메뉴 수동 조작 | 시작 전에는 시간 Picker와 시작을 한 행, 유지 중에는 마감·종료를 우선 노출 |
| 메뉴 최대 높이 | 560pt; 화면 visible frame에 맞춰 축소 |
| 메뉴바 아이콘 | 모든 상태 고정 18×20pt |

이름은 왼쪽, 값·스위치·조작은 오른쪽으로 정렬한다. 텍스트와 버튼은 가능하면 첫 기준선을 맞춘다. 맞지 않는 행은 `ViewThatFits`로 세로 배치한다. 메뉴 높이를 고정하지 않고 긴 내용은 본문에서 스크롤하며 설정·전체 중지의 조작을 접근 가능하게 유지한다.

시스템 글꼴과 공통 `TetherTypography`를 사용한다. 메뉴 대표 상태와 설정 제목은 15pt semibold, 섹션은 13pt semibold, 이름·값·조작은 12pt, 보조 메타 정보는 11pt를 사용한다. 전원 분리·잠금·보호 등 필수 설명은 12pt로 유지한다. 남은 시간은 20pt·`monospacedDigit`로 표시한다.

macOS 본문 13pt는 Apple 권고이며, 이번 12pt 본문은 사용자가 승인한 compact 제품 선택이다. 자간은 시스템 기본값, 설명의 추가 행간은 1pt를 기본으로 한다. 중요한 설명을 11pt 메타 정보로 내려 공간을 확보하지 않는다. 최소 창과 긴 한국어·영어에서도 겹침·잘림을 확인한다.

[Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [기본 글자 크기 권고](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)

## 입력·접근성

`⌘,` 설정, Return 기본 조작, Escape 취소·닫기를 지원한다. Tab·방향키·Space는 native 컨트롤과 사용자의 OS 키보드 탐색 설정을 따른다. 시트·popover 열기/닫기 후 올바른 입력 대상을 확인한다. 시험을 위해 키보드 배치나 시스템 보안 설정을 변경하지 않는다.

마우스·앱 시작으로 처음 연 창은 첫 컨트롤에 자동 포커스 링을 두지 않는다. 키보드로 연 경우와 이후 Tab 탐색·탭 변경·창 재활성화의 포커스는 보존한다. 전역 접근성 설정이나 모든 포커스 효과를 꺼서 테두리를 숨기지 않는다.

절전 영향 시트는 조작 시점의 명시적인 마우스 이벤트로 열린 경우에만 최초 자동 포커스를 한 번 정리한다. 키보드·출처 미확인 진입은 native 포커스를 보존하며, 지연된 정리 전에 키보드 입력이 있으면 정리를 취소한다. 시트 재구성·점검 결과 갱신은 사용자가 고른 포커스를 덮어쓰지 않는다.

메뉴바의 시작·종료 같은 주요 버튼은 native `small` 크기로 맞추되 실제 조작 영역의 높이는 최소 24pt를 확보한다. 버튼의 우선순위는 블루 주요 버튼과 일반 보조 버튼으로 구분하며 텍스트를 잘라 공간을 확보하지 않는다.

조작에는 이름·상태·hint·안정된 AX identifier를 제공하고 장식 아이콘은 중복 AX를 만들지 않는다. 색만으로 상태를 전달하지 않는다. 사용자 결정에 따라 VoiceOver 전용 기능·낭독 튜닝·VoiceOver 시험은 추가하지 않지만 native 접근성 정보는 유지한다. 전체 접근성 인증 완료를 주장하지 않는다.

### 디자인 변경 완료 체크리스트

아래는 각 변경의 검수 기준이다. 미실시·측정 실패·환경 차단은 빈 항목으로 남긴다. 해당하지 않는 항목은 이유와 함께 N/A로 기록한다.

- [ ] 변경한 상태의 핵심 정보와 가능한 다음 조작이 보이며 같은 정보를 중복하지 않는다.
- [ ] 탐색 이름과 본문의 전체 제목이 읽히고, 긴 한·영문을 줄여야 하면 짧은 탐색 이름으로 분리한다.
- [ ] 공통 색·글자·여백 기준을 사용하고 임의의 글자 축소로 공간을 확보하지 않는다.
- [ ] 실제 캡처에서 필요한 글자·버튼 라벨의 대비를 확인한다. 비활성 창과 비활성 컨트롤을 구분한다.
- [ ] 사용할 수 있는 버튼이 비활성처럼 보이지 않으며, 실제 클릭 지점과 보이는 조작이 일치한다.
- [ ] 펼침 화살표·상태·실제로 노출된 자식 컨트롤이 일치한다.
- [ ] 최소 창과 스크롤 끝에서 제목·본문이 겹치지 않고 마지막 조작에 접근할 수 있다.
- [ ] 설정 재열기·페이지 선택·마우스·키보드 포커스가 기존 동작을 보존한다.
- [ ] 변경 범위의 빌드·소스 회귀·선언한 native 검사 범위가 통과하고 전체 검사 완료와 구분된다.
- [ ] 전후 캡처와 결과가 같은 후보에 연결되며 미검증·차단 원인을 기록한다.

### 다음 보완 순서

2026-10-13 `design-selected-20261013` 검증 단위에서 남긴 항목이다. 현재의 구현·합격 상태는 각 수정 후 새 결과로 갱신한다.

1. 영문 sidebar는 `Work`, 본문과 AX 이름은 `Work sessions`로 분리했다. 공유 native Settings의 150pt 열에서 두 이름의 표시를 확인했다. 한국어는 기존 이름을 유지한다.
2. 일시 중지 버튼은 공통 native bordered 스타일과 본문색 라벨을 사용한다. 공유 메뉴 뷰의 native 팝오버에서 사용 가능한 버튼의 표시·클릭과 글자 대비 표본을 확인했다. 실제 MenuBarExtra 호스트의 최종 검사는 별도다.
3. 수동·오류 상세의 펼침 상태는 `TetherPanel`이 소유하고 일반·스크롤 본문 후보에 같은 Binding을 전달한다. 수동 종료와 오류 메시지 변경 때만 관련 상세를 다시 접는다. 팝오버에서 양쪽 상세 펼침 → 스크롤 본문 전환 → 수동 종료 뒤 일반 본문 복귀까지 상태와 마감 보존을 확인했다.
4. 실제 MenuBarExtra의 포인터·키보드·펼침·스크롤 및 한·영문 최소 창·재열기의 scoped XCTest와 필요한 전체 native suite를 마무리한다. 후속 실행에서 초기화가 복구됐고 메뉴 전이 1개와 릴리스의 진단·한국어 최소 창·펼침·오류·포커스 5개가 통과했다. 영문 2개는 짧은 표시 이름과 전체 AX 이름을 혼동한 너비 기준을 수정했으나 최종 재검사는 보류됐다. 설치본 메뉴 캡처는 다른 앱의 전면·입력 전환이 관측된 상태에서 완료되지 않았다. 사용자가 UI 검사를 나중에 진행하기로 했으므로 자동 입력을 재개하지 않는다.

물리 덮개·전원·잠금·Sleep/Wake 검증은 사용자와 정한 별도 단계에서 수행한다. 위 디자인 검수로 물리 동작을 통과시키지 않는다.

### 진행 중 기록과 세부 문구

진행 중인 상세 기록은 앱 설정의 접힌 진단 상세 밖에 상태·기존 마감·종료 조작만 표시한다. 상세를 접거나 페이지를 재구성해도 이 현재 작업이 숨지 않아야 한다. 상세를 펼쳐도 상태와 종료 조작을 중복하지 않는다. 기록이 없으면 행을 제거해 기본 화면의 밀도를 보존한다.

배터리 최대 유지 시간, 현재 유지의 종료 시각, 화면 절전 지연·중지·미확인 설명과 점검 조작은 공통 12pt 보조 문구 토큰을 사용한다. 실제 절전이나 패널 소비 전력의 확인 여부를 설명하는 글자를 공간 확보를 위해 더 줄이지 않는다.

2026-10-13 `design-functional-20261013` 수정본은 소스·모의 상태와 오프스크린 배치만 검증한다. 사용자의 설치 유지·UI 검사 보류 결정에 따라 설치 앱은 이 세부 수정본으로 교체하지 않는다. `--render-settings … --sample --recording`은 메모리 기반 렌더 컨트롤러의 기록 상태이며 실제 상세 기록을 시작하지 않는다.

승인한 그래파이트·블루 compact 기본4개(메뉴·작업 유지·기기 보호·앱 설정)가 이번 구현 기준이다. 기본은 핵심 상태와 조작만 보여주고 전체 기능 검토의 88개 예외 장면은 기능·표시 계약으로 보존한다. 상세를 접는 것은 옵션 삭제가 아니다. 열 보호 OFF, 타사 앱 강제 종료, macOS 잠금 해제, 새 직접 입력 시간은 추가하지 않는다. 물리 덮개·전원·Sleep/Wake 검증은 별도다.

외부 UI 라이브러리는 릴리스·라이선스·의존성을 확인했다. Luminare는 섹션 정렬·작은 조작 위계만 참고하며 패키지는 추가하지 않는다. SwiftUIX·Introspect는 현재 compact 배치 해결에 필요하지 않다. [Luminare](https://github.com/MrKai77/Luminare/releases/tag/0.2.0), [SwiftUIX](https://github.com/SwiftUIX/SwiftUIX/releases/tag/0.3.2), [Introspect](https://github.com/siteline/swiftui-introspect/releases/tag/27.1.0).

## 선택 시안의 세부 표시 보완

2026-10-13 선택한 스타일 기준은 이 작업 공간의 [로컬 선택 시안](../../../../../outputs/tether-design-review-20261013/master-quality.png)이다. 생성 시안은 정보 구조·스타일 기준이며 실제 앱 화면 합격 근거가 아니다. 이후 이 문서에 승인한 구체적인 native 표시 보완은 시안의 이전 표현보다 우선한다.

- 자동 배터리 유지와 수동 유지는 각각 이름과 남은 시간을 표시한다. 헤더에는 짧은 유지 원인만 표시해 타이머를 중복하지 않는다. 수동 종료는 자동 타이머를 끝내거나 바꾸지 않는다.
- 주 상태는 보호 차단, 요청·관측 미확인, 일시 중지, 유지 중, 대기·꺼짐 순으로 기존 상태 판정을 따른다. 도우미 문제는 덮개 유지의 준비 문제로 따로 표시한다.
- 긴 오류는 간결한 제목과 해결 조작을 먼저 보여 주고 완전한 설명은 펼침에 보존한다. 메뉴 본문만 스크롤하며 하단 일시 중지·설정·기타 조작을 유지한다.
- 복구 조작은 ‘작업 재개’로 표시한다. 이미 종료된 수동 유지가 복원되지 않는다는 도움말을 보존한다.
- 설정 제목 16pt, 섹션 13pt, 본문·버튼·값 12pt, 보조 정보 11pt, 타이머 15pt를 사용한다. 본문·제목은 같은 20pt 열에 정렬하고 하단 14pt를 확보한다. 필수 제약 설명은 12pt를 유지한다.
- 다크 본문 `#202126`, 조작 표면 `#2B2D33`, 본문 `#F4F5F7`, 설명 `#B7BBC5`, 흰 글자 버튼 `#1552A0`, 링크 `#76ADFF`, 경고 `#FFCA58`, 오류 `#F28B82`. 밝은 외관·고대비와 시스템 포커스를 보존한다.
- 정상 데스크톱 전원 조건은 읽기 전용으로 표시한다. 저장된 배터리 조건의 AC 복구 조작과 기기 정보 미확인은 별도로 유지한다.
- 생성 그림·영상은 MacBook 첫 시작에만 쓴다. 영상은 사용자가 선택한 무음 1회 재생이며 자동·반복 재생과 디스플레이 절전 방지 요청을 만들지 않는다. 동작 줄이기·비활성·실패에는 정적 안내로 대체한다.

구현 확인은 빌드, shipping View 렌더, 모의 실행기를 쓰는 회귀검사, native Scene의 포인터·키보드·펼침·스크롤을 구분한다. 물리 덮개·전원 및 설치본 검증은 이 UI 변경과 별도다.

### 실제 native 화면에서 발견한 대비 보완

흰 글자가 있는 segmented 조건은 링크색 `tetherAccent` 대신 `tetherAction`을 사용한다. 회색 tint Glass 보조 버튼의 실제 밝은 표면에서 흰 글자 대비가 부족했으므로 글자 버튼은 native bordered를 사용한다. 보조 버튼의 배경에 임의의 어두운 tint를 주지 않고 라벨은 공통 본문색을 명시해 사용 가능한 조작이 비활성처럼 보이지 않게 한다. 상단 native 탐색·창 chrome·표시 전용 Glass는 보존한다. 네이티브 PNG 표본 측정과 전체 접근성 준수는 구분한다.
