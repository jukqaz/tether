# 수동 절전방지 옵션 구현·검증 — 2026-09-30

기본 전원 트리거와 별개인 수동 옵션으로 구현했다. 기존 전원 조건·자동 배터리 시간 설정을 변경하지 않는다. 소스와 화면·시뮬레이션 검증을 완료했으며 설치된 앱·도우미는 교체하지 않았다.

## 동작

| 조작·상태 | 수동 옵션 | 기본 전원 트리거 |
|---|---|---|
| 수동으로 시작하지 않음 | 비활성 | 기존 조건대로 동작 |
| 전원 연결 중 무제한 시작 | 별도 수동 유지 | 기존 설정 보존 |
| 무제한 유지 중 전원 분리 | 배터리 최대 2시간 또는 더 엄격한 사용자 한도로 전환 | 기존 분리 정책대로 동작 |
| 유효한 무제한 세션 중 전원 복귀 | 원래 무제한 요청으로 복귀 | 기존 연결 정책대로 동작 |
| 배터리에서 직접 시작 | 시간 제한만 제공, 최대 2시간 | 기존 설정 보존 |
| 수동 유지 끝내기·시간 만료 | 수동 사유만 종료 | 유효한 자동 사유가 있으면 계속 유지 |
| 기본 전원 트리거를 끔 | 유효한 수동 옵션은 계속 유지 | 자동 사유 종료 |
| 전체 중지·명시적 잠자기·앱 연결 종료·보호 차단 | 종료 | 각각의 기존 종료·보호 계약 적용 |
| 만료 후 연결·깨움·앱/도우미 재시작 | 임시 수동 세션 부활 없음 | 기존 저장 설정에 따름 |

배터리 예산은 같은 부팅에서 수동 중지·재시작 사이에도 보존한다. 짧은 AC 연결이나 전원 조회 실패로 예산을 갱신하지 않는다. AC가 30초 연속 확인되면 새 예산을 허용하지만 수동 세션은 자동 시작하지 않는다. 이 수치는 기존 전원 확인 규칙이며 기기 수명 보증이 아니다.

기존 자동 배터리 최대 4시간과 기존 배터리 연속 사용 API는 유지한다. 수동 옵션의 2시간 제한을 모든 전원 기능의 전역 제한으로 바꾸지 않았다.

## 구현 범위

- `ManualSessionPolicy`가 수동 요청 기한과 실제 전원별 적용 기한, 부팅에 묶인 배터리 예산을 판단한다.
- 노트북 도우미와 데스크톱 사용자 assertion 경로가 이 정책을 공유한다. 활성 세션·임시 기한은 저장해 복원하지 않는다.
- 노트북 IPC에 수동 시작·종료와 상태 관측을 추가했다. 기본 트리거 설정에는 쓰지 않는다. 도우미에 이 기능이 없으면 UI에서 시작을 막는다.
- 설정과 일반·간단한 메뉴바 패널에 수동 옵션을 배치했다. 수동 종료와 기본 트리거 끄기를 구별하며 두 유지 사유가 중복 OS 요청을 만들지 않게 처리했다.
- 화면 관측 실패·가상/원격 화면은 이미 유효한 작업을 종료하는 이유로 사용하지 않는다. 다른 앱이 작업을 요청하면 자체 해제 후 자동 잠자기를 보류한다. 타 소유자의 전역 설정을 획득하거나 해제하지 않는다.

도우미 시험 201개는 실제 도우미 바이너리를 격리된 fixture에서 실행했지만 모든 OS 전원 쓰기는 dry-run이다. 테스트 데이터만으로 실제 Sleep·덮개 동작·패널 전력·무잠금·원격 앱 접속 성공을 통과시키지 않는다. 제외된 5개는 명시적으로 켜야 실행하는 실제 IOKit 시험이다.

기존 서비스 시험의 오래된 화면 기대값도 정리했다. 기본 클램쉘 인계 fixture에는 `nativeDisplayVerified`를 명시했고, 미분류·가상 화면은 작업 유지, 화면 재시도 소진은 화면 기능만 중지하는 현재 설계를 검증한다. 기능을 약화시키거나 화면 성공으로 표시하는 기대값으로 바꾸지 않았다.

## 남은 확인

설치·배포와 물리 덮개/전원 전환, 실제 원격 앱·잠금 상태, 장시간 유지, macOS 15 및 모델별 동작은 이번 검증에 포함하지 않았다. 관리자 실행기의 공통 복구 lock·단계별 journal 등 기존 재설계 잔여 작업도 별도로 남아 있다. 이번 옵션 구현을 전체 재설계나 배포 준비 완료로 표현하지 않는다.
